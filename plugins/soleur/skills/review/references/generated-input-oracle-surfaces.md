# Generated-input oracle surfaces (review checklist)

Loaded by the pointer bullets in `plugins/soleur/skills/review/SKILL.md`'s test-vacuity
heuristic list when a reviewed suite derives its input set or generates cases
(extracted for the skill byte ceiling — ADR-229).

## sampled-once

- **The generalized form — ask "what SET does this claim quantify over, and how many members did the test sample?" The class recurred a THIRD time in the same file one round later, so treat prose here as known-insufficient.** Every hole in #6565/PR #6577 reduced to one sentence — *a claim quantified over a set the test only ever sampled once* — and three reviewers converged on it independently. Five instances, all green: "each arm fires" sampled each arm only on ITS OWN fixture (loosening one arm to match a prefix all six fixtures SHARE left the full suite **byte-identical to control**); "`errno_chars` bounds all ~130 errnos" fed **one** errno, so a hardcoded `22` satisfied every assertion; "every arm literal is outside the credential alphabet" read only **single-quoted `case`** arms, so a double-quoted/unquoted/`[[ ]]` arm carried a LIVE credential oracle past a GREEN test; "pull tokens are `[A-Za-z0-9]`" sampled **zot only** (both GHCR PAT formats carry `_`); and an invariant the plan declared "closed" was measured OPEN because it checked the `printf` TOKENS, not the literals. **A positive-only oracle is true of the correct implementation AND of the broken one** — pair every "X happened" with "X happened ONLY where it should", over the WHOLE set. Cheapest mechanical gate, and the tell that the test usually already holds its own disproof: when a test DERIVES a set S from source and asserts a property over S, also assert **S's cardinality matches the producer's** (`[[ "$LIT_N" -ge "$VOCAB_N" ]]`) — a member the extraction cannot see is silently exempt, and that exemption is invisible to every green run. In #6577 the vocab extraction counted 17 while the literal extraction counted 16; the fix compared two integers the test had already computed. See `knowledge-base/project/learnings/2026-07-17-every-hole-was-a-claim-quantified-over-a-set-sampled-once.md`.

- **Match the pin's assertion form to the spec's quantifier — a `found`/`grep -q` presence pin encodes `∃` and can never detect a cardinality violation.** When a plan or ruling says "exactly ONE site" (or N sites), the pin must be a `count` compared to the literal N with the ruling named in the assert message; a presence check reads green whether the token appears once or five times. **Why:** PR #10718 — a CTO ruling cut RED-vocab guidance to one site, but the first pin used `found()`, which a second site re-added later would still satisfy; fix-round's code-quality seat flagged it, fixed to `assert_eq "1" "$(count …)"`. See `knowledge-base/project/learnings/workflow-patterns/2026-10-21-one-site-rulings-need-count-pins-not-presence-pins.md`.

## generated-input extraction surfaces

- **A generated-input (property-style) oracle's coverage is bounded by THREE extraction surfaces, all fail-open — check the extractor's grammar, the extracted members' validity, AND the generator's stream.** The sampled-once rule in the parent list covers a set the test *could* see but only touched once; this is the stronger failure — members (or a whole syntactic class) the instrument structurally cannot see, with every miss reading as green. (a) **Form coverage** — an extractor reading SUT syntax must read every form the SUT's grammar permits, not just the dominant one: `legal-normalise-property.test.sh` first extracted only `s|LHS|` sed rules, leaving all 8 `s/LHS/` rules invisible to the residue oracle they belonged to (31/39 coverage under a green suite). The gate is a census: count the producer's rules independently (`grep -cE` over the same region) and assert equality with the extracted count — a delimiter the extractor cannot read then fails the suite instead of silently shrinking it. (b) **Member validity** — `if grep -qE "$p"` folds grep's rc≥2 (invalid ERE) into the same branch as no-match, so an extracted pattern that does not compile joins the oracle as a permanent no-op; compile-check every extracted member up front and fail on rc>1. (c) **Generator stream** — on bash 3.2 (macOS default, the `scripts/lib/` portability floor) a `x=$(prop_pick ...)` command substitution reads the SAME `$RANDOM` stream position the parent had at fork, so every loop iteration draws the identical value: the generator degenerates to a one-case suite that prints `runs=100` beside `PROP_PASS`. Outvar APIs (`printf -v`) run in-process on both versions; never let a `$RANDOM`-drawing helper's result cross a command-substitution boundary. Ask of any generated-input suite: which surfaces bound its domain — the extractor's grammar, the members' validity, the generator's actual entropy — and what asserts each? **Why:** PR #10624 — (a) and (b) were two-seat P2 review findings on the suite's first draft; (c) was caught at design time and is pinned in `scripts/lib/property-harness.sh`'s "WHY NO ECHO-FORM" header. See `knowledge-base/project/learnings/test-failures/2026-10-20-generated-input-oracle-extraction-window-and-bash-random-outvar.md`.
