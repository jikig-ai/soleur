# Review check: a workflow suite's coverage

Loaded from the Defect Classes list in [SKILL.md](../SKILL.md) (Defect Classes) when the diff adds or edits a `.github/workflows/*.yml` file or its suite.

- **A workflow suite's coverage is the set of step BODIES it executes under the shell GitHub runs — name each step that writes state and the row that runs it to failure.** A step with no `shell:` key runs as `bash -e {0}` (no pipefail, errexit ON), so `rc=$?` after a failing command is unreachable unless `set +e` brackets it (ADR-170; `lint-workflow-errexit-capture.py` fails on it in CI). A harness that runs bodies under `-eo pipefail` and stubs only the read path certifies the guards and never the writer, and regex pins over the apply line are satisfied by a trailing comment, a double space, `-chdir`, an env-borne `TF_CLI_ARGS_*` or an extra step. Also: a guard's name/config/address list must be READ from the graded artifact (the plan JSON), not restated, and a stub env var shadows the one under test unless namespaced `STUB_*`. **Why:** #9481 — the P1 and four of twelve P2s were this; 169 rows and 35 mutants were green. See `knowledge-base/project/learnings/2026-10-04-a-create-only-workflow-whose-writing-step-my-suite-never-executed.md`.
- **A gate's WIRING is not pinned by regex over its workflow text: execute the extracted `run:` block against a stub that REFUSES any other argv, with a control case proving a changed selector flips the verdict, and keep `absent`/`unknown` apart from `skipped` when classifying run records.** Regex pins stayed green with a case arm replaced by `:`, a changed `--event`, a swapped `--jq` field order and a post-scan reassignment; a classifier that read an absent or conclusion-less step as "skipped" read the plan's own cited failed rotate (a pre-rename step name) as nothing-happened. **Why:** #10166/PR #10184. See `knowledge-base/project/learnings/2026-10-13-a-classifier-that-reads-absent-as-skip-fails-open-on-name-drift.md`.
