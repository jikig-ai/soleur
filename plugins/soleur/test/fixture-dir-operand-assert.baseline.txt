# 2026-09-03 BURNED DOWN, 167 -> 8 (#7709). The grandfather list is spent. Every remaining site

#
#   .github/scripts/test/test-infra-suite-registration-mutations.sh  (8 sites)
#     SB=$(mktemp -d -t infra-reg-mut.XXXXXXXX) || { echo "SETUP: mktemp failed" >&2; exit 2; }
#     The script exits 2 before reaching any of the eight writes. `_guard_res` matches an abort
#     only as the bare words `|| exit` / `|| return`, so it cannot see past the `{`.
#
# A brace-group pattern for exactly this WAS written, and was REVERTED before merge. It is worth
# recording why, because the next reader will have the same idea:
#
#   Five shapes satisfied it while aborting nothing, all measured against the live scanner —
#     (a) `|| { echo "step 1; exit code unknown" >&2; }`   a `;` INSIDE a quoted string reads as
#         a statement boundary. The must-FAIL fixture used a COMMA, so one character separated
#         the covered case from the uncovered one.
#     (b) `|| { [[ -n "$V" ]] && exit 1; }`                a CONDITIONAL abort.
#     (c) `d=$( … || { echo err >&2; exit 2; } )`          `exit` in a command substitution exits
#         the SUBSHELL; the parent continues with d="". Reproduced live.
#     (d) `d=$(mktemp -d); command -v jq >/dev/null || { echo SKIP; exit 0; }`   an UNRELATED
#         abort on the same physical line, credited to the operand by an unbounded `.*`.
#     (e) `|| { echo "…" >&2; return 1; }` at top level    `return` outside a function does not
#         abort. Reproduced live: it created a .git in the probe's CWD.
#
#   Recognising a brace group correctly requires quoting, statement-boundary, subshell-scope and
#   function-scope analysis — shell semantics a line-oriented regex cannot supply. Since a
#   widening that silences a genuinely unguarded site is strictly worse than the false positives
#   it removes, the eight are acknowledged here instead. An additional 54 command-substitution
#   bindings in the corpus use the MULTI-LINE brace spelling, which no single-line pattern reaches
#   at all.
#
#   apps/web-platform/infra/cloud-init-inngest-bootstrap.test.sh  (1 site)
#     LATEST_TAG=$(git -C "$SCRIPT_DIR" tag --list 'vinngest-v*' ...)
#     `tag` is unscoped in OPERAND_WRITE, so `tag --list` -- a READ -- is counted as a write. The
#     operand is also provably non-empty: the file is `set -euo pipefail` with no toggles and
#     binds SCRIPT_DIR="$(cd ... && pwd)", so a failed cd fails the assignment and errexit aborts
#     before the site. A guard was added here during the burn-down and REMOVED on review: it was
#     unreachable on both counts, and this file's own rule is that a vacuous guard is worse than
#     an acknowledged row. Scoping `tag`/`branch`/`config` to their mutating spellings is a
#     detector narrowing and belongs with the P1b scanner work, not here.
#
