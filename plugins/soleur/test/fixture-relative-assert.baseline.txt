# P1b baseline -- operands that are neither provably absolute nor guarded (#7708).
#
# SHRINK-ONLY, ROW BY ROW. A row may fall; a row may not rise, and a new path may not appear. The
# suite diffs every row, not the sum: enforcing only a total is direction-blind on the row axis,
# and a compensating edit (one file 19 -> 0, another +19) passed it. Regenerate with
#   bash plugins/soleur/test/fixture-relative-assert.test.sh --write-baseline
# and only in the same commit as the source edits that earned the shrink.
#
# WHAT THIS IS NOT. These are NOT 2071 defects. P1b asks whether an operand can be RELATIVE, or be
# rooted at `/` by an empty parent. It does not assert any of these is reachable with such a value
# today. The rows are the residue left AFTER the scanner resolved what it could: mktemp in every
# form, one-line and multi-line same-file wrappers, and wrappers reached through a sourced helper
# (399 source directives in the corpus, 158 carrying a literal path tail, 142 resolving to a
# tracked file). What remains is dominated by roots the scanner cannot see through: never-bound
# globals, positional parameters from a caller, and uses that textually PRECEDE their binding.
#
# EVERY FAMILY IS GRANDFATHERED, measured against the repo fix-inline threshold of 100 lines and
# 4 files:
#
#   family      sites  files
#   git -C         39     12
#   rm -rf        274    114
#   redirect     1550    264
#   mv / cp -r    208     98
#
# An earlier revision of this change claimed the git -C family had been burned to 0 across 3 files
# and remediated it inline. That claim was an artefact of an unsound detector, not a result: the
# rule was clearing sites with guards that do not answer its question (see below). Under the
# corrected rule the family is 39 sites over 12 files -- past the threshold like the other three --
# so nothing is remediated inline here and the burn-down is tracked whole.
#
# WHAT A GUARD HAS TO PROVE. This rule asks about RELATIVITY, so only a predicate that REFUSES a
# relative path counts. It previously reused P1a's EMPTINESS set unchanged, and four of those five
# arms clear a relative site while proving nothing about it -- measured, each cleared
# `local d="$1/repo"; rm -rf "$d"`:
#
#   : "${d:?empty}"             refuses empty and unset; says nothing about relative
#   [[ -n "$d" ]] || exit 1     the same predicate, spelled long
#   case "$d" in *) : ;; esac   a catch-all that asserts nothing
#   mkdir -p "$d" || exit 1     `mkdir -p relative/dir` SUCCEEDS, so the abort proves the OPPOSITE
#
# Two forms are recognised now: `assert_fixture_dir` (whose case has an explicit relative-refusing
# arm) and an inline `case` carrying both a `/*` accept and an aborting default. Section C2 of the
# suite pins all four weak spellings in the FAIL direction, so re-widening the set reddens there
# and not only in a count arm whose message tells the reader to regenerate.
#
# THE COUNT HAS MOVED IN BOTH DIRECTIONS, and every move is a detector change, not a code change:
#
#   982  -> 1114   fixing two bugs that made sites look SAFE: a one-line function body was never
#                  read (`range(hi, lo, -1)` is empty when hi == lo), and `mktemp -d "$R/c.XXXXXX"`
#                  was classified absolute when a path-bearing template inherits its prefix.
#   1114 -> 1089   the git -C inline remediation of that revision (since retracted, see above).
#   1089 ->  909   teaching the resolver to read a binding on the SAME LINE as its use, which had
#                  been reported never-bound while its root was plainly mktemp.
#    909 ->  913   a sibling merge adding four sites in new files.
#    913 -> 2071   the review corrections: the guard set above, plus bounding the guard window at

#                  plus three more mktemp forms that are not absolute (`mktemp -d tmp.XXXXXX`,
#                  `-dp "$R"`, `-d -p"$R"`), `mv -f` binding the SOURCE instead of the destination,
#                  a same-line rebind that FOLLOWS its use, a wrapper fallback that credited any
#                  mktemp in the body regardless of what the function emitted, and brace counting
#                  that read `{` inside a string.
#
# A future change that SHRINKS this file deserves the scrutiny a growth would get. From the count
# alone, a better resolver and a detector that stopped looking are indistinguishable -- and every
# defect found in review so far has been in the shrinking direction.
#
