## LinkedIn Personal

A yes only covers what it saw. I learned that when an AI-built change passed review, picked up one more fix, and that fix went live on the old sign-off.

The rule that let it through asked "is there an approval?" It never asked "does the approval cover this exact version?" So I changed the rule: my agents put nothing live if anything changed after the last full approval. I tested it against the change that slipped, and it refused. I tested it against a fully reviewed change, and it allowed it. Every merge step my agents run now does that check; a few background bots are next.

A second lesson came out of the same week. A helper handed an open-ended job with no step limit sat for about 3 hours and produced nothing. Re-briefed narrowly, with a cap on its steps, it answered in under 2 minutes.

If you build with AI, the question before anything ships is not whether an approval exists. It is whether the approval covers the exact version going live. More on how I build this way at https://soleur.ai/?utm_source=linkedin-personal&utm_medium=social&utm_campaign=approval-covers-the-version
