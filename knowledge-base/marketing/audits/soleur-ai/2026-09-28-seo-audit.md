# SEO/AEO Audit Report

**Date:** 2026-09-28 | **Target:** <https://soleur.ai> | **Type:** seo-audit
**Site:** Soleur | **Pages:** ~62 sitemap URLs from source (1 home + 30 pages + 31 blog posts), up from 49 on 2026-05-25

## Scope and method

- **Source audit of the whole inventory.** I read `eleventy.config.js`, `_data/site.json`, `_data/pillars.js`, `_data/stats.js`, every `_includes/*.njk`, `sitemap.njk`, `llms.txt.njk`, `robots.txt`, `blog/blog.json`, the frontmatter of all 31 blog posts and 30 pages, and the JSON-LD in the homepage, `/about/`, the pillar pages and the two most recent posts.
- **No live verification this run.** `WebFetch` and `curl` were both blocked by the cron-containment sandbox (`tool class not permitted` / `not allowlisted`), and there is no `_site/` build in the checkout. Every finding below comes from templates and frontmatter. Findings that depend on rendered HTML (Eleventy's `page.url`, filter output) were derived from the template logic. None could be confirmed against production bytes.
- **Series gap (added by the orchestrating run).** Issue #8460 (2026-09-21) reported 90 (A−), flat against 2026-09-14. Neither run's report file is in the repository, so this audit compares against 2026-05-25. Do not read 90 → 81 as a one-week drop. Treat 81 as the new baseline.
- **Different method from the previous audit.** The 2026-05-25 audit sampled 5 live URLs. This one scanned all ~62 sources but fetched nothing live. Some of the score change comes from that wider coverage, not only from regressions (see Delta).

## Warnings

### P1 -- `faq-schema-without-visible-faq`

These 5 blog posts emit a `FAQPage` JSON-LD block, but none of the questions appear anywhere in the post body:

- `plugins/soleur/docs/blog/2026-09-26-beta-testers-went-quiet.md` (3 Qs)
- `plugins/soleur/docs/blog/2026-06-12-loop-engineering-for-your-whole-company.md` (3 Qs)
- `plugins/soleur/docs/blog/2026-05-12-company-as-a-service-platform.md` (5 Qs)
- `plugins/soleur/docs/blog/2026-03-29-credential-helper-isolation-sandboxed-environments.md` (4 Qs)
- `plugins/soleur/docs/blog/2026-03-29-your-ai-team-works-from-your-actual-codebase.md` (5 Qs)

Google's structured-data rules require marked-up content to be visible on the page. Markup for hidden content can be ignored, or in the worst case earn a spammy-structured-data manual action. AI engines that compare markup against visible text also see a mismatch. The other 25 posts already use the correct pattern: a visible `<details class="faq-item">` list mirrored by JSON-LD (see `2026-09-25-parked-vs-forgotten-ideas.md`).

### P1 -- `pillar-blog-keyword-cannibalization`

It is infrastructure." word for word. Same OG image. Both call themselves "pillar": the hub page labels itself "Pillar Guide", and `_data/pillars.js` marks the blog post as the pillar. |
| `/compare/soleur-vs-devin/` | `/blog/soleur-vs-devin/` | Same comparison, same OG image. |

### P1 -- `conflicting-author-entity`

The founder's `Person` node (`@id` `https://soleur.ai/about/#jean-deruelle`) is defined two different ways:

- **`/about/` `ProfilePage.mainEntity`** (`pages/about.njk`): `sameAs` = `site.x` (`@soleur_ai`), `site.linkedin` (`linkedin.com/company/soleur`), `site.github` (the `jikig-ai/soleur` repo) and `site.bluesky`. These are the **company's** accounts.
- **Every `BlogPosting.author`** (`_includes/blog-post.njk`): `sameAs` = `site.author.sameAs`, which is the **personal** accounts (`github.com/deruelle`, `x.com/deruelle`, `linkedin.com/in/jeanderuelle`).

Entity resolution (Knowledge Graph, AI answer engines) receives two contradictory identity claims for one `@id`, and the canonical one says the person is the brand. The visible link list on `/about/` has the same problem. A second inconsistency: `site.linkedin` (`/company/soleur`) and `site.linkedinCompany` (`/company/jikigai`) are both used for "the company LinkedIn". The Organization `sameAs` and footer use one, `/about/` uses the other.

### P2 -- `undated-pillar-pages`

- `/ai-agents-for-solo-founders/`
- `/ai-cto/`
- `/ai-cmo/`
- `/claude-code-plugins/`
- `/agentic-engineering/`
- `/solo-founder-ai-stack/`
- `/company-as-a-service/`
- `/glossary/`

Several put "(2026)" or "2026 Guide" in the title, which invites a freshness check they cannot pass. The `page-freshness.njk` partial built for this (#3170) is used only on about, agents, skills, pricing, vision, getting-started and the two compare pages.

### P2 -- `sitemap-lastmod-inaccurate`

`sitemap.njk` sets `<lastmod>` from `entry.date`, which causes three problems:

1. **Blog `updated:` is ignored.** `/blog/soleur-vs-paperclip/` and `/blog/soleur-vs-polsia/` were updated 2026-07-20 but report lastmod 2026-03-31 and 2026-03-26. `/blog/soleur-vs-anthropic-cowork/` and `/blog/why-most-agentic-tools-plateau/` have the same problem. The base `WebPage.dateModified` also uses `page.date`, so it disagrees with the `BlogPosting.dateModified` on the same page.
2. **Getting-started dates disagree.** `pages/getting-started.njk` has `date: 2026-06-01` but `last_updated: 2026-09-11`. The page shows "Last updated Sep 11", while the sitemap and JSON-LD say June 1. `page-freshness.njk` itself says to keep the two equal.
3. **Undated pages likely get build-time dates.** Roughly 22 pages have no `date:`: the 8 pillars above plus `/community/`, `/changelog/`, `/blog/`, `/goal-primitive/`, `/legal/` and 9 legal docs. For these, Eleventy falls back to the file's creation time, which on a fresh CI checkout is the build time. If so, lastmod changes on every deploy. Google stops trusting a site's lastmod when it proves inaccurate.

### P2 -- `homepage-og-title-brand-only` (carried over from 2026-05-25 P1, still open)

`index.njk` has `title: Soleur`, so `og:title` and `twitter:title` render as just "Soleur". The `<title>` uses `seoTitle` ("Soleur — AI Agents for Solo Founders | Every Department, One Platform"), but `base.njk` lines 8 and 19 build the social titles from `title` and never read `seoTitle`.

### P3 -- `jsonld-graph-unlinked`

- The base `WebPage` node has no `@id`.
- The `publisher` Organization on non-home pages has no `@id` (the homepage defines `/#organization`).
- `BlogPosting` sits in a separate script and points `mainEntityOfPage` at an `@id` that no `WebPage` node declares.

The markup is valid, but the nodes do not connect into one entity graph. Referencing `{"@id": site.url + "/#organization"}` and giving `WebPage` an `@id` of its URL would link them.

### P3 -- `about-page-profile-polish` (carried over from 2026-05-25 P3)

- `/about/` still renders `og:type=website` and should be `profile`.
- The `ProfilePage` Person has no `image`.
- The author image across the site is an SVG illustration (`/images/jean-deruelle.svg`). A real raster headshot is a stronger experience signal, and SVG is not a supported image format for Google's Person/Article image fields.

## Passed Checks

- **Canonical host:** `site.url`, `CNAME`, `robots.txt` Sitemap line and feed base all use apex `https://soleur.ai`. The CI gate fails the build on any rendered `https://www.soleur.ai` reference. Edge 301 www to apex is probed on every deploy.
- **Canonical tag:** `<link rel="canonical" href="{{ site.url }}{{ page.url }}">` appears on every page.
- **Open Graph and Twitter:** title, description, url, type (`article` on blog via `blog.json` and on pillar pages), site_name, `og:locale=en_US`, image with width/height/alt, `summary_large_image`, `twitter:site` and `twitter:creator`. Every blog post has its own `ogImage`, and the two newest images exist in `images/blog/`.
- **Page-specific titles and descriptions:** every blog post and page sets `description`. Most also set `seoTitle`.
- **JSON-LD coverage** (all server-rendered, all interpolations through `jsonLdSafe`):
  - Homepage: WebSite + WebPage + Organization (logo, founder, sameAs, `subjectOf` Inc.com) + SoftwareApplication (2 Offers) + FAQPage.
  - Blog posts: BlogPosting with full Person author.
  - Pillar and compare pages: Article + FAQPage.
  - About: ProfilePage + Person + FAQPage.
  - The homepage-only condition for SoftwareApplication and Organization is correct.
- **robots.txt:** `User-agent: *`, `Allow: /` and a Sitemap line. No Disallow, so GPTBot, ClaudeBot, PerplexityBot, Google-Extended and OAI-SearchBot are all allowed.
- **llms.txt:** H1, blockquote tagline, description, `## Use Cases`, `## Docs`, `## Optional`. Absolute URLs and counts come from `stats.*`.
- **Static rendering:** all content is Nunjucks/Markdown rendered at build time. JS is limited to the stylesheet swap, Plausible and form submission.
- **Sitemap:** built from `collections.all`, restricted to trailing-slash canonical URLs (redirect stubs excluded), `lastmod` on every entry, excluded templates (`sitemap`, `llms.txt`) use `eleventyExcludeFromCollections`.
- **E-E-A-T on blog posts:** visible byline with `rel="author"`, `<time datetime>` for published and updated, author card with bio and credentials, `/about/` page, legal and privacy pages linked in the footer, status page link.
- **Headings:** a single H1 per template, then H2 and H3 in order. Newsletter and footer headings are H2 and H3 after the main content.
- **Link text:** no "click here" or "read more" anchors. The only "Learn More" is an H3 heading on `/getting-started/`, not a link.
- **Images:** the only `<img>` in templates (author card) has alt, width/height, `loading="lazy"` and `decoding="async"`. No Markdown images in posts.
- **Core Web Vitals (source):** critical CSS is inlined, with the screenshot-gate rule `cq-eleventy-critical-css-screenshot-gate`. The full stylesheet loads async via a CSP-hashed swap script. Both webfonts use `font-display: swap`. Plausible loads `async`. No hero raster images.
- **Technical:** `lang="en-US"`, UTF-8 charset, viewport, Atom feed `<link rel="alternate">`, strict CSP with `upgrade-insecure-requests`, favicon.

## Recommendations (prioritized)

### P1

1. **`faq-schema-without-visible-faq`**
   - In each of the 5 posts, add a visible `## Frequently asked questions` section using the existing `<div class="faq-list"><details class="faq-item">...` pattern. The questions and answers must match the JSON-LD `name` and `text` word for word.
   - If a post should not show a FAQ, delete its JSON-LD block instead.
   - Consider adding a `validate-seo.sh` check that fails when a page's `FAQPage` question names do not appear in its visible HTML.
2. **`pillar-blog-keyword-cannibalization`** -- for each pair, choose which URL owns the head term.
   - **Consolidate:** when the post is the older, thinner duplicate (e.g. `/blog/ai-agents-for-solo-founders/` versus the hub), merge the unique content into the hub and add an edge 301 through the existing Cloudflare Bulk Redirect list (`seo-bulk-redirects.tf`). Update `_data/pillars.js` so the series links to the surviving URL.
   - **Differentiate:** when both should stay, retitle the post toward a distinct long-tail intent (e.g. "…: what we learned running it for 6 months"), rewrite the copied lead paragraph, and give it its own OG image.
   - For the `/compare/*` versus `/blog/soleur-vs-*` pairs, a short compare page plus a long-form blog post works only if the titles target different queries. Today both target "Soleur vs X".
3. **`conflicting-author-entity`**
   - In `pages/about.njk`, change the `ProfilePage` Person `sameAs` to `{{ site.author.sameAs | jsonLdSafe | safe }}` and add `"image": site.url + site.author.image`.
   - Change the visible link list in the `#jean-deruelle` section to the personal profiles. The company links belong in the "About Soleur" section.
   - In `_data/site.json`, settle on one company LinkedIn URL (`linkedin` or `linkedinCompany`) and remove the other.

### P2

4. **`undated-pillar-pages`**
   - Add `date:` and `last_updated:` (equal values) to the 8 pillar pages and include `page-freshness.njk` in each.
   - Add `"datePublished"` and `"dateModified"` to their `Article` JSON-LD, using the existing `dateToRfc3339` filter.
5. **`sitemap-lastmod-inaccurate`**
   - In `sitemap.njk`, use `(entry.data.updated or entry.data.last_updated or entry.date) | dateToShort`.
   - Apply the same fallback to `WebPage.dateModified` in `base.njk`.
   - Set `date` equal to `last_updated` in `pages/getting-started.njk`.
   - Give every undated page an explicit `date:`, or set `date: git Last Modified` in a directory data file, so lastmod stops moving on every build.
6. **`homepage-og-title-brand-only`**: in `base.njk` lines 8 and 19, use `seoTitle` when it is set: `{{ seoTitle or title }}…`. Or add a dedicated `ogTitle` frontmatter key.
7. **`generic-og-image-alt`**: add `ogImageAlt:` describing each card image to the 30 remaining blog posts and the pillar pages. Consider a build warning when `ogImage` is set but `ogImageAlt` is not.

### P3

8. **`overlong-seo-titles`**: trim the 9 listed `seoTitle`s to 60 characters or fewer, with the primary keyword first.
9. **`reused-og-images`**: generate unique OG cards for the 2 posts and the hub pages, which fits with P1 #2.
10. **`llms-txt-coverage-gap`**: add a `## Guides` section to `llms.txt.njk` listing the 7 hub and compare pages plus `/glossary/`, and optionally the 5 pillar blog posts. Make the "8 jobs / 9 hats" wording consistent everywhere, and take the marketing agent count from `stats` or drop it.
11. **`jsonld-graph-unlinked`**: in `base.njk`, add `"@id": site.url + page.url + "#webpage"` to `WebPage` and set `publisher` to `{"@id": site.url + "/#organization"}`. Point `BlogPosting.mainEntityOfPage` at that same `@id`.
12. **`about-page-profile-polish`**: set `ogType: profile` in `pages/about.njk` frontmatter, and replace the SVG author image with a raster photo (at least 400x400 JPG/PNG/WebP).
13. **`pillar-series-orphan-member`**: add `/blog/beta-testers-went-quiet/` to `members` under `billion-dollar-solo-founder` in `_data/pillars.js`, or remove its `pillar:` key.
