# ADR-290: Shrink-only lint ratchet keyed on path, rule and anchor

## Context

GitHub Code Quality reported 169 findings on `main` (tracker #10331). Most were the recurring habits of agent-written code: unclosed files, empty handlers, unused imports and bindings. The repository needed deterministic linters in its own gates, and existing findings could not all be fixed in the PR that introduces a linter (shipped scripts are a brand-risk surface), so each linter needs a baseline that can only shrink.

The existing count ratchets (`apps/web-platform/test/eslint-config.test.ts`, 192 findings) are rename-blind: a count survives a file being swapped for another. They also live inside a required-context test, so folding new directories into them would force a re-baseline of an unrelated gate.

Alternatives rejected:

- **A count highwater file per scope.** Rename-blind and swap-blind; the brainstorm CTO ruling already chose identity keys over counts.
- **An advisory CI job (as `lint-webplat` is).** It cannot block a regression, which is the whole point.
- **Extending the web-platform `eslint .` run and its 192-count test.** It would re-pin that required-context test's counts and file-count floors for directories it does not own.
- **A `(digest, epoch)` header, or an anchor-at-merge-base lookup, to police baseline edits.** A header that carries its own hash certifies itself, and the lookup was vacuous for generic lines while making an in-place edit of a baselined line a dead end (plan review, CTO rulings of 2026-10-16).

## Decision

`plugins/soleur/scripts/lint-ratchet.py` owns two Soleur scopes, `ruff` and `eslint-test-dirs`, each with a baseline file (`scripts/lint-ratchet-<scope>.baseline.txt`) of entries `path|rule|anchor|n`. `anchor` is the first 12 hex of the sha256 of the finding's whitespace-normalised source line (the text is never stored); `n` is the ordinal among identical `(path, rule, anchor)` triples. `--check` enforces, in order: the baseline exists; the tool ran and its report parsed; the scan saw at least a floor of files (ruff 55, eslint 105); the baseline EQUALS the live census (a new finding fails, and so does a stale entry); and per `(path, rule)` the baseline never holds more entries than at the merge base (the Soleur scopes; user mode adds the toolchain-fingerprint exemption of Amendment 1), after applying `git diff -M30%` renames measured against the working tree (so a staged `git mv` passes at pre-commit time). `--update` rewrites the baseline from the live census and refuses to grow it; `--list` prints the live findings.

Before the comparison the scan must also be TOTAL (the Soleur scopes; user mode keeps the checks listed in Amendment 1): every tracked file in scope has to appear in the tool's own file list (ruff: the `--show-files` listing, minus the declared `knowledge-base/` exclusion; eslint: every tracked, non-symlink file matching the scope globs and the eight JS/TS extensions), a file ruff could not read is a failure rather than a smaller census, and the file-count floor stays as a backstop. The baseline is refused when it, or any directory above it, is a symlink, or when it carries a duplicated line, `--update` applies the same floor and, when a baseline already exists, refuses to run if no merge base resolves, and under `CI` a baseline that is missing at the merge base is accepted only when the ratchet script at the merge base does not yet define that scope (the PR that introduces the scope, whether it also introduces the script or adds a scope to an existing one). Any unexpected `Exception` exits 2, never 1 (only `KeyboardInterrupt` and `SystemExit` pass through).

Counting is waiver-proof for the Soleur scopes (ruff `--ignore-noqa`, eslint `--no-inline-config`; user mode honours the user's own waivers) and no tool runs in a fix mode. Ruff is provisioned by the script itself: `plugins/soleur/scripts/ruff-requirements.txt` pins `ruff==0.16.10` with a sha256 for each of the 17 wheels, installed with `pip --isolated --require-hashes --only-binary=:all:` into a per-user `0700` cache with ownership checks and a scrubbed `PIP_*`/`PYTHON*` environment. A hash mismatch is exit 2 everywhere; an unreachable index is a loud `SKIP` locally and exit 2 under `CI`. `ruff.toml` selects `SIM115`, `S110`, `S112`, `F401`, `F841` with `check-typed-exception = true`.

Registration: a `run_suite` pair (`tests/scripts/lint-ratchet`, `scripts/lint-ratchet-ruff-live`) in the required `test` context, both always-on in `scripts/lib/test-affected-paths.sh`; the eslint live arm is `apps/web-platform/test/eslint-test-dirs-ratchet.test.ts` (in `REPO_WIDE_SUITES`); two lefthook pre-commit entries with dual globs. Exit codes: 0 clean, 1 drift or vacuity, 2 infrastructure.

**Control.** CODEOWNERS is documentation only here: the repository has a `* @deruelle` fallback and no ruleset requires code-owner review. The controls are the merge-base comparison, the pin tests in `tests/scripts/test_lint_ratchet.py` (the whole parsed `ruff.toml` document, a sha256 of the eslint config, both scope tuples and both floors), a registration test that fails when a `run_suite` line, an `ALWAYS_ON_SUITES` entry, a lefthook entry or the vitest manifest entry is deleted, and human PR review of the tooling. The pin tests cover the Soleur scopes only; a user's ruff configuration is the user's, and Amendment 1 states what stops it from silently weakening the ratchet.

**PR3b contract (realized, see Amendment 1).** The entry format, the exit codes and the scope-config dict that `check()` takes (`name`, `baseline`, `floor`, `run`, `remedy`, optionally `script`, `recovery_cmd` and the user-mode keys listed in the module docstring) are the interface; `run(root)` returns `(findings, file_count)` and may raise `Vacuous`, `InfraError` or `Skip`, and `Skip` propagates to the caller. The script now lives in the plugin tree; the Soleur scopes derive `REPO_ROOT` from the script location, the pins are script-relative, and `SCRIPT_REL` is `plugins/soleur/scripts/lint-ratchet.py`.

**Bumping ruff.** Take the version and one sha256 per wheel from `https://pypi.org/pypi/ruff/<version>/json`, replace the pin and all hash lines in `plugins/soleur/scripts/ruff-requirements.txt`, then run `python3 plugins/soleur/scripts/lint-ratchet.py ruff --update`; any finding the new version adds is fixed or the bump is held.

## Consequences

A new unclosed file, empty handler, unused import or unused binding in tracked Python, or an unused binding in the scoped test and fixture directories, now fails `lefthook` and the required `test` context. The 62 ruff and 20 eslint findings that exist today are baselined and tracked for drawdown in #10433; none is fixed here (both baselines were later drawn down to empty, see Amendment 2). A Dependabot eslint bump that moves findings fails the vitest arm and is fixed or held (no escape hatch is built until one is first needed).

Accepted residuals, none of which the check can see:

1. A fix of finding A plus a new finding B inside one `(path, rule)` is invisible: the count is unchanged. A rename at or above the 30% similarity cutoff carries the old file's counts to the new path, so replacing a file with a 30%-similar one that holds different findings of the same rule is invisible too.
2. A rename below the `git diff -M30%` similarity cutoff reads as growth; fix the findings in the same PR.
3. A diff that moves the baseline path is caught under `CI` only while the ratchet script at the merge base defines the scope (the rule above, keyed on `SCRIPT_REL`, which a test pins to this file); a diff that also moves the script or renames the scope presents both as new.
4. The pin tests, the configs and the script can be edited together in one diff, and the script is judged by tests that live in the same diff; only human review stops it. The unit suite's own `run_suite` line, its `ALWAYS_ON_SUITES` entry and its duration row can be deleted together (the registration test lives inside that suite; deleting the line alone is caught by the fast-tier budget suite). On a push to `main` the merge base equals `HEAD`, so the comparison is vacuous there and the baseline-equals-census check is the only gate.
5. The scan is an enumerated list, not a property of the repository: a Python file with no `.py`, `.pyi` or `.pyw` extension (a shebang script, a notebook), and a JS/TS test file outside the four eslint scope globs (for example `tests/`, a nested `scripts/**/*.test.mjs`, or a `lib/` test), is never scanned and a totality check cannot see it. None is tracked today. By design, Python in any directory named `knowledge-base` (archived spec scratch) is excluded wholesale; a tracked `node_modules/` path or a symlink to content outside the scope is skipped silently; and a fixture that deliberately contains a syntax error cannot be added, because ruff reports it as a finding and the baseline cannot grow.
6. `--update` and the anchors read the working tree, so a partially staged commit can disagree with the index; the full-tree run in CI is the backstop. Deleting a baselined file stages a deletion that no lefthook glob sees, and the stale entry surfaces only in CI.

Two PRs that each delete one of two identical baselined lines merge cleanly and leave a stale `n=1`; the stale message and the baseline header say to take the base branch's copy and re-run `--update`. Anchors are read from the working tree, so a partially staged commit can disagree with the index; the full-tree CI run is the backstop.

## Amendment 1 (2026-10-18, slice 2 of #10331: user repositories)

Realizes the PR3b contract. The engine and its pinned ruff now ship in the plugin (`git mv` of `scripts/lint-ratchet.py` and `scripts/ruff-requirements.txt` to `plugins/soleur/scripts/`). The pin and the 17 hash lines are unchanged; two comment lines that named the old path were re-pointed, so the cache key (the sha256 of that file) changed once and each machine re-installs ruff one time. The Soleur baselines, `ruff.toml` and the eslint config stay where they are: moving a baseline in the same diff as the script trips residual 3 and exits 2 in CI. All forks were ruled by the CTO agent (`knowledge-base/project/specs/archive/20261019-123512-feat-one-shot-10331-plugin-detect-and-run/decision-challenges.md`); the review round amended some rulings, each recorded there. The Soleur scopes print what they printed before, except for the script path a cap of 25 lines per NEW or STALE class with a pointer to `--list`, and a 200-character clip per echoed field and 600 per line (a golden test pins the rest against the fork point). Count correction for Consequences above: after slice 1 the ruff baseline holds 44 findings, not 62.

**Scopes.** Two new CLI scope names, `user-ruff` (`--check`, `--update`, `--list`) and `auto` (check only). They are not in `SCOPES`, so the Soleur names keep their meaning in lefthook, `test-all.sh` and the vitest arm; the Soleur scopes run only from a Soleur checkout (`build_config` refuses otherwise, with exit 2, also from a copy placed too shallow to have a repository root). `auto` and `user-ruff --check` share one decision function, `classify_user`, which every user verb calls; it runs git but never provisions or runs ruff. `work` and `review` call `auto` behind a guard that is a skip, not an exit 1, when `CLAUDE_PLUGIN_ROOT` is unset or `python3` is missing, so an agent never runs a repo-local copy.

**Adoption is opt-in.** User mode is Python-only and active only when a tracked root `ruff.toml`, `.ruff.toml`, or a `pyproject.toml` with a `[tool.ruff` table (any TOML spelling of that header) exists AND a baseline file is present at `.lint-ratchet/ruff.baseline.txt` in the working tree (not under `.soleur/`, which is gitignored-ephemeral by convention). An untracked baseline is read, with a note to `git add` it, or to remove the ignore rule when it is git-ignored. A repository without a baseline gets one informational line and nothing is installed or run; every verdict that needs no ruff (including an unreadable or conflicted baseline) is decided before provisioning, and an unsafe root config (symlink, not a regular file, over 1 MiB) costs a repository that never adopted nothing (it is mentioned on stderr) and is `REPO-CONTENT:` exit 2 once a baseline exists anywhere (working tree, HEAD or merge base); a symlinked or non-regular `.lint-ratchet` follows the same rule. The user's own config decides the rules and waivers (no `--config`, no `--ignore-noqa`; `--no-fix --no-fix-only`, because `fix-only = true` otherwise rewrites the tree). Adoption is judged at the root; nested configs apply per file and are fingerprinted (below). The user verdict also reports what an `OK` would hide: tracked `.py` symlinks and untracked `.py` files are not scanned.

**Deletion cannot dodge the ratchet.** A baseline present at the merge base and missing from the working tree is exit 1 (`baseline deleted since the merge base`), also under `CI`; a baseline with no ruff config detected is exit 1; a committed baseline missing from the tree with no resolvable base is exit 2 under `CI` and a warning locally, never `not adopted`. Under `CI` a repository with a ruff config and no baseline anywhere also exits 2 when no merge base resolves (a shallow checkout cannot tell a repository that never adopted from one whose baseline this change deleted; fetch with `fetch-depth: 0`). **Accepted cost:** un-adopting on purpose with `git rm -r .lint-ratchet` is red on that branch by construction, because the merge base still has the baseline; it clears once the deletion merges (an admin merge or a CI override). The self-skip for the Soleur repository keys on the running script's identity: `realpath(__file__)` must equal the physical `plugins/soleur/scripts/lint-ratchet.py` of the repository with no symlink on the way, so a file or symlink a PR author plants at that path cannot switch the ratchet off.

**Totality, user mode.** Exit 2 for: a `Failed to`/IO error on stderr, a ruff exit outside {0, 1}, `--show-files` failing, unparsable or mis-shaped JSON, a finding with no rule code (ruff could not parse a file), a reported path outside the repository, a tracked `.py` file whose name is not valid UTF-8, and an unsafe or unreadable baseline. `--show-files` supplies only the file count (no tracked-versus-listed comparison and no `EXCLUDED_DIRS`, which the user's own `extend-exclude` would turn into a permanent false red); there is no numeric floor (zero files is a `WARN`, never `OK`, `--update` refuses to write a zero-file scan over an existing baseline, and an empty listing against a non-empty baseline is the ordinary STALE exit 1). The file list is passed to ruff in chunks of about 24 KB so a large repository cannot hit the platform's argument limit. Causes that are the repository's own content carry the `REPO-CONTENT:` prefix on every verb; toolchain causes (git failing, ruff missing, a timeout) never do.

**Toolchain fingerprint, no flag.** The baseline header `# toolchain: ruff <pin> ; config sha256:<16hex>` hashes every TRACKED ruff config, the root `ruff.toml`, `.ruff.toml` and the `[tool.ruff...]` tables of `pyproject.toml`, and likewise the nested ones (ruff applies the nearest config to each file; an untracked config is not hashed because CI would not see it). The merge-base growth comparison is skipped only when the merge-base header differs from the working-tree header AND the working-tree header equals the live fingerprint AND the plugin is not older than the ruff that wrote the merge-base baseline; `check` and `update` apply that one predicate. `check` then prints `CONFIG CHANGED vs merge base: shrink-only not enforced; review the config diff` and never a plain `OK`; a missing header means unknown (no exemption). A baseline whose header is stale (config or pin changed, baseline not yet refreshed) prints `WARN` first, never `OK`. `--update` with a plugin older than the baseline's ruff exits 2 ("update the plugin") instead of rewriting the header downward. **Tension with the rejected self-certifying header** (Context): here the header is a bounded exemption that `review` raises as a P2, not a trust root; editing only the header buys nothing because the merge-base header must differ from the live fingerprint. **Accepted residual:** an agent can edit the config, run `--update` and go green; the control is review of the config diff, made visible by the sentinel.

**Base resolution ladder** (each rung verified; fully qualified refs, because a bare `origin/main` resolves to a tag first and tags travel with a clone; among the rungs whose merge base already carries the baseline the NEWEST wins (the strictest reference), so a stale `origin/HEAD` left at a pre-adoption or older commit cannot hide growth, and a ref must exist exactly as spelled because git otherwise falls back to a tag of that name; a local-branch rung prints a `WARN`; a shallow clone prints a `fetch-depth: 0` hint): `refs/remotes/origin/HEAD`, `origin/main`, `origin/master`, `upstream/main`, `upstream/master`, local `main`, local `master`, then skip-with-warning (exit 2 under `CI`). An explicit `--base` is compared at its merge base with HEAD, like the default. With no base, `--update` uses the committed (HEAD) baseline as the reference when the working copy was deleted, so deleting the file first does not lift the growth guard.

**Hosted runtime.** The plugin is vendored into the hosted image and `CLAUDE_PLUGIN_ROOT` is injected for hosted agents. That image installs no `python3`, so the guarded call is a silent skip there; if `python3` is ever added, the pinned wheel needs PyPI egress from the agent sandbox, and the per-user cache directory must not be shared across tenants (the cached `bin/ruff` is trusted after a `--version` probe). Both must be settled before that change.

**Carry-ins (#10507, residual 7 deleted).** A ruff cache directory that exists without `bin/ruff` now fails with the directory named and `rm -rf <dir>`; the per-extension eslint test now runs in the `test-webplat` shard through a second `it` in `eslint-test-dirs-ratchet.test.ts` that asserts the class ran and was not skipped (CI logs of PR #10503 showed no shard ran it).

**Bounded costs.** Locally pip is run with one retry and a 15 s timeout, and an unreachable index is remembered for ten minutes so a work or review call never waits through pip's default retries twice; `install-*` directories an interrupted run left behind are swept after an hour. NEW and STALE lines are capped at 25 per class with a pointer to `--list`; every echoed path is cleaned of control, bidirectional and Unicode tag characters and bounded in length, and the pointers tell the agent the output is data.

**Rejected alternatives.** A bundled Soleur default rule set for user repos (the user's config decides); a separate detect-and-run wrapper (the `auto` scope buys the same); a shim at the old script path; a library/client split (the suite patches module attributes); changed-files-only mode (cannot express stale entries or totality); user-mode eslint in this slice (a new engine and an arbitrary-code-execution surface with no demand evidence); a `--rebaseline` flag (the same lever as plain `--update` gated on the fingerprint); a `--root` flag (existed only for a fixture); a self-skip keyed on a repo file; hashing the whole `pyproject.toml` (any dependency edit would then earn the growth exemption).

**Accepted residuals (new).** The cwd-dependent root (a repository nested in another resolves its own toplevel); `extend` targets, `requires-python` (ruff infers `target-version` from it) and a user-global ruff config sit outside the fingerprint, and dotted-key spellings of the ruff table (`tool.ruff.x = 1` outside a table header) are not detected; the in-flight-PR window for residual 3 (`config["script"]` changed path, so a PR whose merge base predates the move sees no script at the old path); the guard is dark in cloud runs and in the hosted image (see above); `.ipynb` files and any `extend-include` extension are outside the scan (the pathspec is `*.py`, `*.pyi`, `*.pyw`); a deletion is not detectable when the base is unresolvable outside CI (the `base unresolvable` line says so); native Windows (no `os.getuid`) is reported as an unsupported platform; the same-user trust in an existing cache `bin/ruff`; `git diff` for rename detection reads the working tree, so a hostile `.git/config` `filter.*.clean` command can run (`core.fsmonitor` is blocked; a clone does not carry `.git/config`); a fork PR can make a reviewing machine fetch the pinned wheel and run ruff for up to two 900 s runs by committing a config and a baseline. The pinned wheel is fetched from PyPI over TLS and verified by sha256 for each of the 17 wheels; a TLS-intercepting proxy is trusted by the user. Precedents for a shipped user-machine surface: ADR-178 and ADR-254. Without Soleur a team can run the same ratchet in CI with `python3 <plugin>/scripts/lint-ratchet.py user-ruff --check` and `fetch-depth: 0`. Deferred follow-ups (JS/TS, monorepo, telemetry, streaming of very large reports, a shared deadline for `auto`) are tracked in #10515.

Tracker: Ref #10331. Drawdown: #10433.

## Amendment 2 (2026-10-19, slice 3 of #10331: baselines drawn down to empty)

Both Soleur baselines, `scripts/lint-ratchet-ruff.baseline.txt` (44 entries, 49 findings) and `scripts/lint-ratchet-eslint-test-dirs.baseline.txt` (20 entries, 27 findings), now hold no entries, so the two scopes behave as plain zero-findings gates. The fixes preserve behaviour: silenced handlers use `contextlib.suppress` or a sentinel assignment, file handles use `with` or `Path.read_text`, and dead bindings are deleted. The engine and its suite are untouched. Removing the `DRAWDOWN` constant and the baseline header lines is tracked in #10583.

Tracker: Ref #10331. Drawdown: #10433 (closed by this change).

## Amendment 3 (2026-10-20, #10583: drawdown plumbing removed)

The `DRAWDOWN` constant, the `drawdown` scope-config key and the `# Drawdown tracking` header line are removed. `render_baseline` now switches between the user form and the Soleur form on `name in USER_SCOPES`. The Soleur baseline header is a short zero-findings-gate header, and a test pins both committed Soleur baselines to the rendered empty form.
