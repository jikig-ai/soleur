# ADR-304: Headless Pencil adapter runs on @pen.dev/cli behind a stable tool surface, with a stale-file save guard

## Context

The headless Pencil MCP adapter (`plugins/soleur/skills/pencil-setup/scripts/pencil-mcp-adapter.mjs`) drove `@pencil.dev/cli` 0.2.9, which npm marks deprecated ("no longer maintained"). The maintained successor is `@pen.dev/cli` (0.3.13 when measured on 2026-10-26; `engines.node >=22.19.0`; bins `pen` and `pencil`). Its `pen interactive` REPL exposes only `execute`, `get_app_state`, `get_style`, `read_skill` and `browser`, plus the shell commands `save()` and `exit()`. The tools the adapter used to forward (`batch_design`, `batch_get`, `get_editor_state`, `get_screenshot`, `export_nodes`, `snapshot_layout`, `get_variables`, `get_guidelines`) answer `Unknown tool:`; their jobs moved inside the `execute` DSL (`TakeScreenshot`, `Export`, `Get`, `GetVariables`, `## issues detected:`).

Agents, hooks (`.claude/hooks/pencil-open-guard.sh`, `pencil-collapse-guard.sh`, keyed on `mcp__pencil__open_document`) and prose all name the `mcp__pencil__*` tools. On a customer machine the adapter's save sentinel is the only protection a design file has, since this repository's hooks do not exist there. The earlier sentinel refused an EMPTY in-memory document over a non-empty file but allowed any save when memory held at least one node, so a session holding 5 nodes could overwrite 8 nodes that landed on disk behind it (`git pull`, a second session, Pencil Desktop).

## Decision

**Engine.** Pin `@pen.dev/cli@0.3.13`, installed from a committed lockfile (`plugins/soleur/skills/pencil-setup/scripts/pen-cli/`) with `npm ci` into its own prefix `~/.local/share/pen-cli`. The adapter resolves only that prefix's `.bin/pen`, whose realpath must equal the package's declared `bin.pen` target (a regular file) and whose package name must be `@pen.dev/cli`. Prefix candidates are the passwd home, then `$HOME` when different; a candidate is used only when the package directory is outside the working directory and `CLAUDE_PROJECT_DIR`, owned by the current uid and not group- or world-writable (CTO ruling, 2026-10-26). `PENCIL_BINARY` in the environment alone is ignored with a value-free WARN; the override is honoured only through the adapter argv flag `--pencil-binary=<absolute path>` that the user-approved registration sets, with the same owner, mode and path-exclusion checks. There is no PATH fallback, so a leftover `@pencil.dev/cli` can never be reached through a shared bin name and is only a warning. Node floor is 22.19.0.

**Tool surface.** The `mcp__pencil__*` names stay, so no hook or `.claude/settings.json` change is needed. The adapter translates eight live tools onto the REPL (`open_document`, `save`, `batch_design`, `get_screenshot`, `export_nodes`, `get_editor_state`, `get_variables`, `read_skill`). Nine tools the engine cannot honour (`batch_get`, `snapshot_layout`, `get_guidelines`, `get_style_guide`, `get_style_guide_tags`, `find_empty_space_on_canvas`, `search_all_unique_properties`, `replace_all_matching_properties`, `set_variables`) are registered as stubs that never reach the engine and answer with a replacement hint from one table. Raw `execute` is not exposed, so no second mutation path bypasses the open and save guards.

**Authentication.** The key resolves from `PEN_CLI_KEY`, else `PENCIL_CLI_KEY` (empty or whitespace counts as unset). The child always receives `PEN_CLI_KEY` only; only the resolved key is redacted, in several encodings (the other name is never forwarded, so it needs no redaction). The existing Doppler value authenticates as `PEN_CLI_KEY`, so the secret is not renamed. An invalid key does not stop the engine (its usage check fails open), so the key-gated probe asserts `pen status` is Active first.

**Still needed from the old design.** `planSpawn` stays, because `pen interactive --out existing.pen` without `--in` still loads an empty document. The `I`/`U` alias preamble stays, because only the long DSL names exist.

**Save sentinel (#11168).** `decideSave` keeps its predicate and refusal text. After it, a separate pure function `decideStale` compares a SHA-256 fingerprint of the document's canonical JSON (raw bytes only when the text does not parse) against a per-process baseline that is captured from the file immediately before a spawn and re-set only after a confirmed `Saved <path>` reply. The capture has exceptions: it is not taken while `refusalPending` is armed or the baseline is `unknown` (a respawn with an `unknown` baseline does not recapture), and a respawn whose pre-spawn capture is `missing` or a hash that differs from a `hash` baseline arms the refusal (`cause=external-change` or `file-missing`) and keeps the old baseline (CTO ruling), because the engine reloaded content the agent never saw. Baseline states are tagged (`none`, `missing`, `hash`, `unknown`). A non-ENOENT read error (EACCES, EISDIR and the like, or a file over the 64 MiB read cap) maps to baseline `unknown` with a capture-failed cause, never to `missing` and never to a pass. Only an exact `hash` match, or a `none`/`missing` baseline that is still missing, may save; one pair is an exception: a `hash` baseline with the file now `missing` behind a LIVE session saves and recreates the file (`recreated`), because the engine's copy is the only one left and nothing on disk can be overwritten (CTO ruling), with a `NOTE:` prefix on the result and one stderr line; the same pair after a respawn still refuses. A stale refusal sets `refusalPending`, which survives a crash respawn until `open_document` succeeds, and echoes the refused operations (capped, redacted) so replay does not depend on agent context. A definite `Save failed: <reason>` keeps the previous baseline and is reported as not persisted (the edit is in memory; call `save` again, do not `open_document`); ambiguous, timed-out, empty or wrong-path replies make the baseline `unknown`. **Marker contract.** The first line of every refusal tool result is `REFUSED save: [reason=<code>] <file> was not modified.` (codes `stale`, `unknown-baseline`, `refusal-pending`, `empty`, `unrecognized`); a non-refusal outcome that did not persist begins `NOT PERSISTED: [reason=<code>] <file> ...` (codes `save-failed`, `unconfirmed`, `save-incomplete`). One `unpersistedEdits` flag is set by either and cleared only by a confirmed save or a successful `open_document`; while set, `export_nodes` and `get_screenshot` replies are prefixed `WARNING: rendered from unsaved memory`. Exactly one `save()` emission site exists. Deleting every top-level node stays refused with no escape hatch (a flag is itself the bypass). **Load fidelity.** One `loadFidelityFailure({ diskCount, memoryCount })` runs on `open_document` and on the respawn load and refuses (no tool runs until `open_document` succeeds) whenever fewer top-level nodes loaded than the file held, measured from the bytes captured before the spawn (CTO ruling). It cannot see dropped nested nodes: a count is the only signal. The ruling's flip condition (a valid committed file that loads with fewer top-level nodes downgrades the refusal to a warning) is checked by the key-gated probe over `knowledge-base/product/design/**/*.pen`.

**REPL framing.** The prompt must be at the end of the buffer after a 50 ms quiet period; bytes after it mean desync (kill and restart from the saved file). The save confirmation is string equality after realpath of both sides. The memory probe uses a per-call random nonce and counts only a line that matches it exactly. Engine errors arrive on stderr and ANSI codes are present on piped output, so the adapter strips ANSI and drains stderr after each prompt.

## Consequences

- **Accepted residual:** `batch_design` forwards raw DSL, so host functions that take paths (`Export`, image-fill URLs) are reachable without `export_nodes` validation. The DSL runs in a sandboxed JavaScript runtime (described upstream as QuickJS; the probe pins behaviour, not the name) with no `process`, `require`, `fetch` or `XMLHttpRequest`: pinned by the probe on 0.3.13 (engine case 11: the `typeof` of each of those names and of timers, `console`, `Buffer` and `module`; the `this`, `Function`-constructor and `eval` escape routes; a dynamic `import("node:fs")` that never settles; and the exact host-function set), so a bump that exposes more fails a named pin. The key-gated probe measured on 0.3.13: `Export` writes to an absolute directory outside the document directory and replaces an existing file, and image fills with an absolute path, a `file://` url or a `../` url load the local file's pixels. The residual is accepted (CTO ruling, 2026-10-26) and pinned by the probe, so engine drift fails a named pin. Reasons: the adapter runs only on the registrant's own machine and the agent calling `batch_design` already has a shell as the same user; image urls are resolved inside the engine, so a shadowing prelude could cover only `Export`, and agent-authored script can reach other host functions, which makes a prelude a guarantee it cannot give. Flip condition: if the Pencil tools are ever exposed to an agent without a shell, or registered hosted, confine the child process with an OS sandbox rather than a prelude.
- **Threat model additions:** a project-scoped settings env block can redirect `$HOME` or `PENCIL_BINARY` for the registered server, and whether the harness forwards it to stdio servers is unverified, so it is assumed to (the credential travels with the child). Hence the trusted-prefix rule and the argv-only override above: an in-repo path cannot supply the engine binary. The adapter reads at most 64 MiB of a `.pen` for the fingerprint and the node count; a larger file is treated as unreadable (baseline `unknown`, saves refuse).
- **Residual, post-save gate:** the gate in `ux-design-lead.md` trusts the agent to report `REFUSED` (CTO ruling 5, 2026-10-26). `REFUSED` is agent-reported: a sidecar marker would be cleared by the `open_document` the agent must call to recover, and a read-back node count equals the file by construction after a re-open, so a skipped replay is undetectable from the file. The gate guards an honest agent against its own mistakes and is not a security boundary. Revisit only if a shipped wireframe is found missing edits after a refusal.
- **Residual, load fidelity:** the top-level count refusal cannot detect nested nodes the engine dropped on load (see Decision). Acceptance (ruling 6, live probe on 0.3.13, 2026-10-26): of the 106 committed `knowledge-base/product/design/**/*.pen` files, 105 load with exactly their on-disk top-level node count and none loads with fewer, so the refusal stands without the warn-and-allow downgrade. The one remaining file (`dashboard/dashboard-load-states.pen`) is rejected outright by the engine (its nodes use type `rect`, which is not a node type; the engine exits and the adapter reports `open failed:`, nothing runs, the file is untouched), pinned by the probe so a repaired or newly rejected file is named.
- **Window the stale guard cannot close:** a second writer between the fresh read and the engine's write, and whatever lands between the engine's write and the post-save read. There is no lock; one writer per file is a documented rule. A change during engine startup refuses the first save.
- **Not measured:** whether the engine's write is atomic, and how it handles a file written by a newer Desktop. The design depends on neither; a truncated file is caught by the existing unrecognizable-file refusal on the next save.
- **Lockfile wiring:** a fifth lockfile directory is registered with lockfile-sync (plus the lint and drain wiring; ADR-191 carries the addendum that this directory has no `.npmrc` floor by design).
- **Alternatives rejected:** renaming the tools to the native names (forces hook and prose churn for no capability); size+mtime as the fingerprint (misses same-size rewrites and a checkout that restores identical bytes); a `batch_get`/`snapshot_layout` shim (invents a node-dump format the engine does not offer); a PATH fallback or auto-uninstall of the deprecated package; renaming the Doppler secret (a production mutation with no benefit).
- **Open items outside this change:** `sharp` install failures on hosts with a global libvips (#8964) and the unbounded install in `copy_adapter.sh` (#9310) are unchanged.
