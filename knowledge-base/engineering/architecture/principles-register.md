# Architecture Principles Register

Queryable index of architectural principles. Each principle links to its canonical source — rationale and full context live there. This register enables structured references in ADRs and automated compliance checking during PR review.

> **Sibling registers:** [`domain-model.md`](./domain-model.md) (domain entities + business-rule invariants), [`nfr-register.md`](./nfr-register.md) (non-functional requirements). Use this register for *how we build*; use `domain-model.md` for *what the product's entities are and the rules that govern them* (e.g. `AP-015`'s workspace owner-canary principle maps to `domain-model.md` rules `BR-WS-3`/`BR-WS-4`).

| AP-016 | GHCR read:packages credential — the machine-account PAT is the INTERIM single-operator exception to `hr-github-app-auth-not-pat`. The ADR-088 App-installation-token minter is NOT the viable multi-tenant target: GitHub App installation tokens **cannot pull** private GHCR packages (they authenticate `docker login` but return `denied` on `docker pull`), so the minter is disabled (`GHCR_MINTER_DISABLED=true`) and the forward direction for the pull leg is the self-hosted **zot** registry (ADR-096/#6122), not App-token minting. The interim GHCR pull path MUST recover on a `docker pull` auth-denial, not only a login failure (#6400). **LAPSED 2026-07-30 (#7071): the interim PAT is REVOKED — `GET api.github.com/user` returns 401 and minting a pull token returns 403 `DENIED` — so there is no live GHCR pull credential and no `hr-github-app-auth-not-pat` exception in force. The recovery clause above is therefore inert: the path it recovers cannot authenticate at all. zot is the SOLE pull path, which is why the CI mirror is now release-blocking (ADR-096 amendment 2026-07-30). Restoring a GHCR pull leg is open debt, not a live capability — see that amendment's clauses (c), (d) and (g).** | ADR-096 (forward + 2026-07-30 amendment), ADR-088 (superseded minter), ADR-087 D1, ADR-082 | advisory | NFR-014 |

| AP-020 | Untrusted input at the agent boundary — the tool-call envelope a hook receives on stdin is MODEL-CONTROLLED. A component must not depend on an invariant of that input which it cannot itself verify: never shell-evaluate it, check a contracted field's TYPE rather than assuming it, and never treat normalization (coercion, scrubbing, case-folding) as a substitute for verification — a normalized value is a different value than the downstream matcher was written against. The register had no principle covering untrusted input; #7164 was an RCE plus an independent guard evasion that a type assumption made invisible for four months. | ADR-156 (response posture in ADR-157) **Scope + carve-out (ADR-175, #7393):** the principle as written scopes to the MODEL-CONTROLLED hook-stdin envelope. preflight Check 10 takes a different untrusted input — a PR-authored plan file — and shell-evaluates it by construction, so the spirit reaches it while the text does not. That violation is ACCEPTED, bounded by a bwrap filesystem sandbox, because the alternative (a static gate) is the documented #4148 failure where plans declare probes nobody runs. Recorded here rather than only in the ADR: an ADR-only note leaves this register silently contradicted, which is the thing the note claimed to prevent. | hook | NFR-024 |
| AP-021 | Diagnostic honesty in operator-facing messages — a CI-emitted message may only name a cause the job MEASURED. Messages branch on a computed verdict or explicitly declare themselves unmeasured; a verdict must never collapse "could not check" into "bad" (the DEAD/UNVERIFIABLE/UNMEASURED distinction calls for different, sometimes opposite, operator actions); where a cheap probe discriminates competing hypotheses the failing step runs it and reports the value rather than pointing at a dashboard. A cause measured ONCE is not a cause measured ALWAYS — #7242 was the third iteration on one code path, each prior one "fixed" by rewriting the sentence, because prose is not an enforcement mechanism. AP-001…AP-020 had no diagnostic-honesty principle. | ADR-166 | hook (CI-required suite: `scripts/lint-diagnosis-claims.sh` via `test-all.sh` -> the `test` context) | NFR-014, NFR-024 |
| AP-022 | Workflow steps clear inherited errexit before treating an exit code as data — GitHub invokes a `run:` block with no `shell:` key as `bash -e {0}`, so errexit is ALREADY ON and `set -uo pipefail` only ADDS flags. A step that captures an exit status (`rc=$?`, `rc=${PIPESTATUS[n]}`) must clear errexit explicitly (`set +e` … `set -e`) or protect the capture (`\|\| rc=$?`); `shell: bash` does NOT clear it. Otherwise the shell dies AT the command and the rc read, the `$GITHUB_OUTPUT` write and every `::error::` below are unreachable — silently. Six occurrences preceded this row, the sixth being the production-staleness alarm going dark on exactly the two verdicts it exists to raise (8/8 runs, zero output). Four learnings + six in-workflow comments + two hand sweeps had already been tried; prose is not an enforcement mechanism. | ADR-170 | hook (CI-required suite: `scripts/lint-workflow-errexit-capture.py` + its unit suite via `test-all.sh` -> the `test` context) | NFR-014, NFR-024 |

## Enforcement Tiers

| Tier | Description | Mechanism |
|------|-------------|-----------|
| hook | Mechanically enforced — violation is blocked | Pre-commit hooks, guardrails.sh |
| skill | Semantically checked — violation is flagged | Skill gates, agent review |
| advisory | Documentation only — relies on awareness | Manual review, AGENTS.md loaded every turn |

## Notes

- **AP-011 — ADR shape rubric.** AP-011's application to new ADRs follows the terse/rich shape rubric in [`plugins/soleur/skills/architecture/references/adr-template.md`](../../../plugins/soleur/skills/architecture/references/adr-template.md) under `## Choosing the shape`. Default is terse (3 sections); use rich (8 sections) when any rubric trigger applies.
- **Canonical-source rubric.** New AP rows pick `Canonical Source` by precedence: `AGENTS.md (Hard Rules)` for mechanical / always-loaded rules; `constitution.md (Architecture/…)` for foundational design tenets; `ADR-NNN` for architectural decisions with a documented migration path. AP-013 → ADR-027 is the first instance of the third tier — extend rather than collapse the precedent when future ADR-sourced APs land.
