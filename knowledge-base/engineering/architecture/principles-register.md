# Architecture Principles Register

Queryable index of architectural principles. Each principle links to its canonical source — rationale and full context live there. This register enables structured references in ADRs and automated compliance checking during PR review.

> **Sibling registers:** [`domain-model.md`](./domain-model.md) (domain entities + business-rule invariants), [`nfr-register.md`](./nfr-register.md) (non-functional requirements). Use this register for *how we build*; use `domain-model.md` for *what the product's entities are and the rules that govern them* (e.g. `AP-015`'s workspace owner-canary principle maps to `domain-model.md` rules `BR-WS-3`/`BR-WS-4`).

| AP-022 | Workflow steps clear inherited errexit before treating an exit code as data — GitHub invokes a `run:` block with no `shell:` key as `bash -e {0}`, so errexit is ALREADY ON and `set -uo pipefail` only ADDS flags. A step that captures an exit status (`rc=$?`, `rc=${PIPESTATUS[n]}`) must clear errexit explicitly (`set +e` … `set -e`) or protect the capture (`\|\| rc=$?`); `shell: bash` does NOT clear it. | AP-023 | An anti-vacuity floor reports directly, and its case counter moves at the call site — a floor that reports by calling the suite's own `fail`/`bad` increments the counter the exit status reads, so neutering that helper silences the assertion rows AND the floor meant to notice the silence; the suite prints a total and exits 0. | AP-024 | A verification surface does not actuate — a component whose job is to decide whether something worked may sense, poll, adjudicate and PUBLISH A VERDICT, but must not itself perform the write it is judging. ## Notes

- **AP-011 — ADR shape rubric.** AP-011's application to new ADRs follows the terse/rich shape rubric in [`plugins/soleur/skills/architecture/references/adr-template.md`](../../../plugins/soleur/skills/architecture/references/adr-template.md) under `## Choosing the shape`. Default is terse (3 sections); use rich (8 sections) when any rubric trigger applies.
- **Canonical-source rubric.** New AP rows pick `Canonical Source` by precedence: `AGENTS.md (Hard Rules)` for mechanical / always-loaded rules; `constitution.md (Architecture/…)` for foundational design tenets; `ADR-NNN` for architectural decisions with a documented migration path. AP-013 → ADR-027 is the first instance of the third tier — extend rather than collapse the precedent when future ADR-sourced APs land.
- **AP-019 — the "self-reverting" justification is VOID until the apex-topology precondition is live (2026-08-20, #7640).** AP-019 sanctions the `cron-gh-pages-cert-reissue` DNS toggle as a NARROW AP-001 exception on five stated grounds, one of them that the mutation is *"self-reverting to the Terraform-declared steady state"*. **That ground becomes provably false the moment the #7640 apex cutover lands**, and a justification that has stopped being true is not a carve-out — it is the unexplained bypass AP-019 exists to prevent, so it is recorded as void here rather than left to be re-derived. Read from the source: `listToggleRecords()` queries exactly `[apex, "A"]` and `[www, "CNAME"]`; post-cutover the apex is a `CNAME`, so the `A` query returns nothing, the apex is untouched, and **`www` alone is flipped to `proxied = false`** — dropping HSTS, Rule 10's HTTPS upgrade, WAF and bot management on a host `domains.md` mandates be proxied. It then cannot revert: `restoreStateInner` opens with `if (records.length < EXPECTED_TOGGLE_RECORDS)` where `EXPECTED_TOGGLE_RECORDS = 5`, the post-cutover read returns fewer, and it throws *"refusing to restore a subset"*; `retries: 1` exhausts, `onFailure` calls the same restore and throws again, and it pages `proxy_restore_failed`. The routine's own fail-loud safety guarantee is what makes the de-proxying **one-way**. Probe-only mode does not save it — `resolveProbeOnly` defaults to `true`, but `setRecordsProxied(deps, records, false)` runs unconditionally and only the cname toggle is skipped. **Scope of the void:** only the self-reverting ground, which is the load-bearing one; transient / single-attempt / human-gated / lock-guarded are unaffected, and the row above stands as written for the pre-cutover `A`-record topology in which it was measured. **Lifting condition:** the #7640 PR1 disarmament — an apex-topology precondition in `checkReissuePreconditions` that returns a non-benign terminal outcome unless the live apex record type is `A`, plus removal of the `0 3 * * *` trigger on `cron-gh-pages-cert-state` (its manual-trigger arm retained). Once that is live the routine can only execute against the topology the self-reverting claim was measured against, so the ground holds again for every topology in which the routine can run at all. **Until then, treat AP-019 as suspended, not as authority:** do not fire the routine against a non-`A` apex, and do not cite the self-reverting clause as precedent for a new off-Terraform mutation. Sources: [ADR-194](./decisions/ADR-194-migrate-marketing-docs-site-off-github-pages-to-cloudflare-pages.md) `## Addendum — 2026-08-20 (#7640)` §2; `knowledge-base/project/plans/archive/20260903-221104-2026-08-20-chore-migrate-docs-site-to-cloudflare-pages-plan.md` `## Design Decision D2`; ADR-125 (AP-019's canonical source) is **not** amended — it correctly describes a routine that will refuse to run.
