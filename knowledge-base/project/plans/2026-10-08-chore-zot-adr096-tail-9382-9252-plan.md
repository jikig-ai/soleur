### Phase 1 — Item 4: split Class A into declared-pending and drift (the only code)

Files to Edit:
- `apps/web-platform/scripts/sentry-monitors-audit.sh`
- `apps/web-platform/scripts/sentry-monitors-audit.test.sh`
- `knowledge-base/engineering/architecture/decisions/ADR-031-sentry-as-iac.md`

No file to create. No workflow touched (the PR therefore keeps the agent admin-merge path, though merge authority itself stays with the operator). `sentry-audit-gate.yml` is path-triggered by the script, so CI runs the gate.

Design (write the test rows first, see Guard Contract):
1. In the existing `tf_dir` coherence block (the `if [[ -z "${SENTRY_FIXTURE_MONITORS:-}" || -n "${SENTRY_TF_DIR:-}" ]]` block that already computes `declared_slugs`, `apps/web-platform/scripts/sentry-monitors-audit.sh:1258`), add one awk pass over `"$tf_dir"/*.tf` that emits the monitor **slugs** of every key of `cron_monitor_alert_unrouted`: collect map keys inside `cron_monitor_alert_unrouted = {` … `}` (a key is `^\s*[a-z0-9_]+\s*=\s*"`, so `#` comment lines never match), and resolve each key to the `name = "…"` of the `sentry_cron_monitor` block with the same Terraform label (same anchor construct as the `declared_slugs` awk, `:1272`). A key with no matching resource resolves to nothing.
2. Partition `class_a_unrouted_labels` into pending (label ∈ that slug set) and drift (everything else, including the `<unresolved detector id=…>` and `<non-slug detector id=…>` placeholders, which are never slugs). Set `class_a_count` to the drift count, so `total_orphans`, the "No orphans detected" verdict, the report counter and the `::warning::` all keep reading one number whose healthy state stays 0. Declared-pending goes in a new `class_a_pending_labels` array.
3. Report: keep `**N** of **M** cron detectors` but say "undeclared" (N = drift only), and when pending is non-empty add one line plus a bullet per slug: `**K** more declared pending in cron_monitor_alert_unrouted (two-PR rule; not drift, not warned)`. Pending stays in the Article 30 artifact.
4. A run with no coherent tf half (fixture run without `SENTRY_TF_DIR`) skips the partition: every unrouted detector stays drift, so every existing T19-series fixture keeps its meaning.
5. Bash trap: the partition loop iterates `class_a_unrouted_labels`, which is empty when `detectors_evaluated == 0` or nothing is unrouted. Guard the loop with `(( ${#class_a_unrouted_labels[@]} > 0 ))` (the existing consumers are already guarded by `class_a_count > 0`); an unguarded `"${arr[@]}"` on an empty array aborts under `set -u` on bash < 4.4.
6. ADR-031: amend the "Supersedes the Class A invariant" bullet: the healthy state is `class_a_count == 0` over *undeclared* unrouted detectors; declared-pending detectors are listed in the report and do not warn; a stale map entry (no live detector) is inert. Add the rejected alternative "warn for declared-pending too" with the reason (permanent noise on a pending route that is on purpose, which teaches the operator to ignore the one line that also carries real drift).

**Size measurement (the "inline-sized" criterion).** The criterion is the issue-filing hook's boundary: at most 100 changed lines and at most 4 files is fixed inline. A prototype of the script change was built in the scratchpad against a copy of `sentry-monitors-audit.sh` (not committed): `diff -u orig new | grep -c '^[+-][^+-]'` = **23** non-blank changed lines (27 with blank lines), plus about 4 lines of report wording. Decision: do it inline, under a hard stop rule, because the file count is well inside the cap and the line estimate straddles it.

## Guard Contract

### Guard 1 — Class A declared-pending vs drift partition

**Property.** A cron detector with an empty `workflowIds` is excluded from the routing `::warning::` if and only if its monitor is a key of `local.cron_monitor_alert_unrouted` in the same Terraform root the audit reads; every other unrouted detector still warns.

**Assembly.** One chokepoint: the partition of `class_a_unrouted_labels` in `sentry-monitors-audit.sh`, whose outputs feed every consumer (`class_a_count`, `total_orphans`, the "No orphans detected" verdict, the report counter, the warning part). Inputs it quantifies over: (a) unrouted detectors resolved by the structured binding `dataSources[].queryObj.slug`, (b) those resolved by the `.name` fallback, (c) the placeholders `<unresolved detector id=N>` and `<non-slug detector id=N>`; (d) the declared set, drawn from two files (`cron-monitor-alerts.tf` map keys, `cron-monitors.tf` label-to-name). The partition runs only when the tf half is coherent (`SENTRY_TF_DIR` set, or production where no fixture is injected). A second reader of the map exists elsewhere: Guard 1 in `sentry-cron-monitor-routing-parity.test.ts` (declared monitors are routed XOR unrouted, with a reason); this guard does not replace or relax it.

**Mutation matrix:**

| # | Mutation | Expected |
|---|---|---|
| 1 | Remove the pending slug's key from the fixture map (declared becomes undeclared) | RED: the warning names it again |
| 2 | Dispatch: make the awk emit an empty set (rename the map in the fixture to `cron_monitor_alert_unrouted_x`) while a detector is unrouted | RED for "suppressed": the unrouted detector must still warn (fail toward noise, never silence); and a fixture asserting the pending report line reads `0 pending` must fail if the set is empty while a key exists |
| 3 | Add a second unrouted detector `m2` NOT in the map after a compliant first (`m1` in the map) | RED unless `m2` warns and `m1` does not (a check that stops at the first match fails here) |
| 4 | Comment out the map line (`# m1 = "reason (#1)"`) | RED unless `m1` warns |
| 5 | Map key whose resource label does not exist in `cron-monitors.tf` (typo), with an unrouted detector of the similar name | RED unless the detector warns |
| 6 | An unrouted detector with no resolvable binding while the map is non-empty | RED unless the placeholder warns (placeholders are never slugs) |
| 7 | Run with `SENTRY_FIXTURE_MONITORS` set and `SENTRY_TF_DIR` unset | RED unless every unrouted detector warns (existing T19 stays unchanged) |

Harness rows: (H1) a SUITE edit that must drive it RED: stub the partition out (`pending_slugs=""`) and the new "pending not warned" test must fail while the existing T19 tests stay green, proving the new test observes the new code and not the old path. (H2) a must-PASS input that is not the canonical: a map written with tab indentation, extra spaces around `=`, and a trailing `#` comment on the key line, with the same expected result as the canonical fixture. A 0-checked dispatch row: the new assertions must also assert the report's pending line is present (a fixture where the partition never ran reports no pending line and fails).

**Anchor.** The value compared is the declared map in the repo, so one PR can add a monitor to the map to silence its warning. What outside the commit must also move: the map's `"<reason> (#N)"` value is gated by Guard 1 in `sentry-cron-monitor-routing-parity.test.ts` and reviewed in the PR diff; and the audit report still lists the pending slug on every run (property 3), so the silencing is visible in the Article 30 artifact and cannot be silent. This guard proves consistency with the declared record, not integrity of the record; that limit is stated in the ADR amendment.
