## Overview

## Observability

This is CI tooling; the surface is the job's check-run, its marker line and annotation, and the jobs API. (Plan Phase 2.9's code-path list does not name root `scripts/`, but a `.github/workflows` edit and a new job are an infrastructure surface, so the schema is declared.)

```yaml
liveness_signal:
  what: the SOLEUR_PR_AFFECTED_RATCHET marker line in the job log (exit, reason, live, baseline), the ::error annotation, the job's conclusion in actions/runs/<id>/jobs once the canary settles how a failing continue-on-error job reports, and its wall time (completed_at minus started_at)
  cadence: every pull_request and merge_group run of ci.yml (not push); the observation window of PR3b needs at least 3 pull_request and 3 merge_group runs
  alert_target: the red job on the PR check list (advisory in PR3a); the required context turns red on the PR or the queue entry after PR3b
  configured_in: .github/workflows/ci.yml (job affected-index-ratchet) and scripts/ci-pr-affected-replay.py (ratchet)
error_reporting:
  destination: exit 1 (drift or a structural verdict) or 2 (infrastructure) with one ::error title=affected-index-ratchet::exit=<1|2> annotation emitted by the workflow step and the marker line with a fixed reason token; the failure text names suite, path and file:line
  fail_loud: every infrastructure error (selector failure, short output, fallback, unresolvable base, unreadable baseline, unexpected exception) exits 2 with a fixed reason token; none is swallowed into a green; a non-success run with no annotation counts as exit 2
failure_modes:
  - mode: a suite names an undeclared tracked path
    detection: ratchet exit 1 naming suite, path and referencing line
    alert_route: red advisory job now, required context red after PR3b
  - mode: the selector fails, prints no rows or a fallback (vacuous audit)
    detection: ratchet exit 2 from the floors, with the marker reason token
    alert_route: the same job, annotation exit=2
  - mode: the job hangs or runs long
    detection: PR_AFFECTED_REPLAY_SELECT_TIMEOUT (200 s) then the 5 minute job timeout; p95 wall time over 210 s fails the PR3b entry criterion
    alert_route: jobs API conclusion timed_out or cancelled, counted separately and never green
  - mode: the advisory job reddens the CI run and skips a deploy
    detection: the biconditional wiring row (continue-on-error if and only if the name is not in required-checks.txt) and the exact positive if: row; workflow-run-deploy-invariants.test.sh
    alert_route: the replay suite (test-scripts leg) turns the required test context red on the PR that removes it early
logs:
  where: GitHub Actions job logs for affected-index-ratchet and for the test-scripts leg that runs the replay suite
  retention: GitHub Actions default log retention (90 days)
discoverability_test:
  command: bash -c "python3 scripts/ci-pr-affected-replay.py ratchet --list <(printf 'AFFECTED_SELECTED\tx\t1\talways_on\t\nAFFECTED_SUMMARY selected=1 of=1 always_on=1 edge=0 fallback=none\n') --baseline scripts/ci-pr-affected-audit.baseline.tsv"
  expected_output: SOLEUR_PR_AFFECTED_RATCHET
```

## Test Scenarios

1. Live tree (a one-time acceptance reading, never a suite row: the audit alone takes about 12 minutes under load and races with sibling merges): `python3 scripts/ci-pr-affected-replay.py ratchet` on the rebased tree exits 0 with `live == baseline == gap_refs`; the suite rows cover the same property on a scratch `git init` repo (`GIT_CEILING_DIRECTORIES` set): adding a line that names an undeclared tracked path to a registered suite exits 1 and names suite, path and line.
2. New-suite attack: a PR adds a suite with three undeclared reads and three baseline rows for it; the ratchet exits 1 (growth rule), not 0.
3. Swap attack: one baseline pair of a suite replaced by a different pair of the same suite; exits 1 (pair-set growth).
4. Stale baseline: remove the last mention from a suite; the line is stale; exit 1 and the text prints the exact line to delete.
5. Cause discrimination: a PR adds a file X that an existing suite already names: exit 1 and the golden text "your change added file X that suite S names"; a PR edits suite S: "you edited suite S"; neither (main moved, or an edge or accept row was removed): the third golden text. Precedence is added-file, then edited-suite, then neither.
6. Infrastructure: the selector exits non-zero or hangs past `PR_AFFECTED_REPLAY_SELECT_TIMEOUT`, prints no rows, prints `fallback=runner-changed` or `index-missing`, prints a hazard or unknown `AFFECTED_*` record, a second summary, or a row count that disagrees with `of=`: exit 2 with its own `floor-*`/`selector-*` reason, never 0 or 1, even when an offending pair is also present.
7. Runner-state input: a canned selection carrying `AFFECTED_RUNNER_IN_SCOPE reason=registration-only` exits 2 (the real selector cannot produce it under `--paths=README.md`; the classifier itself is pinned by `scripts/test-all-affected.test.sh` re1-re4).
8. Dark state: the marker line and annotation are readable from the job; the name is absent from `scripts/required-checks.txt`; a forced red on a throwaway canary branch (Phase 3 step 6) settles what the jobs API reports for a failing job-level `continue-on-error` job and whether the `CI` run stays green.
9. Cost: the job's cold wall time on the first real run is at most 270 s (the 210 s p95 is the PR3b entry criterion); over 270 s on the first run stops the PR.
10. Baseline states: base absent/HEAD present passes when live equals the baseline (adoption); base present/HEAD absent passes only with an empty live set; absent at both is strict zero; present at both is equality plus the growth rule. After PR5 the baseline is gone, `audit` prints `gap_suites=0 unaudited=0 stale=0`, a single planted gap exits 1 and a reintroduced non-empty baseline file with an empty live set exits 1 as stale lines.

## Risks and Sharp Edges

- **`continue-on-error` is no longer deploy protection by itself.** `web-platform-release.yml` acts on a `push` run and refuses a non-success `CI` conclusion; the job never runs on push (CTO row 14), so a red ratchet cannot reach the deploy gate today. The line keeps the pull_request and merge_group run conclusions green while the context is not required (`plugins/soleur/scripts/ci-head-verdict.sh` maps a completed `failure` run to `full-decided`, so it is not misread there either); adding `push` to the `if:` later re-activates the deploy coupling. The biconditional wiring row (continue-on-error iff the name is absent from `scripts/required-checks.txt`) is the guard; PR3b must remove the line in the same commit as the required-checks edit. How the jobs API reports a failing job-level `continue-on-error` job is unsettled in-repo (comments disagree); the canary settles it before the PR3b window relies on `.conclusion`.
- **Baseline race and advisory-phase decay.** The baseline is regenerated on the rebased tree immediately before merge; any main commit that touches a suite or adds a tracked name between that and the queue run changes the live set and fails equality (CTO row 8a). A new pair on main is repairable only by declaring the edge or an accept row (`--print-baseline` is prune-only); a stale line is deleted. While the job is advisory nothing forces a repair, which is why the ADR amendment carries a 30-day review trigger. Gap pairs also move when sibling PRs #7390, #10744 and the `scripts/test-all.sh` PRs merge.
- **Until PR4, a PR that adds a new path mention to a suite fails the ratchet** (advisory in PR3a, required after PR3b) and must declare an edge in `scripts/lib/test-affected-paths.sh`, which runs the full battery once. The runbook states it; the failure text says so.
- **Cost on every PR and queue run** (about 3 to 4 billed minutes, docs-only PRs included). No path filter is safe because the read set is unknown. The 210 s p95 / 270 s maximum / 5 minute timeout ceiling is a PR3b entry criterion; the first run is measured before the PR is ready.
- **Local gate degradation.** Editing `ci.yml`, the replay script's suite or the pin suites can degrade the local `test-all.sh --affected` gate to the full battery or to `rc=6 AFFECTED_GATE_BUDGET_DEFERRED` when queued behind other worktrees; run suites detached, check `list_runs test-all.sh` and `kill_mine test-all.sh`, and treat CI as the authority.
- **The replay suite grows.** It takes about 4.5 minutes today; the new rows and mutants add to it. If the shard-totality census requires a leg change, use `scripts/regenerate-shard-manifest.py`, never a hand edit. Splitting the ratchet rows into their own suite file waits for PR4 (index files open up).
- **Untracked files read green.** `git add` the baseline before any whole-repo gate (`lint-orphan-test-suites.sh`, the totality census), and re-run after tracking.
- **Renames and moves.** A rename or move of a tracked file that a baselined suite names reads as a new pair (growth, exit 1) with no remedy except declaring an edge (44 edges for `scripts/lib/scratch-root.sh`); rename-carry is deferred to a PR3b entry condition (row 25) and the runbook calls such a rename a drain-class PR meanwhile. The baseline also absorbs the pairs this PR's own new test text creates; PR4 drains them.
- **The audit numbers drift.** Every figure in this plan was measured on `4da1673510` (`gap_refs=1884`, `refs=3407`, `files_read=958`); the brief's earlier figures were on `4cd25c706b` (refs 3,404). Quote the live line from the PR's own tree and never mix the pinned and final-tree numbers.

- **Hyphenated module name.** Python probes load `scripts/ci-pr-affected-replay.py` and `plugins/soleur/scripts/lint-ratchet.py` with `importlib.util.spec_from_file_location`; a plain `import` cannot reach either.
