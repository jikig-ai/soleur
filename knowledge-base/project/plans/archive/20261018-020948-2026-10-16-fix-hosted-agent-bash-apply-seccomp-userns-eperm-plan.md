# P1: hosted agent Bash is down - sandbox fails with apply-seccomp unshare(CLONE_NEWUSER) EPERM, no alert fired

## Overview

Every hosted Concierge Bash call fails at sandbox start with
`apply-seccomp: unshare(CLONE_NEWUSER): Operation not permitted`, production `/health` stays `ok`, and
nothing alerted. The RCA below was self-pulled from the observability layer (Better Stack, Sentry,
`/hooks/deploy-status`) and reproduced locally; no SSH was used and no operator data fetch is needed.

**Root cause (reproduced, not inferred).** Two controls we ship are mutually exclusive:

1. The bwrap PATH shim (`apps/web-platform/infra/bwrap-shim/bwrap`, introduced by #9595, first tag
   `web-v0.324.3`, 2026-10-06) injects, on every inner SDK sandbox spawn, the nested-userns filter
   generated by `apps/web-platform/scripts/gen-bwrap-userns-seccomp.mjs`: `clone`/`unshare` carrying
   `CLONE_NEWUSER` return `EPERM`, `clone3` returns `ENOSYS`.
2. The Agent SDK (`@anthropic-ai/claude-agent-sdk` 0.3.284, embedded `claude` binary) wraps every
   sandboxed Bash command as `ARGV0=apply-seccomp /proc/self/fd/<N> <shell> -c <cmd>` (the
   `seccomp(unix-block)` arm). That embedded helper's first syscall, when it holds no capability, is
   `unshare(CLONE_NEWUSER)`. The inner sandbox runs `--cap-drop ALL`, so the helper always takes that
   branch, and our own filter kills it.

Local reproduction with the committed artifact:
`bwrap --unshare-user --unshare-pid --ro-bind / / --dev /dev --tmpfs /proc --add-seccomp-fd 9 -- env ARGV0=apply-seccomp <claude-agent-sdk-linux-x64/claude> /usr/bin/true 9<apps/web-platform/infra/bwrap-userns-clone3-deny.bpf`
prints exactly the production line (rc=1).

**Why nothing alerted** (four independent gaps, all closed by this plan):

- The faithful canary replays only the captured bwrap SETUP argv ending in `-- true`
  (`parseShimSetupArgv` in `apps/web-platform/scripts/sandbox-canary.mjs` documents the command tail as
  "model-chosen ... we never store or replay"), so the `apply-seccomp` wrapper is never run. Its
  `nested_userns_deny` hardening probe even REQUIRES the denial that breaks the helper. Result:
  `sandbox_canary.consecutive_pass=108` (green since 2026-10-11 18:44 UTC) over a hard-down Bash.
- The in-app tool_result mirror (`classifyBashSandboxFailure`, `server/sandbox-startup-classifier.ts`)
  requires the token `bwrap|bubblewrap` AND `Operation not permitted` on one line. The helper's line has no
  `bwrap`, so it returns `null` and Sentry saw nothing (Sentry search for `feature:agent-sandbox` over 14 days
  shows only canary events).
- Even a matching `op=bash-tool-result` event pages nobody: the Sentry rule is deferred in #10052 (blocked on
  #7985, the legacy-trigger rules are `ignore_changes = all`).
- No alert reads `SANDBOX_CANARY_FAIL` rows or the `op=sandbox-canary*` Sentry events at all; the standing
  report-only outer-wrap canary has been red for a week (Sentry issue 152662657, 153 events,
  `wrong_elevation_userns`) and paged nobody.

The earlier #8752 plan recorded the helper as "inert today (our config sets no `allowUnixSockets`)" and
recorded a CONSTRAINT to make a deliberate decision before enabling it; the #10032 measurements logged
"if prod's real command DOES wrap apply-seccomp, its NEWUSER dies under our bpf" as a non-gating open risk
and no follow-up issue was filed. The wrapper IS emitted by default (`allowAllUnixSockets` unset), so the
premise was false from the day the shim shipped.

## Problem Statement / Motivation

Hosted agents cannot run a shell command; every web-egress use (including the egress-audit canary #9545) is
blocked behind it (after this fix, entitled web-egress sessions stay blocked until #10457 lands), the incident went undetected for ten days, and the only detector was a user. The same class
(report-only canary red, mirror silent, alert deferred) already produced the #9860 and #5873 incidents.

## Proposed Solution

Decision record: `knowledge-base/project/specs/feat-one-shot-10445-sandbox-seccomp-eperm/decision-challenges.md`.
Plan-review (2026-10-16, five-seat panel) reshaped the original draft: the fixture-v2 "wrapper replay" was
vacuous once the fix removes the wrapper, so Phase 2 became an end-to-end SDK Bash smoke; the socket gate became
a runtime two-session test after the architecture seat found a cross-session bridge-socket path.

**Stage A (restores service; ships first, Phases 0, 1, 3, 4):**

1. **Fix (CTO R1 = option c, conditional).** Set `network.allowAllUnixSockets: true` in `buildAgentSandboxConfig`.
   The SDK maps it from `sandbox.network.allowAllUnixSockets` (verified in the vendored binary:
   `allowAllUnixSockets: e.sandbox?.network?.allowAllUnixSockets`) and the vendored builder then skips the helper
   ("Skipping seccomp filter - allowAllUnixSockets is enabled"). The nested-userns / clone3 filter is untouched.
   Conditional on the runtime two-session socket test (Phase 1 G2); if it fails the binding fallback is option (b).
2. **Detect at runtime (R2 i).** Widen `classifyBashSandboxFailure` to the helper's own line shape and page through a
   Better Stack logtail alert at one event, filtered on the new `sandboxErrorCode` so a tenant-printed `bwrap`
   line cannot reach it.
3. **Record (R3).** PIR (redaction-gated), ADR-079 and ADR-075 addenda, runbook updates.

**Stage B (detection depth; separable, time-boxed, Phase 2):**

4. **Detect at deploy time (R2 ii).** An end-to-end SDK Bash smoke inside the canary container: the real SDK
   `query()` with `buildAgentSandboxConfig` against a local stub of the Messages API that returns one canned Bash
   `tool_use`, executing a no-op command through the REAL command-side wrapper path and the shim. Non-blocking
   first (`wg-dark-launch-deploy-gates`), reported as `sdk_bash_smoke` in deploy-status, promoted to
   rollback-gating after observed-green real deploys. This replaces the fixture-v2 wrapper replay: a replay of a
   captured tail executes zero wrappers once the fix lands, so its green proves nothing.
5. **Page when the faithful canary goes red.** A second logtail alert on `SANDBOX_CANARY_FAIL` rows for
   `(op=sandbox-canary;` (positive match; sunset when the smoke is promoted into the `DEPLOY_ROLLBACK` lane that
   `bwrap_probe_rollback` already pages on).

Time-box: if the stub-model smoke is not working within half a working day, file the tracking issue, ship Stage A
alone, and keep the docker-suite wrapper arm (Phase 1) as the pre-merge regression guard.

## Technical Considerations

### Attack Surface Enumeration (the fix relaxes AF_UNIX blocking inside the inner sandbox)

What AF_UNIX blocking stopped, and what bounds each path after this change:

| Path an inner-sandbox process could use | Bound after the fix | Verdict |
|---|---|---|
| Pathname unix sockets visible through `--ro-bind / /` (`connect()` works through a read-only bind) | enumerated at runtime in the docker suite with an allowlist (Phase 1 G2); no `docker.sock`, no host runtime socket | gate before merge |
| Egress bridge sockets of a SIBLING session (socat `UNIX-LISTEN` at `os.tmpdir()/claude-http-<random>.sock` and `claude-socks-<random>.sock`; all sessions share one uid and one container) | each session's SRT proxy requires its own `proxyAuthToken`, carried only in that session's env (`HTTP_PROXY=http://<workspaceId>:<token>@127.0.0.1:<port>`); `/proc` is masked and owner credential env is denied inside the sandbox. UNVERIFIED: socket visibility from another tenant, and that the proxy answers tokenless/wrong-token requests with 407 | runtime two-session test (G2); fail => option (b) |
| Abstract-namespace sockets | scoped to the sandbox netns by `--unshare-net` (in the fixture argv). Distinct from the outer-wrap residual in `agent-outer-wrap.ts`, which covers the outer layer only | safe |
| SCM_RIGHTS fd passing from an inherited fd | the shim's fd sweep closes every unreferenced fd; the canary `fd_census` probe asserts it | safe, existing control |
| Nested userns / clone3 (the property the filter exists for) | filter unchanged; the canary `nested_userns_deny` probe keeps asserting it | P2 held |

### Risks

- **Vendor knob silently ignored or settings-gated.** `network.allowAllUnixSockets` sits in a privileged-key array
  in the binary next to `enableWeakerNestedSandbox` (which already works through our options). G1 runs first and
  proves the OUTCOME with a control arm: `true` yields a command without `apply-seccomp` and a real Bash success
  through the shim; `false` yields the wrapper and the EPERM.
- **Cross-session bridge sockets** (architecture P0): see the table; the binding fallback on a failed G2 is
  option (b) in this PR (a single `socket(AF_UNIX)` deny in the one bwrap filter, never `socketpair`, which
  libuv child_process needs; the bridge socat already runs before the command's filter applies). A per-session
  private TMPDIR is defense in depth only. Interim if Bash must be restored before (b) is ready: do not ship (c)
  to all tenants; restore it behind the existing flag for an allowlist of internal workspaces and track the
  cross-tenant residual with a deadline. Contingent, not planned work.
- **Free-text classifier forgery.** Bash tool_result text is tenant-controlled. The new arm is anchored to the line
  start (`apply-seccomp:` after trim), per-user debounced, and the alert filters on the NEW `sandboxErrorCode`,
  not on the whole `op`. A tenant can still print the exact line and send one email; accepted at this scale and
  named in the runbook entry, because the deploy-time smoke is the authoritative signal.
- **Dark-launch sequencing.** The smoke cannot gate its own introducing deploy (`wg-dark-launch-deploy-gates`);
  promotion evidence is meaningful because the smoke executes a real Bash command through the real wrapper path.
- **Schema/order independence.** `ci-deploy.sh` (deploy_pipeline_fix) and the image ship separately: an old
  `ci-deploy.sh` meeting the new `sdk_bash_smoke` verdict, or a new `ci-deploy.sh` with an old image, must both
  degrade to "field absent" without failing the deploy; both orders get a test.
- **Both alerts apply concurrently with the release deploy** (`apply-web-platform-infra.yml` on `infra/*.tf`
  merge). The post-merge readback gates "resolved".
- **Census source.** The classifier never matched the line, so no Sentry/Better Stack row exists for it and the hot
  window is about 40 minutes. Phase 0 identifies where Bash tool_result text persists (if anywhere) before any
  census is promised; otherwise the PIR states plainly that the affected-user count is unmeasurable and uses a
  session-count proxy since 2026-10-06.

## Guard Contract

### Guard 1 - End-to-end SDK Bash smoke (deploy-time, Stage B)

**Property.** A production build in which a real SDK-issued Bash command cannot execute through the real
command-side wrapper path under the shim's seccomp filter is reported `sandbox_broken` / `sdk_bash_smoke_failed`
on the deploy that carries it.

**Assembly.** One chokepoint: `sdk-bash-smoke.mjs` drives the real SDK `query()` with `buildAgentSandboxConfig`
and the PATH-resolved shim -> exit classification -> `ci-deploy.sh` verdict map -> deploy-status `sdk_bash_smoke`
-> journald `SANDBOX_CANARY_FAIL` -> Better Stack alert. Sibling spawn paths that do NOT flow through it, stated
explicitly: the outer-wrap path (`agent-outer-wrap.ts`, separate canary, report-only, tracked), the C4 render argv
(bypasses the shim by design, absolute `/usr/bin/bwrap`), and the legacy `bwrap -- true` probe. The smoke uses
no captured fixture, so there is no stored value to weaken; the pre-merge anchor for the same property is the
docker-suite wrapper arm and the pinned-binary extractor.

**Mutation matrix:**

| # | Mutation | Expected |
|---|---|---|
| 1 | Set `allowAllUnixSockets: false` in the config the smoke imports (the wrapper reappears) | RED, `sdk_bash_smoke_failed` with the helper EPERM line |
| 2 | Make the stub model return no `tool_use` (the guard's own dispatch: zero commands executed) | RED (`smoke_infra_error` is not a pass; a run that executed zero Bash calls never reports `pass`) |
| 3 | Stub returns two `tool_use` blocks, first benign, second a command that fails under the filter | RED (every member is asserted, not the first) |
| 4 | PATH without the shim (filter absent) | the smoke passes but the canary `nested_userns_deny` fails, so the pair is RED together |

Harness rows: (H1) replace the real `bwrap` with an always-exit-0 stub: the suite must report
`smoke_infra_error`/fail, never pass; (H2) must-PASS non-canonical inputs: a different benign command and a
different stub reply shape both PASS.

### Guard 2 - Bash tool_result classifier (runtime)

**Property.** A Bash tool_result line of the helper shape `apply-seccomp: <step>: Operation not permitted` (and
every existing bwrap denial) produces a mirrored event; an agent's own `unshare -U` output does not.

**Assembly.** `classifyBashSandboxFailure` in `server/sandbox-startup-classifier.ts` is the only decoder; its
single caller is `mirrorBashSandboxFailure` in `server/cc-dispatcher.ts` `onToolResult`. The legacy agent-runner
loop has no tool_result observer (recorded scope limit, unchanged).

**Mutation matrix:**

| # | Mutation | Expected |
|---|---|---|
| 1 | Remove the `apply-seccomp:` arm | RED (fixture string taken from the real binary and the issue line) |
| 2 | Call the classifier with empty output / only benign lines (dispatch vacuity) | RED if it ever returns non-null; a positive-control line in the same case must be non-null |
| 3 | Benign first line, helper line second, third line a bare `unshare: ... Operation not permitted` | classifies line 2 only (a stop-at-first-line scan is the defect) |
| 4 | Widen the arm to a bare `unshare`/`seccomp` token | RED (negative fixture: an agent's own `unshare -U` output) |

### Guard 3 - Better Stack alerts (drift)

**Property.** Each alert's SQL matches exactly the rows it names, a sampled production-shaped row passes the
predicate, and its `-target=` lines are present in the apply workflow.

**Assembly.** `betterstack-logs-alerts.tf` (two exploration+alert pairs) -> `apply-web-platform-infra.yml`
`-target=` list -> `sandbox-alerts.test.sh`.

**Mutation matrix:**

| # | Mutation | Expected |
|---|---|---|
| 1 | Change the needle (`SANDBOX_CANARY_FAIL: verdict=sandbox_broken` -> `...X`) | RED |
| 2 | Drop one `-target=` line from the workflow | RED |
| 3 | Loosen `(op=sandbox-canary;` to a prefix match so the standing outer-wrap row matches | RED (it would page every deploy) |
| 4 | Add a third alert resource without its `-target=` pair | RED (census over the file, not the plan's names) |

### Guard 4 - Runtime socket exposure (G2, pre-merge)

**Property.** From a second tenant's inner sandbox, no sibling session's egress identity and no host runtime
socket is reachable without that session's token.

**Assembly.** The docker-suite two-session test; the allowlisted pathname-socket census.

**Mutation matrix:**

| # | Mutation | Expected |
|---|---|---|
| 1 | Proxy accepts tokenless requests (stub the check off) | RED |
| 2 | Add `docker.sock` to the visible mounts of the run tuple | RED (census allowlist) |
| 3 | A second sibling socket added after a compliant first | RED (census iterates every member) |
