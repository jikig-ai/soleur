## Overview

The always-loaded rule corpus (`AGENTS.rules.md`) has a documented shrink ladder for when `B_ALWAYS` approaches the 46000-byte critical cap. One rung of that ladder — "retire a rule on usage evidence from `rules_unused_over_8w`" — cannot be walked: the metric counts enforcement events (warn/deny/bypass/applied), so a rule that is simply obeyed emits nothing and reads as "unused". Today the committed figure is **81 unused of 100** (`jq '.summary' knowledge-base/project/rule-metrics.json`, generated 2026-09-14T15:03:50Z), which is the demonstration that the number nominates the best-obeyed rules for deletion rather than the least valuable.

This change has two coupled deliverables in one PR (issue #8030 options 1 + 3):

1. **Re-scope the ladder.** Every site that restates the shrink ladder or the "N rules had no ENFORCEMENT event" hint names the criteria that actually produce headroom — editorial value, and migration of domain-scoped rules to a skill-local home per `cq-agents-md-tier-gate` — and drops every implication that `rules_unused_over_8w` supports retirement.
2. **Run migration tranche 2** in the exact shape of tranche 1 (PR #8034, commit c786c3e0f): enumerate the tagged candidates in `AGENTS.rules.md`, apply the bind-vs-check test to each with a recorded one-line verdict, and move only the rules that CHECK into their enforcing skill doc with the migration banner, walking the hash-manifest governance path. The tranche also closes the one defect tranche 1 hit (a rule placed under the wrong heading) by making the migrated-rule registry self-checking.

Spec lacks valid `lane:` — defaulted to `cross-domain` (TR2 fail-closed). No `spec.md` exists for this branch; the one-shot driver entered `plan` directly.

## Problem Statement / Motivation

- A shrink ladder that advertises an unwalkable rung wastes the next budget session: the reader runs the aggregator, sees "81 unused", and either prunes the wrong rules or gives up. The lint's own comment already says the rung "is not currently actionable" for the #6794 fragmentation reason; #8030 adds the structural reason (enforcement-only events) that survives any telemetry fix.
- The corpus is at `[OK] B_ALWAYS=43343` — 657 bytes below the 44000 WARN tier. Tranche 1 bought 2,555 bytes; a second tranche buys the next increment and, more importantly, validates that the ladder's newly named mechanism (migration) is repeatable.
- Tranche 1's one defect — a callout placed under the wrong heading, caught only by a post-hoc in-session assertion — is not guarded by any test today. The registry it created (`scripts/migrated-rule-ids.txt`) has a reader-parity test but no placement test.

## Guard Contract

### Guard 1 — migrated-rule registry placement lint (`scripts/lint-migrated-rule-ids.sh`)

**Property.** Every rule listed in `scripts/migrated-rule-ids.txt` has its `[id: <id>]` body line inside the section of the named heading in the named file, is absent from `AGENTS.rules.md`, and has an orphan-exemption row in `scripts/retired-rule-ids.txt`; and every migration banner in `plugins/` names an id that has a registry row.

**Assembly.** Two chokepoints, both structural: (1) `scripts/migrated-rule-ids.txt` — the only file the telemetry hook and aggregator accept a migrated id from, so a migration that skips it loses telemetry, which is why every migrated rule must flow through it; (2) the banner literal `— migrated out of \`AGENTS.rules.md\` on` — the only marker a migrated body carries at its new home, discovered by plain `grep -rlF -- '— migrated out of `AGENTS.rules.md` on' "$ROOT/plugins"` (never `git grep`: a `mktemp` fixture is not a git repo, and under lefthook in a linked worktree `GIT_DIR` is exported, so `git -C "$ROOT" grep` would search the real repo's index from inside a fixture — the #7833 class) over `plugins/` (reverse direction: a banner with no row). Per row the guard quantifies over: the target file, the heading line (exact match, `grep -Fx`), the line range from that heading to the next heading of equal or higher level **outside fenced code blocks** (a `# comment` line inside a bash fence is not a heading), asserted with `grep -qF` (prose may mention the `[id: …]` token more than once), `AGENTS.rules.md`, and `scripts/retired-rule-ids.txt`. Rows-checked floor: `--min-rows N`, default 7 when run against the real repo (no `--root`), so the guard cannot pass on "0 checked"; fixtures pass `--root <dir> --min-rows 1`, and mutation row 2 is `--min-rows 1` + an empty registry → RED. The floor is the measured count, same convention as `MIN_CHECKS` (a future un-migration lowers it deliberately). Ordering coupling: Deliverable B lands before or with C in the same commit, so the default is 7, never 5.

**Mutation matrix:**

| # | Mutation | Expected |
|---|---|---|
| 1 | In a fixture home file, move the migrated body line above its heading (still in the file) | RED — the range check is heading-anchored, not file-anchored (the tranche-1 defect) |
| 2 | Empty the fixture registry (or comment out every row) | RED — own-dispatch floor: `0 checked` exits 1 |
| 3 | Fixture with one compliant row, then a second row whose heading does not exist in its file | RED — second member after a compliant first |
| 4 | Fixture where the migrated id also still has a body line in `AGENTS.rules.md` | RED — duplicate, not a migration. *Defense-in-depth:* `lint-rule-ids.py` already rejects a retired id reintroduced as active, so this row is a second net, not the guard's reason to exist |
| 5 | Fixture where the id has a registry row but no row in `retired-rule-ids.txt` | RED — aggregator orphan gate would exit 5 |
| 6 | Fixture with a banner in a `plugins/` file naming an id with no registry row | RED — reverse direction |
| 7 | Fixture registry row with the heading at a different level (`####`) and rows in non-alphabetical order, spacing `id|date|#N|path :: #### H` (no spaces around pipes) | must-PASS — grammar permits it |
| 8 | Fixture where the body line sits in the section but AFTER a sub-heading of lower level (`###` inside the `##` section) | must-PASS — lower-level headings do not close the section |
| 9 | Fixture home file whose section contains a fenced code block with a `## `-prefixed line inside it before the body line | must-PASS — a heading inside a fence does not close the section (fence-aware scan) |
| 10 | Fixture `plugins/` file containing the loose phrase `These were migrated out of AGENTS.md` (no backticks, `AGENTS.md`, as at `ship/SKILL.md` "CI workflow edits" bullet) and no registry row | must-PASS — the reverse grep is the exact literal ``— migrated out of `AGENTS.rules.md` on``, never a loosened one |
| H1 | In the test suite, delete the assertion that case 1 exited non-zero (keep the run) | suite must FAIL (case count floor `CASES >= N` and a per-case `rc` check) |
| H2 | In the test suite, replace the mutated fixture of case 3 with the canonical fixture | case 3 must FAIL (the RED expectation now sees GREEN) |
