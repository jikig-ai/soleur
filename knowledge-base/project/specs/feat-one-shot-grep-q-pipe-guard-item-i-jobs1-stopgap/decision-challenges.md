## Corrections

- 2026-10-16: the CTO brief and the rulings above quoted "81 of 192 completed infra steps". The denominator was a planner arithmetic slip. The re-run of the instrument (since deleted, `main` branch only) reads 81 killed of 269 infra steps that could deliver a verdict (30%), plus 31 runs with no verdict (cancelled or early). The numerator and every ruling are unchanged; the ratio the rulings lean on is 30%, not 42%, and the baseline argument (a broken main goes unreported for those runs) holds at either figure. The first measurement also included four early-August dry-run dispatches from feature branches (`-P 4` rows); the instrument now lists `--branch main` only, so those rows are gone. (The 2026-10-16 note that the infra `-P` column then read `1` for all 269 was wrong: the extractor had cached storage-error bodies as logs for a few runs and 268 of 269 read `1`.)
- 2026-10-16 (deepen-plan): the paired comparison was tightened in the instrument (a ceiling-killed monitor step has a censored RED set and is excluded, as is a run with a cancelled leg). It now reads 15 usable paired shas with 3 informative and zero parallel-only REDs in either direction, so the re-consult figure "5 informative" is superseded by 3. The CTO re-ruling already withdrew statistical sufficiency as the basis, so no ruling changes; the dispatch gate, the revert trigger and the harm comparison carry the decision.
- 2026-10-18 (review): "a broken main unreported for 81 of 269 runs" overstated. A ceiling-killed run does report a verdict (`infra=failure`, no `infra_elapsed_s`); the sample is censored, not silent. The risk acceptance still holds (a killed step cannot name the failing suite), but "unreported" is replaced by "censored" in the workflow note and the evidence. The workflow comment's pin-history tally (seven executions, four suites, "-P 6 on 16 cores clean") was also wrong against #7376's own later correction (eight executions, six suites, the -P 6 run failed under load) and is corrected.
