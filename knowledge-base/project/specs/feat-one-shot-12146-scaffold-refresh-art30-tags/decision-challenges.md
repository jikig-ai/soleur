## Plan refinements made after the rulings (not overrides)

- The ledger has no commit column: a PR cannot know its own squash-commit id. Rows are generated by a command recorded in
  the ledger header, so a reviewer can re-derive any row from git history.
- The CTO's "no 40-hex string in the ledger" check is implemented as a word-bounded scan, because a sha256 row is 64 hex
  characters and contains 40-hex substrings that are not action SHAs.
- Plan review (DHH, Kieran, code-simplicity; all Mechanical) trimmed R6: one committed fixture (the v1.0.236 era the
  tracker names) instead of two, 11 test cases instead of the 20 first drafted, and no history-reproducibility anchor test.
  R6's other content (new test file, sorted registry rows, the RED row that forces a ledger append) is unchanged.
- Plan review corrected the implementation sketch in R3's exit-site table: verification happens before the `mv`, so no
  failure after the write exists; the refusal path hand-rolls its exit instead of calling `die`; the shared trap owner is
  reused instead of adding a second handler.
