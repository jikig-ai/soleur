# Decision Challenges — feat-one-shot-10368-codeql-fs-race

## Decision Classes

| Item | Class | Ruling |
|------|-------|--------|
| Is CodeQL alert #248 a real residual race or a false positive? | technical | Ruled by CTO agent, 2026-10-27: split verdict confirmed. The leaf write is already fail-closed (`wx` = O_CREAT\|O_EXCL refuses any existing final path including symlinks → EEXIST, never write-through) — false positive on that half. The ancestor lstat→(mkdir)→lstat walk + path-resolved `writeFile(target)` IS a true residual: every path op re-resolves ancestors, so a same-UID racing writer inside the agent-tainted ephemeral workspace can swap a verified ancestor for a symlink between the last check and the write, redirecting the digest write outside `spawnCwd`. The threat actor is narrow (presumes a prior exact-literal bash-allowlist escape; `_cron-claude-eval-substrate.ts`) but is precisely what the #7122 containment exists for. |
| Structural fix vs documented suppression? | technical | Ruled by CTO agent, 2026-10-27: structural — fd-pinned traversal. Per-ancestor `open(O_RDONLY\|O_DIRECTORY\|O_NOFOLLOW)` resolved through `/proc/self/fd/<fd>` pins the dentry (Node has no openat/dirfd; `fs.promises.open` numeric-flag support proven in-repo at `resolve-protected-branches.ts`, `compound-promote-create-gates.ts`, `kb-binary-response.ts`; runtime floor `node >=20.16 \|\| >=22.3`, CI Node 22/ubuntu). Leaf: `unlink` (ENOENT-tolerant; EISDIR/EPERM → "target is a directory") then `open(O_WRONLY\|O_CREAT\|O_EXCL\|O_NOFOLLOW, 0o644)`. Realpath-then-verify rejected — it reintroduces a check→use gap; fusing check into the open both closes the race and removes the CodeQL pair. Suppression rejected per `type/security`. |
| Fix scope: include `stageExactPaths` (`_cron-safe-commit.ts`) sibling lstat→hash-object pair? | technical | Ruled by CTO agent, 2026-10-27: no — acknowledged residual. A swap between lstat and `hash-object` produces wrong blob bytes, which `expectedContent` byte-verify and `pushTipReason` refuse to commit or push — fail-closed; the attacker blob sits unreferenced in `.git/objects` with no read-back or push channel. Widening the PR adds review surface for no security gain. Documented in the plan's Attack Surface Enumeration. |
| Non-Linux platform handling (`/proc/self/fd` is Linux-only)? | technical | Ruled by CTO agent, 2026-10-27: Linux gets the dentry pin; non-Linux falls back to joined paths with the same atomic `O_NOFOLLOW`/`O_DIRECTORY` opens (refusals identical, only the pin is lost). The tainted-workspace threat model is the production Linux Inngest worker; dev machines run only the unit suite, and `it.skipIf(process.platform !== "linux")` is fine since CI is ubuntu-latest. Implementation caveat: `fs.constants.O_DIRECTORY`/`O_NOFOLLOW` can be undefined on non-POSIX platforms — coalesce to 0 in flag math so fallback opens never compute NaN flags. |
| Brand-survival threshold | technical | Ruled by CTO agent, 2026-10-27: `none` with sensitive-path scope-out is correct. A broken fix fails the daily digest cron loudly (step failure → FAILED audit issue + Sentry per the plan's Observability block); the digest is handler-rendered counts over public community activity — no user data, user-facing surface, or user workflow is touched. `apps/web-platform/server/` matches the preflight sensitive-path regex, so the `threshold: none, reason:` line is present in the plan. |
