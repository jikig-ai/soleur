# Decision Challenges — feat-one-shot-agent-auth-failure-diagnostic

Headless-path record (no interactive operator gate). Every technical fork was sent to the CTO agent
with the evidence and the instruction not to ask the operator. `/ship` renders this table into the PR body.

## Decision Classes

| Item | Class | Ruling |
|---|---|---|
| F1 — cc-path wiring: wrap the returned Query's async iterator in place (A) vs thread an observer sink through `QueryFactoryArgs` and `soleur-go-runner` (B) | technical | Ruled by CTO agent, 2026-10-25: A, with the wrapper delegating `return` and `throw` to the real iterator and observing only `next`; no-op when the object is frozen, non-writable or not iterable - the runner consumes with `for await`, a generator re-wrap would swallow `break` and cleanup, and B widens a hot shared interface. |
| F2 — authMode source: lazy failure-path lookup (A) vs thread from ws-handler (B) vs omit (C) | technical | Ruled by CTO agent, 2026-10-25: A with an injected resolver (not a dynamic import); claim the debounce slot synchronously first, then resolve (1.5 s timeout, fail to `unknown`), then emit, all fire-and-forget - the claim before the lookup caps DB reads at one per tuple per window, and B touches both runner signatures for a failure-only field. |
| F3 — volume control: once per probe plus a 5-minute per-user debounce keyed on the full tuple (A) vs once per probe (B) | technical | Ruled by CTO agent, 2026-10-25: A with authMode REMOVED from the key; key = `runner\|scheme\|envPresent\|artifact\|egress\|sandbox\|outerWrap` - authMode is async and stable per user, so keying on it would force the lookup before the claim; the synchronous dimensions are the ones that flip under a config change. |
| F4 — matcher scope: structured `error === "authentication_failed"` OR anchored whole-message text patterns (A) vs text only (B) | technical | Ruled by CTO agent, 2026-10-25: A, plus a fixed `match_kind` enum tag (`structured`, `not_logged_in`, `invalid_api_key`, `oauth_token_revoked`, `session_expired`) and `·` escapes for the separator - anchored whole-message matching rejects the "Invalid API key format" and model-prose near-misses; the enum is the only message-derived value emitted. |
| F5 — alert shape and discoverability: filter `feature` AND `op` plus contract test and a one-line rg probe (A) vs clone the masked-dir bash script and mutation suite (B) | technical | Ruled by CTO agent, 2026-10-25: A; rule `agent_auth_failure`, `frequency_minutes = 40`, filters `feature=agent-auth` AND `op=cli-auth-failure` - the op filter stops future `agent-auth` diagnostic ops from paging, and the triple-parse contract test covers drift where a cloned script would serve a single-emitter rule badly. |
| F6 — payload: discriminators in searchable tags (the `extra` question is F6b); add `outer_wrap`, `credential_scheme`, `match_kind` beyond the operator's list | technical | Ruled by CTO agent, 2026-10-25: accepted; every tag value is a string from a closed enum and `userId` stays out - the outer wrap changes how env reaches the CLI, so it is a discriminator, not leakage. |
| F6b — also duplicate the tuple into `extra` (the pino line carries `extra`, never `tags`) | technical | Ruled by CTO agent, 2026-10-25: A, same closed-enum key/values in `tags` AND `extra`, built from one object and pinned equal by a test; no `err`/`feature`/`op`/`message` keys, no ids - without `extra` the Better Stack copy carries no discriminators, and that second sink is the one that still works if Sentry capture is the broken part. |
| F10 — add the CLI's own `apiKeySource` (closed `ApiKeySource` enum from the init message) as a tenth key `cli_key_source` | technical | Ruled by CTO agent, 2026-10-25: accepted with modifications - taken from the init message only when it is a member of the closed list, else `unknown`, in both tags and extra, kept OUT of the debounce key as first ruled (it arrives later and is probe-local; amended in the plan's Proposed Solution 3 and implemented 2026-10-25: the slot is claimed after `init`, so the tuple is complete at claim time and `cli_key_source` is IN the key, so a changed key source re-emits); `error === "authentication_failed"` alone suffices for the structured arm, and `is_api_error_message` / `model === "<synthetic>"` are corroboration for the text arm, never requirements, because the synthetic literal is unverified against the SDK types. |
| F11 — alert lifecycle after the fix: avoid a permanent email nag from user-revoked tokens | technical | Ruled by CTO agent, 2026-10-25: accepted with modifications - step 1 drops the email action within 48 hours of the first recorded event (the pino line and the Sentry issue stay), step 2 removes the rule when the root-cause fix merges or 30 days after the first event, whichever comes first, with a tracking issue filed before merge; dropping the email only reduces notification. |
| F12 — also match the text on a thrown iterator error (`match_kind: thrown`) | technical | Ruled by CTO agent, 2026-10-25: declined - the credential-free local run of the real binary produced a normal synthetic message and exit 0, not a throw; recorded as a non-goal with two triggers (outage persists with no event, or a user report of the auth text with no event); accepted limitation: a spawn-time throw is invisible to this probe. |
| Plan-review challenge: drop the authMode resolver and ship `auth_mode=unknown` (DHH) | taste | Default taken, operator direction kept: authMode is in the brief's list of required fields, so dropping it is a scope cut the review panel may not make; the cost is bounded (failure path only, one lookup per tuple per window) and the decode key says when it carries no information. Surfaced for the operator in the PR body. |
| Plan-review challenge: drop the 5-minute cross-dispatch debounce and keep per-probe once only (DHH, code-simplicity) | taste | Default taken, CTO F3 stands: the new spec-flow finding (a warm Query serves many turns, so the latch now resets per `result`) makes the cross-turn debounce the only rate limit; "one event" in the brief is per dispatch, not per outage. |
| Plan-review challenge: keep only the structured arm and one text pattern (DHH) | taste | Default taken, operator direction kept: the brief names the "not-logged-in / invalid-credential family"; the four anchored patterns are data in one const, and the structured arm covers wording drift. Surfaced in the PR body. |
| Plan-review challenge: cut test volume (about 650 test lines, two guard contracts) because the diagnostic is temporary (DHH) | taste | Default taken in part: Guard 1 row 8 was cut as duplicate coverage of the wiring tests; the rest stays because the brief asks for the three test kinds, the CPO made the secret canary blocking, and the repo's guard-contract gate requires the matrices; removal is one pass via the module-header checklist. |
| F13 — the text arm is tenant-forgeable (a tenant can make the model reply with the exact CLI string); require CLI-set fields | technical | Ruled by CTO agent, 2026-10-25: accepted, reversing the corroboration-only part of F10 - the text arm requires `message.model === "<synthetic>"` OR `is_api_error_message === true`, text is classified first and `structured` is the fallback so `match_kind` keeps its variants, a forged plain-assistant block with neither field must not fire; if the SDK renames the fields the text arm goes silent and only the structured arm fires, which the plan records. |
| F14 — tenant-triggerable genuine failures and eviction churn | technical | Ruled by CTO agent, 2026-10-25: accepted - a process-wide cap of 10 events per 5 minutes under a global key, checked FIRST so a flood cannot evict per-user entries, on top of the per-user debounce; suppressed events are counted in a bounded in-memory counter and never logged at warn (that feeds breadcrumbs); `cli_key_source` values project, user, apiKeyHelper and org are documented as tenant-influenced. |
| F15 — cross-tenant breadcrumbs and user on the process-wide scope | technical | Ruled by CTO agent, 2026-10-25: accepted - emit inside `Sentry.withIsolationScope` with `scope.clearBreadcrumbs()` and `scope.setUser(null)`; confirm at work time that the installed `@sentry/nextjs` exports it and that an async-context strategy is active, and prove with a pre-seeded test that other tenants' breadcrumbs and user are absent from the captured event while the outer scope is unchanged. |
| Issue B escalation date (ship the friendly error alone if the root-cause fix has not merged by a stated date) | operator (schedule) | Proposed default, for the operator to confirm in Issue B: 14 days after the first recorded event. Not decided by this plan; the date is a schedule and priority call. |
| F7 — module placement: leaf `server/agent-auth-failure.ts` (matcher, probe, tap) plus a second small file for the authMode resolver, injected at the call sites | technical | Ruled by CTO agent, 2026-10-25: accepted with injection instead of dynamic import - a dynamic import breaks vitest mocking and bundler analysis, and injection keeps matcher tests mock-free and the client/server boundary untouched. |
| F8 — probe inputs: which options object feeds the context derivation | technical | Ruled by CTO agent, 2026-10-25: derive from the FINAL options object passed to `sdkQuery`/`query` (after `recordCcSeccompArtifact` in cc), never a pre-wrap object - a pre-wrap read would report the wrong seccomp artifact and outer-wrap values. |
| F9 — alert lifecycle: the rule also fires on user-caused revoked BYOK tokens | technical | Ruled by CTO agent, 2026-10-25: frame the rule as a temporary diagnostic with a constant message (one Sentry issue; the 40-minute re-notify bounds email) and file a removal-trigger issue in the ship phase. |
