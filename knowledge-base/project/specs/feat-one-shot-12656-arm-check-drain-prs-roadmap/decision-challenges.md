| A. drain-prs §4 merge semantics | technical | Ruled by CTO agent, 2026-11-12: A2, with the sub-question ruled strictly. The arm check is required for every PR whose §5 route is `soleur:review`, and for every PR onto which drain-prs pushed any commit other than a plain main sync. That covers a fix-recipe (a) lockfile regen, a (b) conflict-resolving merge, and any other commit drain-prs wrote. On refusal, run `soleur:review` and then the check again. If it still refuses, report "unarmed: no evidence covers the head" and skip the PR; never arm around it. A PR is exempt only when it is bot-authored, §5 routes it to the inline `gh pr diff` read, and drain-prs pushed nothing to it. A conflict-free `gh pr update-branch` or `git merge origin/main` does not break the exemption. The exempt arm pins the head it read with `--match-head-commit`. A fix-recipe push, even a mechanical npm@11 lockfile regen, removes the exemption. Rationale: the #12656 hazard is a commit after the evidence. A PR that never had evidence and was never pushed to has no such commit. A1 would refuse almost the whole bot workload (9/9 recent bot PRs carry no evidence). A4 would forge the agent review. Dissent (CTO), confirmed at plan time: bot PRs that touch `infra/` or `.github/workflows` belong on the `soleur:review` route. #12691, #12700 and #12546 touch `apps/web-platform/infra/`, so the exemption excludes any PR touching a domain surface listed in review-evidence-comment.md `## The gate`. |
