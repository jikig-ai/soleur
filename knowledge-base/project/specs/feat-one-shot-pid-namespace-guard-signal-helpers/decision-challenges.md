## 2026-10-10 Plan

1. **User-Challenge: scan size.** The CTO read recommends cutting the scan to ancestor walks only (2 sites) as a grep inside an existing suite with no baseline file, because baselining the 19 non-walk sites (parent signals, group signals, pattern kills) does not reduce hazard. The brief asked for "an inventory scan (a script plus test, ideally a lint or ratchet with a baseline)" listing walkers "or other signal-to-ancestors patterns". Default kept: the brief (four classes W, P, G, M, 21 rows). Cheap fallback if the panel agrees: gate only W and keep P, G, M as `--list` output.
2. **User-Challenge: breadth of rule text.** The CTO read recommends keeping only `work-scratch-sandboxes.md` and the reviewer agent pointer, dropping the review `SKILL.md` pointer (322 bytes of ceiling headroom) and the plan sharp-edges entry. The brief names the reference doc, the allocator, the review skill's brief text and the reviewer agent; the sharp-edges entry is an inferred item (the incident began in a plan). Default kept; the `SKILL.md` pointer is already conditional on fitting the byte headroom.
3. **Taste: helper placement.** CTO preference: helper in `scripts/lib/`, only its test under `plugins/soleur/scripts/`. Kept in `plugins/soleur/scripts/` because the brief says "for us or soleur users", a repo-only file would not ship to plugin users, and the glob registration needs no runner edit either way. Revisit if the plugin count or description-budget checks object (Phase 6 runs them).
4. **Taste: rc 125 vs a rarer code.** `git bisect run` and `xargs` also use 125; the marker line is the disambiguator and is documented. A rarer code (86, 97) would collide less. Kept 125 (the `timeout`/`env` convention).
5. **Taste: write confinement.** The namespace bounds signals only. bwrap (`--ro-bind`, already used by the sandbox canary) would also bound file removal but is not available everywhere. Not planned; the doc states the limit. Raise if the panel wants it.
6. **User-Challenge: local affected-gate classification.** The scan's suite is derived (stem equality), not ALWAYS_ON, so a local `--affected` run does not select it when an unrelated diff adds a walker; CI's full battery does. Promoting it needs a one-line edit to `scripts/lib/test-affected-paths.sh` (fenced off by the brief) plus a runner-parity enumerate check.
7. **Split assessment.** 4 roots and about 1300 lines exceed the thresholds. Single PR kept as briefed; seam if wanted: PR-A helper + verb + wiring, PR-B scan + baseline + roadmap-reconcile bound.
8. **Inferred scope item: bound the second walker.** `plugins/soleur/test/roadmap-reconcile.test.sh` (`term` branch) is an unbounded ancestor walker found by the scan prototype. Fixed here so the baseline never certifies an unbounded walker. Drop it if the panel wants the change to be tooling only; then the scan's admissibility rule needs a temporary exception row, which is worse.
