Headless planning run for issues #13098/#13099. This depth-1 harness cannot spawn the CTO or review panel as independent subagents; technical rows were ruled through the required sequential inline fallback. The fallback is disclosed in the plan and no row claims independent review.

## Decision Classes

|---|---|---|
| Per-file timeout budget: 30s plus 5s kill grace vs the issue's illustrative 120s | technical | Ruled by sequential inline CTO fallback, 2026-11-27: Confirmed — 30s/5s. Planning probes measured the 422,652-byte `ci-deploy.sh` completing in about 9s and the 261,363-byte `worktree-manager.sh` in about 6s under a memory ceiling. The issue's 120s is explicitly an example (`e.g.`), not a required constant; 30s is roughly 3x the slower measured completion and prevents a large diff from multiplying two-minute stalls. Caveat: rc=1 must remain a completed scan, not a failure class. |
| Size cap: enforce 512 KiB vs omit the optional cap vs use 128/256 KiB | technical | Ruled by sequential inline CTO fallback, 2026-11-27: Confirmed — enforce 512 KiB. Only three tracked shell files exceed 512 KiB, including the argv-bearer monolith and `test-all.sh`; the measured 422,652-byte production script still completed. A 128/256 KiB cap would refuse dozens of files that may scan successfully. Caveat: size is a prefilter, never a safety proof; the timeout remains mandatory for all smaller files. |
| Unscannable input receipt semantics: `refuse` vs warning-only `ok` vs a separate token | technical | Ruled by sequential inline CTO fallback, 2026-11-27: Confirmed — `refuse` with trailing `scanned=`/`unscannable=` fields and a `file:0 unscannable-*` evidence row. A separate token would force every consumer to learn a fourth verdict for the same fail-closed outcome. Caveat: real ShellCheck findings remain non-blocking; only missing coverage refuses. |
