| Per-file timeout budget: 30s plus 5s kill grace vs the issue's illustrative 120s | technical | Ruled by CTO agent, 2026-11-28: use a 30-second per-file wall-clock budget with a 5-second kill grace - measured full-analysis completion of the largest completing inputs was 4.32-10.43 seconds, so 30 seconds is roughly 3x the slowest observed completion; 120 seconds was illustrative, and kill grace is not analysis budget. Dissent: a saturated host may falsely time out a valid input, but visible refusal is preferable to a silent wedge. |
| Size cap: enforce 512 KiB vs omit the optional cap vs use another threshold | technical | Ruled by CTO agent, 2026-11-28: omit the optional size cap in this PR and scan every classified shell file under the per-file timeout, failing closed only on actual noncompletion or scanner-execution failure - byte size is neither a necessary nor sufficient predictor in the measured corpus: `scripts/test-all.sh` exceeds 512 KiB yet completes, while a smaller cutover test hit the probe bound. Dissent: a pathological large file can consume the full timeout envelope, and timeout alone does not bound memory before it fires. |
| Unscannable input receipt semantics: `refuse` vs warning-only `ok` vs a separate token | technical | Ruled by CTO agent, 2026-11-28: emit `refuse` for any unscannable input, carrying trailing `scanned=`/`unscannable=` fields and a `<file>:0 unscannable-<reason>` evidence row - ADR-324 makes the receipt architectural evidence, so `ok` while coverage is missing would falsely certify the scan. Dissent: one bad input blocks review even when others scan cleanly, which is deliberate fail-closed behavior. |
