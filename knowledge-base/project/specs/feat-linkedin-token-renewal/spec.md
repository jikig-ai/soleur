# LinkedIn OAuth token renewal — operator bootstrap

**Refs:** #7404 (LINKEDIN_ACCESS_TOKEN, opened 2026-08-10), #7606
(LINKEDIN_ORG_ACCESS_TOKEN, opened 2026-08-17)

> **Update (PR #9183, #9181):** the Community app (`clientId 78s808ujpe6lve`)
> has no `openid`, so the org token can never pass `/v2/userinfo`. The cron and
> `bootstrap.sh` below now probe it via `organizationalEntityAcls` and mint it
> under the Community app's generator URL; this spec's per-token scope lists
> and single-generator instructions are the historical record only.

## Context

`cron-linkedin-token-check` (weekly, Monday 11:00 UTC) calls
`api.linkedin.com/v2/userinfo` for both LinkedIn secrets and opens a
deduplicated action-required issue on HTTP 401 — LinkedIn OAuth tokens carry a
60-day TTL. Both issues remain open; the 2026-09-28 run was the latest weekly
"still expired" comment.

## Why a bootstrap script

Per `hr-multi-step-post-merge-bootstrap-script`: the renewal has more than two
scriptable steps (write both tokens to GitHub Actions secrets AND to Doppler
`soleur/prd`, verify each, refresh the deployed app's env) gated on ONE
credential the agent cannot mint — a LinkedIn sign-in + OAuth consent in the
token generator (verified via Playwright: the generator redirects to
`linkedin.com/developers/login`).

## The artifact

`bootstrap.sh` — generated by `soleur:operator-bootstrap` on the shared
`plugins/soleur/scripts/lib/operator-script.sh` library. Four stages:

1. `LINKEDIN_ACCESS_TOKEN` — Doppler-auth preflight, then opens the token
   generator (scopes: `openid, profile, w_member_social, email`), reads the
   pasted token, verifies it against userinfo BEFORE persisting, then writes
   GitHub secret + Doppler `soleur/prd` behind per-command acks.
2. `LINKEDIN_ORG_ACCESS_TOKEN` — same flow (scopes: `openid, profile,
   w_member_social, w_organization_social`) plus an advisory
   `organizationalEntityAcls` org-scope probe.
3. Env refresh — the app reads Doppler at container start; offers to dispatch
   `web-platform-release.yml` (`bump_type=patch`, ships current main, class-2
   ack) or defer to the next merge. The dispatch is stamped BEFORE
   `gh workflow run` and the run id is captured by createdAt, so an
   interrupted run can never double-dispatch.
4. Verify — both Doppler values re-checked live, both GitHub secrets confirmed
   present, in-flight deploy state reported.

Design notes: tokens are verified BEFORE any persistence; the GitHub-write
marker is keyed to a sha256 fingerprint of the value written (a stale marker
can never skip a write a new token needs); Bearer headers travel via
`curl --config -` stdin, never argv; a 60s `bound` caps every vendor CLI call;
`live | rejected | transport` is tri-stated so a network failure never
prescribes a needless re-mint.

Run: `bash knowledge-base/project/specs/feat-linkedin-token-renewal/bootstrap.sh`

Non-interactive: set `SOLEUR_BOOTSTRAP_LINKEDIN_ACCESS_TOKEN` /
`SOLEUR_BOOTSTRAP_LINKEDIN_ORG_ACCESS_TOKEN` (+ optional
`SOLEUR_BOOTSTRAP_DEPLOY_CHOICE=yes|defer`). Store writes still require a typed
`yes` per command — no fully unattended prod write by design.

## Recovery paths

- **Bad paste / expired token recorded** — `bootstrap.sh --reset <KEY>` forgets
  a persisted `.env` value.
- **Live-but-wrong token in Doppler** (valid token, wrong scopes) —
  `SOLEUR_BOOTSTRAP_FORCE_MINT=1 bash bootstrap.sh` skips both reuse rungs and
  goes straight to credential entry (`--reset` alone cannot reach this state:
  the Doppler-first ladder would re-import it).
- **Interrupted deploy dispatch** — the script wedges on the
  `DEPLOY_DISPATCH_ATTEMPTED` stamp; check `gh run list` then
  `--reset DEPLOY_DISPATCH_ATTEMPTED`.

## Closeout (automatic)

Once a deploy has picked up the new Doppler values, the weekly check calls
userinfo, finds both tokens valid, and auto-closes #7404 and #7606 (the cron's
own dedup + auto-close path). To close sooner after a deploy, fire
`cron/linkedin-token-check.manual-trigger` via `soleur:trigger-cron`.

## Lifecycle

Delete `bootstrap.sh`, `bootstrap-runs.jsonl` and `.env` together when #7404
and #7606 close — the `.env` holds live credentials.
