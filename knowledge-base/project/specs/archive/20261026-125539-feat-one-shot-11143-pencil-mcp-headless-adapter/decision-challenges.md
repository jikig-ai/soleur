| R4. Empty-overwrite sentinel | technical | Ruled by CTO agent, 2026-10-26: one `guardedSave()` chokepoint for all four write sites including the explicit `save` tool. Refuse (isError, no write) when the on-disk target parses with `children.length > 0` and the in-memory document is empty. Short-circuit when the target is missing, 0 bytes or unparseable. Refuse when the target is non-empty and the in-memory state cannot be determined. A deliberate delete-all-then-save over a non-empty file is refused; the message gives the escape (save to a new path). |
| R5. Regression test strategy | technical | Ruled by CTO agent, 2026-10-26: all three layers. | R6. | R7. MCP-boundary strictness (reject unknown keys on every tool via `registerTool` + `.strict()`) | technical | Ruled by CTO agent, 2026-10-26: concur, cut strict MCP-boundary schemas (do not move to `registerTool` + `.strict()`) - re-measured here with a spike against `@modelcontextprotocol/sdk` 1.32.1 (`apps/web-platform/node_modules`): legacy `server.tool()` with `{a: z.string()}` called with `{a, filePath}` returns `{"a":"1"}`, so unknown keys are stripped silently, and `.strict()` would reject Desktop-grammar callers that pass `filePath` (`pencil-mcp-adapter.mjs` registers `filePath` on `open_document` and callers pass it elsewhere), breaking working flows. The real drift class (adapter vs engine signatures) is closed by the engine-side surface conformance table (Guard 2); data safety does not depend on boundary strictness because `guardedSave()` is the write chokepoint. Flips to build-it if a caller is shown to depend on a stripped key producing a wrong write. Revisit in #11156. |

| R11. Pre-switch save in `open_document`: guard it (R4 as ruled) or delete it (DHH) | technical | Ruled by CTO agent, 2026-10-26: concur, delete the pre-switch `save()` in `open_document` rather than guard it - verified at `pencil-mcp-adapter.mjs` open_document: the save already runs only when the prior mutation did not error, and every mutating tool (`batch_design`, `set_variables`) auto-saves, so the pre-switch save can only re-persist state that was already saved or that the guard would refuse; deleting satisfies the issue's "skip the pre-switch save when the document is empty" strictly, removes a write site (four to two, both through `guardedSave()`), and loses no data because the skip-on-error branch already prevented any retry in the only case a retry would matter. R4's chokepoint and fail-closed predicate are unchanged. Flips to guard-it if a mutating tool is added that does not auto-save. Dissent: none (DHH's position is adopted). |
