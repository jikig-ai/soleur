| (superseded in part by the review-round rows below) D1 Shape of the wait: one shared helper vs inline loops at each site | technical | Ruled by CTO agent, 2026-10-13: one shared helper with its own BEGIN/END sentinels, counted by iterations, bound `GIT_DATA_ATTACH_WAIT_S` default 300 - a single helper stops the two sites drifting (same reason as `soleur-inngest-nic-wait`) and lets the extracted test harness cover it. Constraints: the helper takes a predicate and retries the WHOLE check each pass (section 1 re-runs the by-id glob plus `cryptsetup isLuks`, because the plaintext volume can attach first and a "some volume exists" wait would exit early); the plaintext predicate adds `blockdev --getsize64 > 0` to the existing `realpath -e` + `stat -L` test; the bound is validated (`^[0-9]+$`) before the first probe and an invalid value gets its own FATAL and `exit 1`, never a default; existing FATAL sentences stay byte-identical; one log line at wait start and one at resolution to the runcmd detail; `-u GIT_DATA_ATTACH_WAIT_S` added to the `env -u` list and census C2 updated; `MIN_ASSERTIONS` raised in the same PR. |
