## RULING 1 - the fork: (C) "A now, as one must-ask lane in canUseTool; B recorded as a later consolidation"

Not B. Reasons, in order of weight:
1. B is structurally a no-op under autonomy. A plugin-hook `ask` is delivered to the SDK permission flow, which then calls `canUseTool`; `canUseTool` returns `allow` for `autonomous-bypass`. Unless `canUseTool` also reads the hook's reason (`options.decisionReason`, a free string whose contract is unmeasured), the hook's ask is silently answered by the bypass. B therefore needs A's code anyway.
2. B also turns on the 4b ask classes (`bound`, `lexer-empty`, `unparsed-wrapper`, `wrapper-depth`, parse asks) for every hosted Bash call; their false-positive rate is unmeasured (CPO3-R3). That is a hosted-wide friction risk for no scope gain.
3. B adds perl+jq+bash process spawns to the hosted hot path and a second approval surface.
The "hosted ask is unmeasured" objection in D8 is about the hook's `ask` through the SDK. The `review_gate` WS surface that A uses is the proven production gate (it carries every non-safe command in non-autonomous mode).

Not "A as an ad-hoc regex either": ship a pure TS classifier with a corpus bound to the hook (below), so B/consolidation later is a measured swap, not a rewrite.

### Where the code goes

1. NEW `apps/web-platform/server/destroy-ask-classifier.ts` - pure, no I/O: `classifyDestroyFamily(command, resolveProtected): Promise<DestroyMatch | null>` where `DestroyMatch = { ruleId, family: "git-default-branch" | "terraform-destroy" | "fail-closed" }`. `resolveProtected` is awaited ONLY after a force/delete/mirror push is found (lazy; most sessions never call it).
2. NEW `apps/web-platform/server/resolve-protected-branches.ts` - the only I/O: returns `{ names: Set<string>, authoritative: boolean }`. Sources, UNION: (a) GitHub API `default_branch` via the installation token (server-held, agent cannot tamper -> `authoritative = true`), (b) local `<workspacePath>/.git/refs/remotes/origin/HEAD` (agent-writable, so used only to ADD names, never to remove), (c) constants `main`, `master`. 3 s timeout, memoised per session record (negative result cached 30 s). Failure -> `reportSilentFallback(op: "default-branch-resolve")` and `authoritative = false`.
3. EDIT `permission-callback.ts`: add dep `resolveProtectedBranches?: () => Promise<ProtectedBranches>`; insert the lane at ONE point: immediately AFTER the support-persona deny and BEFORE `if (deps.bashAutonomous)`. Order is therefore: blocklist deny (wins) -> safe-bash allow (cannot match a destroy command; invariant test) -> near-miss telemetry -> support deny -> **must-ask lane** -> autonomous branch / opt-out hold / batch cache -> review-gate. On a match, set `mustAsk` and wrap the autonomous block, the existing-workspace opt-out block and the `bashApprovalCache.allow` lookup in `if (!mustAsk)`; on `mustAsk` the gate options are exactly `["Approve","Reject"]` (no "Approve all"), and the question is `Destructive command - paused for your approval\n\n<one-line reason>\n\n\`<redacted preview>\`` (reuse `redactCommandForDisplay`, 200-char cap, offline-notify path unchanged). Approval grants nothing durable: not an ack, not a cache entry. Gate timeout/abort throws -> deny (existing fail-closed).
4. EDIT `cc-dispatcher.ts` near the `ccDeps` construction (`bashAutonomous`, `isOwner`, `resolveAckPosture` are wired there): wire `resolveProtectedBranches` from the already-resolved installation id, repo owner/name and `workspacePath`.
5. The lane is a function list (`MUST_ASK_CLASSIFIERS`) with this classifier its only member; #9388 adds a second member later. Do not build more abstraction than that list.
6. The classifier runs in BOTH modes. In autonomous mode it removes the bypass/hold; in non-autonomous mode it removes the cache laundering. Same code path, no extra surface.
7. Any exception inside the classifier is treated as a match (ask) plus `reportSilentFallback(op: "destroy-classifier-error")`.

### Default-branch determination (fail toward ASK)

Protected set = union of (a), (b), (c) above, compared case-insensitively after stripping `refs/heads/` or `heads/`. A force/delete/mirror push is a match when its destination is in the set, is a glob/expansion (`*`, `?`, `[`, `$`, backtick), is `:` (matching) or `--all`/`--mirror`, or is IMPLICIT (no refspec, `HEAD`, `.`). When `authoritative = false` (API failed, no installation, no connected repo) EVERY force/delete/mirror push asks (rule `git-push-unknown-default`). Rationale: force pushes are rare; one extra click is cheaper than one erased history. No per-command network call and no `git` spawn on the hot path. Implicit-destination force pushes ask unconditionally (no HEAD read): simpler, and measurable via telemetry; tune later if the rate is non-trivial.

### What the classifier must recognise

- Command position: split on unquoted `; & && || | newline`; recurse (depth <= 4) into `$(...)`, backticks, `<(...)`, and `sh|bash|zsh|dash|ksh|ash` with any short-flag cluster containing `c` (`-c`, `-lc`, `-ec`); quote removal (`"git" push`), backslash-newline joins, leading `NAME=value` words, absolute-path binaries by basename, case-insensitive names, wrappers `env command nohup time timeout nice doas` (small table; unknown wrapper words are skipped until a `git`/`terraform`/`tofu` basename is found).
- `git`: ANY argv word equal to `push` after the `git` word (so `-C dir`, `-c k=v`, `--git-dir`, `--work-tree`, `--namespace`, `-P` need no table). Force: `-f`, `--force`, `--force-with-lease[=..]`, `--force-if-includes`, any short cluster containing `f`, any `+refspec`. Delete: `--delete`, `-d` (also in clusters), `--prune`, `:ref`. `--mirror` and `--all` with force. Push-option/value flags (`-o`, `--push-option`, `--repo`, `--receive-pack`, `--exec`) consume a word; `--` ends options. First positional is the remote; the rest are refspecs; `--delete` makes them branch names. Destination normalisation: strip `+`, take the part after `:`, strip `refs/heads/`/`heads/`.
- `terraform|tofu`: any argv word `destroy`; or `apply` plus `-destroy`/`--destroy`/`-destroy=<v>` where `<v>` is not `0 f F false FALSE False`; global `-chdir=...` needs no table (word scan). `plan -destroy`, plain `apply`, `fmt`, `validate` pass. An env word or `export` containing `destroy` on a terraform/tofu command (TF_CLI_ARGS) asks.
- Fail-closed rule for an unparseable command (unbalanced quote, unterminated substitution, NUL, depth/size bound >64 KiB): ask IFF the quote/backslash-stripped, case-folded text contains `destroy` or `push`; otherwise pass (an ask there is pure false positive: no D1 command can be spelled without those letters, except variable-built names, a stated residual). A raw-text scan (`push` + force/delete marker + protected-name token, or `destroy`) also runs when the structured pass found nothing AND the command has a here-doc, `<<<`, a pipe into a shell, or `xargs`.

### What it need not recognise (stated residuals, same as hook D2)

Variable-built command names, aliases (`git -c alias.p=push`), a script written then run, `xargs`/`find -exec` without the raw-scan trigger, `terragrunt|pulumi destroy`, plain `terraform apply` of a destroy plan, recursive `rm` (CPO-excluded), `gh api -X DELETE .../git/refs/heads/<default>` and `gh repo delete` (equivalents of the same harm, deliberately NOT in this PR: CPO scoped git-push forms; record them in the ADR addendum as a residual, file one sized issue only if sized, no roll-up), `git update-ref`, force-push to a non-default branch.
