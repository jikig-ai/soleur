# Spec-flow findings (not yet integrated into the plan)

Source: soleur:product:spec-flow-analyzer run against the plan, 2026-09-24. Fold these in during deepen-plan.

1. **P0 — host follows a symlink the child plants in writable `/c4-out`.** `renderToValidatedModel` `readFile`s `<dir>/out/model.likec4.json`; a compromised likec4 can make it a symlink to another tenant's `/workspaces/.../model.likec4.json`, which passes both gates and gets committed into the attacker's repo. Fix: `lstat` (regular file only), open with `O_NOFOLLOW`, size-cap before read. Guard row: fake spawn plants a symlink, RED on plain `readFile`.
2. **P1 — no resource bounds on a compromised child.** Unbounded stderr buffer (`stderrChunks` sliced only at `close`), uncapped `--tmpfs /tmp` (RAM), output read whole before the 4 MB cap, no process/memory limit. Fix: stop buffering stderr past 512 B, tmpfs `--size` if bwrap 0.8.0 supports it, `prlimit`, `stat` output size before read.
3. **P1 — "It will refresh" line promises what the UI never does.** No client polls/reloads after save. `rerendered:false` with no diagnostic covers both a real supersede and a resync failure (an incident, `op=resync`); Concierge guidance also says "will update shortly". Fix: `c4-writer.ts` returns a diagnostic on resync failure; for a real supersede, bounded re-fetch of `/project` or "Reopen the diagram in a minute". Test resync-failure → diagnostic.
4. **P1 — Concierge `edit_c4_diagram` while the banner is up changes nothing on screen.** Workspace has no listener; stale reason stays and diagram isn't reloaded. Fix: clear stale reason + reload on Concierge edit completion for this `dirPath`; test row.
5. **P1 — boot self-probe proves far less than a real render.** `likec4 --version` doesn't write `/c4-out`, may not touch `/etc/passwd` (`os.userInfo`), no wasm layout. Fix: probe does a real export of a one-element fixture through the same argv, assert ≥1 view (~4 s, once per boot).
6. **P1 — real-bwrap isolation row passes vacuously on CI.** Runners have no `/workspaces`; `/proc/1/environ` unreadable anyway. Fix: sentinel dir + sentinel env var in the test process, target `/proc/<test pid>/environ`; positive control outside the sandbox, then assert unreadable through the builder's exact argv (only the post-`--` command swapped).
7. **P2 — AC2 proof uses a mocked `C4Diagnostics`.** Add a `c4-diagram.test.tsx` row rendering the real component through `reload()` + `setTab`.
8. **P2 — stale state leaks/disappears.** `C4Workspace` has no `key` (banner carries across dirs); page reload drops the reason; zero-view committed models show blank canvas / user-blaming message. Fix: `key={c4DirPath}`; `/project` reports "elements but no views" as a diagnostic.
9. **P2 — saves slower with no feedback.** Real layout +4–15 s, slot wait up to 10 s; "Saving…" only covers ~1 s commit; mid-request network drop shows "Save failed" for a committed save; slot-wait timeouts say "Save again" (adds load). Fix: state latency in ACs; consider "Saved — updating diagram…".
10. **P2 — Sentry grouping.** `new Error(render.detail)` puts variable stderr/counts in the message. Fix: fixed message per reason, detail in `extra`, `warnSilentFallback` for `render slot wait`.
11. **P2 — classification.** `sandbox_error` must key on raw stderr first line, not the `exit=1 stderr=…` detail string. Row: stderr starts with a likec4 line, `bwrap:` later → `non_zero_exit`.
