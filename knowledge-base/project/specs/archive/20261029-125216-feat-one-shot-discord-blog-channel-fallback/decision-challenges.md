## Deferred escalation (ruled — replaces Not Yet Specified)

Ruled by CTO agent, 2026-10-29: **Yes — escalate a persistent fallback via in-cron standing issue filing** through `ensureDedupIssue` with a dedicated label and auto-close-on-recovery (the `runStarvationCheck` pattern already in this handler), implemented as a follow-up, not this branch. File-on-marker-fire is the trigger (dedup collapses repeats; auto-close handles recovery; this cron only runs in prd where the blog webhook is supposed to be set, so there is no legitimate persistent-fallback environment). A `sentry_alert` rule rejected: permanent Terraform state, pages on first fire, and cannot express unresolved duration — whereas an open `action-required` issue literally is the persistence record.
