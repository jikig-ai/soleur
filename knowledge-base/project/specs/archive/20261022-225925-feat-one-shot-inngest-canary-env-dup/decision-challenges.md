# Decision Challenges — feat-one-shot-inngest-canary-env-dup

The owner's brief reserved every technical fork to `soleur:engineering:cto`. One batched consult was run at plan time
(2026-10-22, the CTO was told not to ask the operator anything). All rows are ruled, none are pending. `soleur:ship`
renders this table into the PR body. The only operator-only item in this work is the authorization to merge, which the
brief already reserves ("a typed go naming the merge"); it is not a technical question and is not a row here.

## Decision Classes

| Item | Class | Ruling |
|------|-------|--------|
| Fix shape for the duplicated `INNGEST_BASE_URL` / `NODE_EXTRA_CA_CERTS` entries in the canary's `Config.Env`: (A) scrub both names from the env-file copy before the docker runs and keep the check strict, vs (B) relax the check to last-wins semantics | technical | Ruled by CTO agent, 2026-10-22: (A), scrub unconditionally (http and https) after the resolver succeeds, leave every other key byte-identical, keep the inspect check strict - the check proves what the container was handed, so it must not lean on the daemon's merge order; scrubbing fixes the cause, (B) weakens the proof, and dropping the `-e` flags in favour of the file would take the pinned values from an untrusted snapshot |
| Where the scrub lives and how it fails | technical | Ruled by CTO agent, 2026-10-22: its own function inside the `inngest-link-resolver` markers, called at the deploy site right after the resolver and before `PROD_NODE_OPTIONS=`; atomic rewrite via `mktemp "$1.XXXXXX"` then `mv -f`, reusing `_gak_tmp` so the existing EXIT trap covers the temp file and no trap edit (and no conflict with #10697) is needed; read the `grep -v` rc the way the overlay does (1 = every line matched, fine; 2+ = read error); post-scrub recount with the same regex must be 0; any failure aborts the deploy keeping the previous version with the fixed literal reason `inngest_env_scrub_failed` and an `INNGEST_LINK: class=env_scrub_failed level=error stage=<read\|write\|recount>` event - a fixed literal because `final_write_state` splices the reason into JSON unquoted |
| Diagnostics grammar for the inspect check | technical | Ruled by CTO agent, 2026-10-22: `check=inspect cause=<inspect_failed\|url_count\|url_value\|ca_count\|ca_value> url_lines=<n> url_https=<n> ca_lines=<n> ca_ok=<n>`, first failing condition in that order; the `docker inspect` return code is captured separately from its output (today `\|\| envs=""` makes a failure look like a wrong count); integers are normalized with `$((10#${n:-0}))` and clamped to 99; no env value, key or raw text ever enters the event; a test asserts `check=inspect` never reports `cause=none` again |
| Scope boundaries: first-boot path (`soleur-host-bootstrap.sh`, cloud-init) and `docker-run-tuple.py` | technical | Ruled by CTO agent, 2026-10-22: leave both unchanged - the first boot has no inspect check and Docker's last-wins makes its duplicate harmless (the next deploy replaces it), accepted residual; the tuple census parses ARGV only and lists the env-file content as a stated residual, so an in-place rewrite changes nothing it sees; run its tests, do not edit it |
| Test plan shape | technical | Ruled by CTO agent, 2026-10-22: make the `MOCK_IL_CANARY` inspect mock env-file-aware; prove the new rows RED on unmodified code (`cause=url_count url_lines=2`) and GREEN after, canary and prod each with exactly one https URL in effect; add a strictness row (a real duplicate still fails with the scrub in place) and a `kill_mut` for the scrub; resolver-suite unit rows for the scrub (other keys byte-identical incl. `INNGEST_LINK_TLS`, `INNGEST_TLS_CA` and the signing and event keys; bare-name and whitespace-padded lines removed; no-match is a no-op and idempotent; mode preserved; `stage=read` / `stage=write` / `stage=recount`); a `NODE_EXTRA_CA_CERTS` row fed straight to the scrub plus the deploy-level `env_hijack` abort; a wiring row for call order; one E-row per cause with an exact event-line assertion; one local-only real-Docker confirmation recorded in the PR description |
| Synchronous deploy-state reason for a failed canary inspect (observability layer 6, the run log), vs a single constant for every Inngest canary check | technical | Ruled by CTO agent, 2026-10-22: (B) for `check=inspect` only set `CANARY_FAIL_REASON=canary_inngest_link_inspect_failed`, every other in-container check keeps `canary_inngest_link_failed` - the inspect failure is usually a deploy-composition defect (the container was handed the wrong env; `cause=inspect_failed` is the daemon call itself failing) and the others are network, CA or registry defects, so the run log alone separates them without a Better Stack read; the reason is picked from a literal per branch and is never built from `$why` or `$cause` (container output must not reach the deploy state, and `final_write_state` splices it into JSON unquoted); (A) rejected because the failure that just burned a flip would stay async-only, (C) rejected as taxonomy churn with no differing operator action; both suites and both runbooks list the split, and the old literal is re-grepped before editing |
| Scrub failure scope, host-state footprint and grep robustness (raised by plan review: a persistent scrub fault would block the rollback path; non-UTF-8 and NUL bytes make grep lose lines silently) | technical | Ruled by CTO agent, 2026-10-22: abort a scrub failure only when `INNGEST_LINK_CA_STRICT=1`, emit `env_scrub_failed` and continue when 0, safe only because every failure path leaves the env-file byte-identical (a persistent scrub fault must never block `action=off`, a revert or any flag-off deploy (with the flag on it blocks like a resolver fault; amended in review round 2)) - the scrub stays after the resolver, the strict-abort footprint (CA file installed, scheme uncommitted) equals a canary failure after install and is accepted, with a row asserting no container started and last-scheme unwritten; every grep in the scrub runs `LC_ALL=C grep -a`, plus a conservation check (kept plus removed equals total, else `stage=write`), contract "kept lines byte-exact, final newline guaranteed"; keep the recount but run it on the temp file before the `mv` together with the conservation check, because conservation proves nothing was lost and the recount proves the target lines are gone; the overlay's own `grep` weakness is filed as #10855, not widened into this PR |
| Scrub regex breadth and web-2 delivery mitigation (raised by the deepen-pass security review: Docker trims Unicode whitespace and a BOM while the ASCII-only regex does not, and the recount shares the regex; web-2 gets ci-deploy.sh by an in-place file write) | technical | Ruled by CTO agent, 2026-10-22: use `^[^A-Za-z0-9_]*(INNGEST_BASE_URL\|NODE_EXTRA_CA_CERTS)([^A-Za-z0-9_]\|$)` under `LC_ALL=C grep -a` for the scrub, the conservation check and the recount alike - a broader prefix fails safe, lookalikes keep their lines and a comment line naming the variable is harmlessly dropped; amended in review round 1: the trailing class is `([^A-Za-z0-9_.-]\|$)` so `.bak` and `-X` lookalikes, which Docker reads as other variables (measured), keep their lines; the Docker parser behavior was then reasoned and is now measured (`docker-evidence.md`: NBSP and BOM prefixes are accepted as the plain name, a padded name is refused), so the Phase 4 local Docker record was required and the L1 NBSP, BOM and CR rows stay even if Docker does not strip them; the overlay's identical weakness stays out of this PR (#10855, linked from the PR body); the web-2 in-place write (#10856) is accepted with a read-only idle check before the owner's merge go plus PR-body disclosure, and no production write happens in this pipeline |
| ADR treatment | technical | Ruled by CTO agent, 2026-10-22: amend ADR-294 with an addendum (the `-e` flags are the only source of the pinned variables; the env-file is scrubbed of them after resolution) in this PR, not a follow-up issue |
