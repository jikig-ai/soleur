# Decision challenges — kb-archive-gate

Decisions taken during `plan`/`work` that needed a ruling or went against a
recommendation. Recorded per ADR-084 so `ship` renders them into the PR body.
This planning session ran inside a Task subagent without the Agent/Task tool,
so technical rulings went to a batched `soleur:engineering:cto` spawn after the
plan phase (2026-10-12), per the technical-ruling-delegation contract.

## Decision Classes

| Item | Class | Ruling |
|---|---|---|
| Gate `gh pr ready` in addition to `gh pr merge`? | technical | Ruled by CTO agent, 2026-10-12: `gh pr merge` only - `gh pr ready` marks review-readiness, not publication; the leak event is the merge landing live paths on `main`. Live artifacts during review are legitimate working state (`worktree-manager.sh draft-pr` produces WIP drafts that iterate at live paths); three sibling ready-gating hooks gate ready on PR-metadata properties, not tree state. Under the restructured flow (Phase 6.45 before Phase 6.5 ready+arm) a ready-deny adds zero coverage on the sanctioned path and creates false denies on draft-for-review flows; a ready-then-UI-merge bypass is covered by postmerge Phase 5.8 regardless. Binding nuance: the trigger regex must NOT absorb the sibling's `ready` alternation — keep `gh pr merge` alone. |
| Deny on `M` (modified) rows at live KB paths, or `A` (added) rows only? | technical | Ruled by CTO agent, 2026-10-12: deny on both `A` and `M` (`--diff-filter=AM`) - the brief's literal "adds or modifies". An `M` row means the artifact is live at the PR head and this PR touched it without archiving it; remediation is the same archive. `archive-kb.sh` itself treats `M` rows on plans/brainstorms as that feature's artifacts, so hook and remediation tool agree for files. The accepted false-positive surface (a drive-by edit forcing whole-dir archival of a backlog dir) shrinks the measured backlog. Binding amendment: `archive-kb.sh` deliberately refuses to collapse `M`-row spec dirs (a drive-by edit to a sibling's live spec is not ours to archive), so for an `M`-on-`specs/` deny the scripted remediation prints `No artifacts found` and the deny persists — the deny reason must name the manual path (`git mv` the spec dir under `specs/archive/<ts>-<dir>`, commit, push) or the env hatch, not only `archive-kb.sh`. |
| Fail-open scope for `main`/detached/bare? | technical | Ruled by CTO agent, 2026-10-12: the brief's fail-open applies to the HEAD-based path only - `main`/detached/bare are states where HEAD is not the merge's measured object; a numbered `gh pr merge <N>` or `--match-head-commit <sha>` resolves a pushed object and is always verifiable, so it gates on every checkout state (this is what keeps `soleur:schedule`'s main-checkout merges and drain sessions covered). Blanket fail-open on main/detached/bare rejected: it would disarm the gate in exactly the sessions that merge other PRs. Binding nuance: the early check must be `git rev-parse --git-dir`, NOT `--is-inside-work-tree` — a bare repo must still reach the numbered-resolution path; only the HEAD path requires branch-state checks. |
| Unresolvable merge target (mixed numbers, non-bare arg, foreign cd, unprovable repo pointer) — HEAD fallback or deny? | technical | Ruled by CTO agent, 2026-10-12: deny carrying `MERGE_TARGET_WHY` - the sibling's HEAD fallback is right for a review-evidence gate grading the session branch; for an artifact census, checking HEAD when the merge targets a different PR is simultaneously a false-pass and a false-deny. Proven-foreign `-R`/env pointers exit 0 — not our repo. Binding nuance: the deny applies to invocations that carry a target token the ladder cannot prove; a purely flag-only invocation (`gh pr merge --squash --auto`, no positional) has no named target and correctly takes the HEAD path. Flag-first-with-number (`gh pr merge --squash 42`) staying in the conservative deny is acceptable; the deny text tells the user to reorder. |
| PR-head resolution mechanism? | technical | Ruled by CTO agent, 2026-10-12: verbatim byte-copy of `pre-merge-rebase.sh`'s #8778/#9401 resolver helpers (`_merge_args`, `--help` pass-through, `_repo_url_parts`, `_repo_flag_operands`, `_repo_env_operands`, `_repo_pointers_same_repo`, `_strip_repo_flags`, `MERGE_TARGET_WHY` ladder, in-command-`cd` scan, `timeout`→`gtimeout`→bare wrapper, `^[0-9a-f]{40}$` validation), parity-pinned by a suite row that diffs each function BODY against the source - a presence grep is insufficient; the copied functions are the ones that run. `refs/pull/<N>/head` fetch resolves the head sha with no `gh` dependency; `--match-head-commit <sha>` takes precedence when present (the admin hatch emits that form). Rejected: shared-lib extraction (forces an edit to a live production gate for ~zero net code) and hand-rolled HEAD-only check (reintroduces the #8778 false-pass/false-deny pair). |
| Trigger regex boundary set? | technical | Ruled by CTO agent, 2026-10-12: widen the sibling's start/chain-operator-only boundary per `pre-merge-rebase.sh` and `prod-write-defer-gate.sh` precedents - boundary `(^ or && or double-pipe or pipe or ; or ( or whitespace-dash-dash-whitespace)` plus a repeated invocation-prefix clause (assignments, `if`, `while`, `until`, `then`, `do`, `elif`, `else`, `!`, `time`, `env`, `command`, `builtin`, `exec`, `nohup`, `sudo`). The `with_lock merge-main 600 -- gh pr merge` form is the sanctioned arming form `ship` emits; the sibling boundary verifiably misses it (#3689 class). Binding nuance: the dash-dash member must appear in BOTH the fire-check regex and `_merge_args`' extraction regex. Documented residual, shared with all siblings: `gh pr merge` inside a quoted `bash -c '…'` payload is blanked by `strip_command_bodies` and does not fire; postmerge Phase 5.8 is the net. |
| Fetch/verify failure (origin unreachable, pull ref missing) — fail open or closed? | technical | Ruled by CTO agent, 2026-10-12: fail-closed deny - sibling parity (the unpushed-commits gate fails closed on fetch failure: "the bug this gate exists to prevent IS the silent-miss class"). An unverifiable head is precisely the invisible failure this feature was commissioned to end; "unplug the network" must not become a universal bypass. The deny names the failed fetch and the manual retry; the env hatch is the escape for a genuinely wedged network. |
| Unresolvable merge-base (shallow clone) — fail open or closed? | technical | Ruled by CTO agent, 2026-10-12: fail open, but NOT silently - emit one `headless_or_stderr` warn line naming the cause, matching the sibling convention that no fail-open path is silent. Once the fetch has succeeded (fetch failure denies per the previous row), an unresolvable `git merge-base` is the shallow-clone class — git genuinely cannot compare, and denying every merge from a shallow checkout would wedge drain/schedule sessions. `archive-kb.sh` already degrades to slug-only on the same condition, so the exposure predates the hook and is not widened by it. Amends the planner's "fail-open silently". |
| Env escape hatch? | technical | Ruled by CTO agent, 2026-10-12: `SOLEUR_SKIP_KB_ARCHIVE_GATE=1` pass-through before all other checks - four shipped precedents use the same contract (`SOLEUR_SKIP_OPERATOR_STEP_GATE`, `SOLEUR_SKIP_NET_ISSUE_FLOW_GATE`, `SOLEUR_SKIP_RUNBOOK_SSH_GATE`, `SOLEUR_SKIP_SOAK_FOLLOWTHROUGH_GATE`). Deliberate one-keystroke repair for a wedged gate; not a hole — the deny remains the default. Binding nuance: the deny message must name the hatch explicitly, as `ship-operator-step-gate.sh` does — an undocumented hatch is discoverable only by reading the hook. |
| New corpus rule id for the gate? | technical | Ruled by CTO agent, 2026-10-12: `wg-kb-artifacts-archived-in-pr` as a Workflow-Gates-tier entry in `AGENTS.rules.md` + the `AGENTS.md` pointer index - verified independently: rule-budget `B_ALWAYS=43435` vs the 46000 cap (~2565 B headroom, fits ~60 B pointer + ≤600 B body); id unique repo-wide; tier placement per `cq-agents-md-tier-gate` (the violation can only occur in the ship pipeline → `wg-`). In-corpus precedent `wg-ship-push-before-merge` carries the "hook covers Claude Code Bash only; non-hooked contexts MUST run the equivalent check" clause — the new rule copies that shape. The hook emits this rule id via `emit_incident`; the named phase echoes `SOLEUR_RULE_APPLIED`. |
| Named-phase number and placement in `ship/SKILL.md`? | technical | Ruled by CTO agent, 2026-10-12: `## Phase 6.45: KB Artifact Archival` between the "If no open PR exists" `gh pr create` block and `### Semver Label and Changelog`, so BOTH arms converge through it before any `gh pr ready`/`gh pr merge` - step 5.5's body moves verbatim; the exists-arm's `gh pr ready` + `wait-ready-run` steps consolidate into Phase 6.5's `### CI Status Check` as the single initial-arming site. Rejected: in-place `###` promotion inside the exists-arm keeps the conditional-wrap and two arming sites — the root cause. Binding nuance: Phase 7's CI-failure recovery retains a `gh pr merge <number> --squash --auto` re-queue — a second merge site by construction, but post-archive and still covered by the hook; the invariant is "no merge site before Phase 6.45", not "one site total". Do not remove the Phase 7 re-queue in this PR. |
| archive-kb.sh discovery — is a fix needed for #7383? | technical | Ruled by CTO agent, 2026-10-12: no fix needed for the #7383 covered surface; the in-scope residual is the untracked-file gap - the #9803 branch-diff discovery already covers topic-named plans (`--diff-filter=AM` commit provenance) and `feat-one-shot-*`/non-`feat-*` spec dirs (A-row collapse); measured 2026-10-12 on `feat-one-shot-9969-edge-roots` (topic-named plan + spec dir both listed by `--dry-run`). The residual is real: `git diff` sees only committed state, so an uncommitted topic-named plan or uncommitted non-`feat-*` spec dir is invisible to both axes. Extend `discover_branch_diff` (or add a sibling `discover_untracked`) to `git status --porcelain` `??` rows under the three roots, same `*/archive/*` exclusion and spec-dir collapse; `git add` before `git mv` already handles untracked files on the move side, so the fix is discovery-only. Scope to `??` rows only and keep the spec-dir collapse symmetric — an untracked dir under `specs/` collapses to the dir; a lone untracked root-level file does not fire. Merge-base unresolvable degrading to slug-only matches the Item-8 exposure — noted, not widened. |
| Sibling hooks' dash-dash gap (`ship-unpushed-commits-gate.sh`, `cla-signed-author-gate.sh`)? | technical | Ruled by CTO agent, 2026-10-12: defer the sibling fix out of this PR - verified real (`ship-unpushed-commits-gate.sh` and `cla-signed-author-gate.sh` both use start/chain-operator-only boundaries, so the sanctioned `with_lock merge-main 600 -- gh pr merge` arming form bypasses both on the main path; `pre-merge-rebase.sh` fixed the same class in #3689). A two-line-each fix in a different concern would widen this diff past the leak-gate scope. Binding amendment: at ship time run the `wg-defer-only-after-inline-triage` triple test before filing; if it passes, file the `type/chore` tracking issue; if not, the deferral lands as durable in-place documentation (plan Non-Goals + a comment at each sibling's trigger line naming the gap), never conversation-only. |
