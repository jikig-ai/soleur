# Decision Classes - feat-one-shot-10924-p4c-monitor-lock

Umbrella #9757, item #10924, slice P4c. Every technical fork below was delegated to the CTO agent per
`plugins/soleur/skills/brainstorm-techniques/references/technical-ruling-delegation.md`; none was put to the operator.

| Item | Class | Ruling |
|---|---|---|
| F1 Contention behaviour: refuse vs take over the holder vs wait vs attach to its output | technical | Ruled by CTO agent, 2026-10-27: REFUSE. The second monitor prints one terminal `DUPLICATE MONITOR` line and exits rc 4 - the holder is already watching, so refusing loses nothing; take-over can kill a healthy watcher, wait queues a zombie, attach is a new feature. The line carries the `kill <pid>` command and the `SOLEUR_MONITOR_LOCK=off` override and no verdict token (`MERGED`, `GREEN`, `CLOSED`). |
| F1b Refusal exit code | technical | Ruled by CTO agent, 2026-10-27: rc 4, distinct from 0/1/2/3 - callers that treat only 0 as success cannot read a refusal as green; `sync-pr-behind.sh` uses 4 for `kind=gh` but that is a separate script. |
| F2 Lock mechanism: symlink vs mkdir+holder-file vs flock(1) | technical | Ruled by CTO agent, 2026-10-27: symlink lock (`ln -s` of the holder record: atomic create plus atomic record, no flock on stock macOS, no mid-write window). No reclaim guard: the stale-reclaim race degrades to a duplicate monitor, today's behaviour, never a false refusal. Conditions: liveness by `ps -p P -o pid=` not `kill -0` (EPERM on another user's process reads as dead); live = pid exists AND not zombie AND `lstart` equals the recorded one; record the script's own `$$`, never `BASHPID`. Release only if `readlink` still equals our value. Planner refinements inside this ruling (mechanical): the record separator is `\|` not `:` because `lstart` contains colons; reclaim is compare-before-remove; `lstart` is read under `TZ=UTC LC_ALL=C` (measured: `ps -o lstart=` follows the caller's TZ). |
| F3 Lock root | technical | Ruled by CTO agent, 2026-10-27: `${XDG_RUNTIME_DIR:-/tmp}/soleur-monitor-locks-$(id -u)`, mode 0700, owned by us and not a symlink; the fallback is the literal `/tmp`, never `$TMPDIR` (a per-session TMPDIR would hide the lock from another session). `SOLEUR_MONITOR_LOCK_DIR` stays as the test seam. A holder in another PID namespace reads as dead and is reclaimed, which degrades to a duplicate monitor. Known residual (CTO devex review): two sessions that resolve different `XDG_RUNTIME_DIR` values never see each other. |
| F4 Fail posture when the lock cannot be established | technical | Ruled by CTO agent, 2026-10-27: fail OPEN with one loud line (`monitor-lock: UNAVAILABLE (<why>) - running without exclusion`); fail CLOSED (rc 4) only on a positive finding that a live process holds the lock. A false refusal leaves a PR unwatched; a duplicate only costs extra `gh` calls. `SOLEUR_MONITOR_LOCK=off` is the escape hatch and also prints a loud line, so a bypass is never silent. |
| F5 Key when `--repo` is absent | technical | Ruled by CTO agent, 2026-10-27: derive `owner/repo` from `git config --get remote.origin.url`, lowercased; with `--repo`, use it lowercased; if neither yields a key, skip the lock fail-open with the loud line. Never key on a bare PR number (two repos share PR numbers; a false refusal is the dangerous direction). |
| F6 Re-scope: script lock vs upgrading the report-only hook to deny | technical | Ruled by CTO agent, 2026-10-27: the script lock is the right P4c. `.claude/hooks/monitor-supersede-guard.sh` stays report-only (denying would depend on the undocumented transcript shape its header says cost a ship run); the lock also covers Codex/Grok/Devin, a second session, and a re-arm by a different command shape. The CTO allowed a pointer comment in the hook; the planner cut it (`harness.ts` prose already links the two layers) - the hook is untouched. |
| F7 Single cleanup path | technical | Ruled by CTO agent, 2026-10-27: line-106 `trap ... EXIT` must not be overwritten; one cleanup function removes `$ERRTMP` and releases the lock. Acquire after argument validation and before the first poll, so usage errors (rc 3) never take the lock and a refusal exits before any `gh` call. Superseded in part by F12: no INT/TERM traps. |
| F8 Lock-age ceiling for a live-but-wedged holder (deadline reclaim) | taste | Decided by the planner (a scope cut, recorded for challenge): CUT. The poll loop is bounded by `--max-polls` (default 60 x 120 s = 2 h; drain-prs 90 x 60 s), a wedged live holder is released by `kill <pid>` (named in the refusal line), and a deadline field would add a clock mechanism that buys a property no incident has shown. Corrected rationale (CTO devex review): the Monitor tool's one-hour cap does NOT bound a `persistent: true` watch, so the real bound is the script's own poll budget. |
| F9 P4c scope vs sibling pollers (`sync-pr-behind.sh` standalone loop, ship Phase 7 poll, `triage-prs.sh`) and the `purpose` dimension | taste | Decided by the planner: only `monitor-pr-checks.sh` adopts the lock in this PR. The `purpose` argument is dropped (DHH and simplicity reviewers: a single adopter, YAGNI); `pr-checks` stays a constant prefix of the lock name so a later adopter is distinguishable without a rename. Not filed as a deferred issue: no second duplicate-monitor incident exists; revisit if one appears. |
| F10 Bounded release-race grace before refusing | technical | Ruled by CTO agent, 2026-10-27: when a live holder is found, retry the acquire up to 2 more times at 1 s spacing before refusing, so "stop the old monitor, then arm the new one" does not false-refuse while the old process is still running its EXIT trap. This is a bounded release-race grace, not wait-for-holder, so F1 stands. `SOLEUR_MONITOR_LOCK_GRACE_S` (default 1) is the test seam. Source: the CTO devex review of the finished plan. |
| F11 Refusal-line wording | technical | Ruled by CTO agent, 2026-10-27: the line branches on ownership - "if this session armed that monitor, read its output; if not (a resumed or other session), stop it with `kill <pid>` and arm this watch once" - and names `SOLEUR_MONITOR_LOCK=off` only as the escape for a misbehaving lock mechanism, so an agent does not take the bypass and recreate duplicate monitors. Source: the CTO devex review of the finished plan. |
| F12 Prompt release on stop: `sleep & wait` plus INT/TERM traps vs only the EXIT trap | taste | Decided by the planner on measurement, accepting the DHH review (mechanical): ONLY the EXIT trap, no TERM or INT trap, and the loop's foreground `sleep` is unchanged. Measured: with no TERM trap bash dies at once on TERM and still runs the EXIT trap (+1 s); installing `trap 'exit 143' TERM` defers the trap to the end of a foreground sleep (+6 s of 6 s). This dissolves `SLEEP_PID`, `sleep & wait` and the unobservable INT test (a backgrounded non-interactive bash ignores SIGINT on entry). |
| F13 Panel cuts of `inferred` items | taste | Decided by the planner after the plan-review panel (simplicity, DHH, Kieran, CTO devex): CUT the `--lock-selfcheck` flag (the discoverability test becomes a one-line `bash -c` over the lib; the runtime UNAVAILABLE line is the real signal), the two CODEOWNERS rows (`* @deruelle` already owns every path), and the hand-run mutation rows with the PR-body proof (all rows are automated or plain assertions). KEPT against the simplicity reviewer: the zombie check (the CTO's F2 condition), `drain-prs/SKILL.md` rc-4 sentence (CTO devex: a re-run drain re-arms every enqueued PR), `harness.ts` lines. Reclaim shrinks to one reclaim plus one retry; exhaustion is rc 2 `contended`. |
| F14 Review amendment to F11 (refusal wording: drop the bypass hint, branch on a live Monitor task, `ps` check before `kill`, "watching for Ns") | technical | Ruled by CTO agent, 2026-10-27: UPHOLD (amend F11) - adopt the amended line as written in `acquire_or_exit`; the bypass hint stays in `--help` and the script header only - an agent should not be offered a bypass that recreates the duplicate polling, and the `ps` check closes the pid-reuse window between print and read. |
| F15 Review amendment to F2 (serialise the stale-reclaim under a `mkdir` guard) | technical | Ruled by CTO agent, 2026-10-27: UPHOLD (amendment) - keep the `<lock>.reclaim` mkdir guard, the stale-guard sweep, never removing an absent link, and the 6-contender x 6-round regression arm; this replaces the earlier "no reclaim guard" ruling - a measured silent double-win (12 of 60 rounds) defeats the lock's purpose, and the earlier ruling rested on an unmeasured assumption. |
| F16 Review amendment to F3 (lock root not writable by group or other) | technical | Ruled by CTO agent, 2026-10-27: UPHOLD - the `find -maxdepth 0 \( -perm -020 -o -perm -002 \)` test in `_ml_dir`; a refused directory fails open with the loud UNAVAILABLE line, which is today's behaviour, so `SOLEUR_MONITOR_LOCK_DIR=/tmp` being refused is correct. |
| F17 Review scope question: other pollers and the hook's blindness to the canonical script command | technical | Ruled by CTO agent, 2026-10-27: UPHOLD F9/F6 - other pollers stay out of scope and the `harness.ts` prose correction stands; extending `monitor_sig` to `monitor-pr-checks.sh <PR>` is a tracked follow-up, not this PR (the lock is the only layer for that command, so this PR already delivers the guarantee; `monitor_sig` belongs to a separate report-only hook with its own tests). |
