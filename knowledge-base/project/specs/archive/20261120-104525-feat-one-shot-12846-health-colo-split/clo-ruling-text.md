## Rulings

1. **Class R: yes, conditionally.** The read stays Class R. It is defined by effect, as the 2026-11-09 ruling holds: a fixed compiled-in query, read-only token, aggregate output. Conditions, in addition to every 2026-11-09 condition, which all still stand:
   - (a) The offset is digits only, with no sign and no leading zero, from 0 to 527. Hours is 1 to 216. Hours plus offset is at most 743. Both are checked before the credential is loaded and before anything is sent. A failed check is refused with nothing sent.
   - (b) Only window stamps the wrapper computes from the clock enter the query. Host `app.soleur.ai`, path `/health`, the dataset, the dimensions and the fields are compiled-in literals.
   - (c) The selection is exactly `datetimeHour` and `coloCode` as dimensions, and `count` plus avg/p50/p90 `originResponseDurationMs`. No `clientIP`, `userAgent`, `clientCountryName`, `clientAsn`, `clientRequestQuery`, `clientRefererHost` or any other client-side dimension.
   - (d) It uses the same POST chokepoint and the same bound token `CF_API_TOKEN_ANALYTICS_READ` with no fallback. The token set stays five.
   - (e) `coloCode` is printed only when it matches three capital ASCII letters. A non-matching value is never printed: print `null` in its place, or report `bad-response`. Either choice is the CTO's. This keeps vendor free text out of the transcript, and the bounded error line stays the one stated departure. Hour stamps are printed only in the `YYYY-MM-DDTHH:00:00Z` shape.
   - (f) Drift check: the first live read of this subcommand is after the merge. A run from the branch copy before merge is not Class R.
2. **GDPR/ePrivacy: not personal data. No suppression for `/health`.** `coloCode` identifies Cloudflare's serving data center, which at most suggests a metro area. It is selected with no IP, UA, country, ASN, query, referrer or per-visitor field. The path is a machine endpoint hit mostly by uptime monitors. A public reader has no reasonably likely means of singling out a natural person from (hour, colo, sampled count), even at counts of 1 to 5 (Art. 4(1) and Recital 26; *Breyer* C-582/14; *EDPS v SRB* C-413/23 P). The controller's own logs are already held, and the committed aggregate adds nothing to them. ePrivacy Art. 5(3) is not engaged, because nothing is stored on or read from terminal equipment. Art. 6 traffic-data rules bind communications providers, not Soleur. Cloudflare is already a disclosed processor (compliance-posture row "Cloudflare Inc", AUTO). There is no new processor, no transfer and no change to the Privacy Policy, DPD or GDPR Policy. Conditions:
   - (i) The determination is scoped to host `app.soleur.ai` and path `/health`. A colo, country or network split on any other path or host re-runs the GDPR gate and starts from a minimum-count suppression of k >= 10 per cell.
   - (ii) The evidence JSON holds the projection only, never a raw response. It is never joined with Sentry, Better Stack or app-log rows.
   - (iii) The evidence file gets a new dated filename. It never overwrites `2026-11-11-analytics-health-216h.json`, `2026-11-11-analytics-edge-errors-216h.json` or any other file a record cites.
   - (iv) Under 1(f), it is generated by a post-merge Class R run.
3. **Zone id: printing is permitted.** The zone id is a resource identifier, not a credential. It grants nothing without a scoped token, and Cloudflare treats it as non-secret. The account id is already public in `apps/web-platform/infra/main.tf` (R2 endpoint). The zone id serves a real evidentiary purpose: it shows which zone the read hit after the #12931 account and zone move. Conditions:
   - It is printed only as the environment value already validated against the 32-hex `ID_RE`, never as a value from the response body.
   - No other environment value is printed. That includes the account id, any token, and `CF_ACCOUNT_ID`.
   - The section 9 text says expressly that this is not a credential print.
   - Committing the full id to the public repo is an owner-review item. The alternative the owner can choose is a short fingerprint.
4. **Text:** sections A to D below.
5. **Owner-review items:** section E below.

The query reads `httpRequestsAdaptiveGroups` filtered to a datetime window, the host `app.soleur.ai` and the path `/health`, grouped by `datetimeHour` and `coloCode`, and selects the count and the average, p50 and p90 of `originResponseDurationMs`; every literal is compiled in, and the new host filter and `coloCode` dimension are the further filter and field that the 2026-11-09 conditions send to re-review. This amends the 2026-11-09 condition that the only caller input is one bounded integer of hours back: this subcommand alone takes a second, a whole number of hours from 0 to 527 by which the window end moves back from the current hour, with the two numbers together at most 743; both are digits only and range-checked before the credential is loaded and before anything is sent, and only stamps the wrapper computes from the clock enter the query. Data protection (CLO ruling of 2026-11-19): `coloCode` names the Cloudflare data center that served a request, an infrastructure dimension and not a visitor attribute; on this fixed host and path, with no IP, user agent, client country, client network, URL query string, referrer or per-visitor field selected, a per-hour, per-colo sampled count is not personal data under Art. 4(1) GDPR, in the wrapper's output or in evidence committed to this public repository, even where a count is small, so no minimum-count suppression is required; ePrivacy Art. 5(3) is not engaged; there is no new processor, no transfer and no compliance-posture entry. That determination covers the host `app.soleur.ai` and path `/health` only: a colo, country or network split on any other path or host re-runs the GDPR gate first and starts from a minimum-count suppression. The projection prints `coloCode` only when it is three capital letters, and it prints the zone id the read used (the validated 32-character hex value from the environment, a resource identifier and not a credential, never a value from the response) and no other value from the environment. This is not a delegation, adds no Gate kind and discharges no hold; a read stays evidence and never a precondition. `status: adopting` is unchanged and there is no C4 change. The CLO's 2026-11-09 conditions for a POST read to stay Class R otherwise stand unchanged, including that any further field, filter or dataset needs a new CTO ruling and CLO re-review.

## E. Owner-review items for the draft PR (six)
