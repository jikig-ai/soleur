# Decision challenges: feat-one-shot-p5-mint-sink-page-request

Rulings for the p5-mint.js sink hand-off through `page.request` (Ref #12931). The CTO agent ruled each item. None
of them went to the operator (`hr-technical-fork-is-not-an-operator-question`). Earlier rulings on the token POST
are N1-N5 in `knowledge-base/project/specs/archive/20261128-170705-feat-one-shot-p5-mint-node-post/decision-challenges.md`.

**Defect (measured 2026-11-28).** The mint step 5 hand-off called a bare Node-side `fetch`. The
`browser_run_code_unsafe` vm context of @playwright/mcp 0.0.78 holds only `page`, `__end__` and the compiled `__fn__` (playwright-core
coreBundle.js `runCode`; V8 supplies its own `console`, and no host global such as `fetch` is copied in), so the call threw `ReferenceError`. The cleanup then deleted a good token, the mint
returned `{refused:"sink"}`, and p5-sink.py never got a request.

| # | Question | Ruling |
|---|---|---|
| S1 | Does `page.request.post` carry the value to the 127.0.0.1 sink? | Ruled by CTO agent, 2026-11-28: yes. Must-haves (all in the body): `maxRedirects: 0`, `failOnStatusCode: false`, `timeout: 15000`; no Origin header; success only on status 200 with `text()` exactly `ok` (the answer carries no secret); `dispose()` in a `finally`; `secret = null` before the check; any throw goes to `failAfterPost('sink')`. New must-have, done in this PR: playwright-mcp-redact-proxy.py refuses every proxy setting at start: `--proxy-server`, `--proxy-bypass`, their `PLAYWRIGHT_MCP_*` env twins, and config `browser.contextOptions.proxy`, `browser.launchOptions.proxy` and `browser.contextOptions.extraHTTPHeaders`, plus config `browser.contextOptions.recordHar`. A HAR would record the hand-off body. It is the HAR sink that 0.0.78 still exposes, since that version has no `--save-har` flag. The hand-off is plain http, and playwright-core skips a proxy only for an explicit bypass list with no loopback default (coreBundle.js `createProxyAgent`/`shouldBypassProxy`), so a proxy would read the value. Rejected: going back to `fetch` (absent from the run context); calling the sink from inside the page (the sink refuses an Origin header). |
| S1-correction | What does `maxRedirects: 0` do? | Ruled by CTO agent, 2026-11-28: playwright-core turns 0 into -1 (coreBundle.js), so a 3xx comes back unfollowed as an ordinary response and does not throw. The result is still `refused:"sink"`. The harness now emulates this: M9c returns the 307 unfollowed and asserts the dispose. |
| S2 | Does p5-sink.py need a change? | Ruled by CTO agent, 2026-11-28: no. page.request sets Content-Length from the body bytes and sends user-agent, accept and accept-encoding but no Origin. Retries default to 0, so the one-shot holds, and the URL is used verbatim. The sink does not check content-type. Integration row I1 runs the real p5-sink.py through the emulated page.request and writes the value byte-exact. Rejected: adding content-type or user-agent checks (brittle, no added protection). |
| S3 | Required tests and mutants | Ruled by CTO agent, 2026-11-28: (a) the harness returns the 3xx unfollowed, and M9c asserts `refused:"sink"`, the dispose and an untouched second listener; (b) the 403 and "nope" sink rows assert the dispose; (c) XM19 (sink `timeout: 15000` dropped) is killed by M1; (d) redact-proxy FR5 cases for each proxy setting above. All four are in this PR, with N1 (a trap `fetch` on the run context is never called), XM17 (sink back on a bare `fetch` -> N1) and XM18 (sink answer not disposed -> M1). |
| R1 | Node runtime env inherited by the server child (`NODE_OPTIONS` `--require`/`--import`/`--inspect`/`--heapsnapshot-signal`, `NODE_EXTRA_CA_CERTS`, `NODE_TLS_REJECT_UNAUTHORIZED`) | Ruled by CTO agent, 2026-11-28: refuse at start, for every Playwright skill. Added to `SINK_ENV_ONLY` with one FR5 case each. Rejected: a silent scrub (it hides the refusal), an allowlist (more upkeep and no added protection), and a Phase-5-only refusal (the risk is the same for every skill). |
| R2 | State left by an earlier `browser_run_code_unsafe` call on the shared `page` (a running trace, or a patched `page.request.post`) | Ruled by CTO agent, 2026-11-28: both controls, with the restart as the primary one. Runbook: restart Claude Code (a fresh MCP server and browser) before the sitting, and allow no other run_code call during it. Body: `tracing.stop()` before any request, then refuse `tampered`. **Correction, measured:** the ruled `Object.hasOwn(page, 'request')` check would refuse every mint, because playwright-core 0.0.78 assigns `page.request` in the Page constructor (coreBundle.js:60639). The body therefore checks `page.request === page.context().request` and that the request object has no own `post`/`delete`. A patched prototype stays invisible from inside the body, which is why the restart is the primary control. Pinned by T1-T3, XM21 and XM22. |
| R3 | Sink substitution: a local process that rebound the port could answer 200 `ok` | Ruled by CTO agent, 2026-11-28: the sink must prove itself. p5-sink.py draws a fresh 32-character answer and answers with it, and p5-mint.js requires an exact match or deletes the token. **Mechanism:** the answer travels as the `sink_url` fragment (`…/<nonce>#<answer>`), not as a new argument. The archived plan's holds must match the runbook's byte for byte except for the sha, and that plan is never edited (CTO F5). Every hold already passes `<sink>` verbatim. A fragment is never sent on the wire, and the body strips it before the POST. Pinned by M9d and XM20. Rejected: a nonce-derived answer (a fake sink receives the nonce in the path). |
| U1 | The user-impact seat (P1, P2): the R1 `NODE_EXTRA_CA_CERTS`/`NODE_OPTIONS` and S1 proxy refusals lock out every host that browses through a corporate proxy or an extra CA, not only the Phase 5 sitting | Ruled by CTO agent, 2026-11-28: amend. The refusals stay on by default. A proxy flag before `--`, `--allow-proxy-and-node-env`, turns off exactly the 3 `NODE_*` rows of `SINK_ENV_ONLY`, the 2 proxy rows of `SINK_FLAGS` (argv and env) and the config `proxy` key under both scopes; every other refusal stays. `plugins/soleur/.mcp.json` passes it (Guard 3 pins the argv, Guard 3 mutant 8 kills its removal). The repo `.mcp.json` does not (its Guard-2 pin is unchanged), and the runbook's "Before the sitting" check now requires that `claude mcp get playwright` shows no such flag. Tests: refused without the flag (the FR5 rows), allowed with it (U1 rows for each env var, argv flag and config scope), the other refusals still fire with it (`--storage-state`, `PLAYWRIGHT_MCP_USER_DATA_DIR`, `launchOptions.recordHar`, `DEBUG_FILE`), the flag given twice refuses; mutants 87-89. Rejected: dropping the refusals (the sitting would lose them), and a per-variable opt-out (more surface, same protection). |
| U2 | The user-impact seat (P3): a refusal names the setting but no remedy | Ruled by CTO agent, 2026-11-28: amend. Each startup refusal on a setting ends with a `To fix:` remedy. The proxy and `NODE_*` rows say: unset the variable (or remove the flag or key) before the Cloudflare re-mint sitting; for normal browsing use the plugin `playwright` server, which allows it. Every other refusal says to remove the flag or key from the server args or the `--config` file, to unset its env var, or (`.ini`, NaN) to rewrite the config as JSON. Pinned by the U2 rows. Usage and install refusals (a bad proxy flag, a missing redactor) keep their text: their reason is already the remedy. |
| U3 | The coordinator (2026-11-28): the sitting is pinned to the repo registration, which cannot start on a host with no Google Chrome (measured: `mcp__playwright__browser_navigate` failed with "Chromium distribution 'chrome' is not found at /opt/google/chrome/chrome"); the repo registration had no `--chromium-fallback`, so merging as written blocked the sitting | Ruled by CTO agent, 2026-11-28: (A). Add `--chromium-fallback` before `--` in the repo `.mcp.json` launch string; the strict refusals and U1 stay. With Chrome present the flag appends nothing; without it the proxy appends `--browser chromium --sandbox` (sandbox on; `--no-sandbox` and `chromiumSandbox:false` stay refused). Pinned by redact-proxy Guard 2 property `fallback-once` (Chrome paths forced absent) and mutant 11, and by lifetime `reg_ok` project kind (one fallback before ` -- `, no opt-out) with Guard 3 mutants 6-7. Runbook: the args must show `--chromium-fallback` and not the opt-out; a `.mcp.json` change needs a full Claude Code restart; the repo server's browser profile differs from the plugin server's, so the operator signs in again; on a sandbox failure stop and install Chrome, never `--no-sandbox`, never switch servers. Rejected: (B) a second strict registration (drift, a third tool prefix to forbid); (C) the plugin server plus a one-time env/args check (weaker than a start-time refusal; reverses U1). |
