## Parked follow-ups (comment on #8211, not new issues)

- `git-data-container-probe.sh` treats ANY `remote: git-data transport:` answer as `ok`, so a wrapper refusal of the `repo path does not resolve` kind would also read as a pass if the probe ever dialed a non-resolving path. The probe already dials the absolute form, so it did not mask this defect, but the acceptance set is wider than "the path resolved". Candidate: accept only `repo does not exist (provision it first)` for the absent-repo dial.
- The positive no-SSH refs read for R3/R6 (see the table).

After this fix the symlink is no longer on the app's path; the bootstrap comment is stale but cannot be edited without a user_data change (host replacement). Fold into the next deliberate host replace.
