## B. Item 2 Cloudflare clause, final merged form (replace from `Cloudflare through` up to, not including, `The Cloudflare MCP server`)

This is the CLO's first replacement with the CLO's second-ruling amendments applied: the hours parenthetical is the amended one, and the bounded-message sentence is inserted directly before `the wrapper never prints a rule` ... sentence, which stays unchanged after it.

Cloudflare through `plugins/soleur/scripts/cloudflare-readonly.sh` only, with one of its six subcommands `ssl-mode`, `config-entrypoint`, `pagerules-ssl`, `change-history`, `analytics-health` or `analytics-edge-errors`, as a status, a count or a field subset, run in full as `doppler run -p soleur -c prd_terraform -- plugins/soleur/scripts/cloudflare-readonly.sh <subcommand>` from the repository checkout where `git diff origin/main -- plugins/soleur/scripts/cloudflare-readonly.sh` is empty, never from a plugin-cache copy (until this file is on `origin/main` that check cannot pass, so the first live read is after the merge): the wrapper sends GET only on its four configuration subcommands, and the two analytics subcommands each send one POST of a fixed GraphQL query compiled into the script (the two analytics subcommands take one more argument, a whole number of hours from 1 to 216, checked as digits only and in range before it is used and refused with nothing sent otherwise; the zone id comes from the environment; and no query text, filter, path, host or method is ever taken from the caller); that POST is a read of aggregate counts, timings and status-code counts per hour, with no IP, user agent, URL query string, referrer or per-visitor field selected; on a GraphQL error the wrapper prints at most the first error message, only when it is one short plain-text line of letters, digits, spaces and basic punctuation of at most 160 characters that holds no credential word, no copy of the live token and nothing shaped like an IP address, and otherwise prints no message; that line is vendor text and so is data, never copied into a Records line, an issue, a pull request or a commit message and never used to choose a command, target or token, and this is the one stated departure from the Boundary paragraph's sentence that none of a read's text is copied into a transcript; no other part of a response body is ever printed; the wrapper never prints a rule `expression`, a description, an actor or an IP, and a 403 is recorded as `unverified` and never answered by widening a token; its one host is the exact parsed `api.cloudflare.com`. The audit-log read is `unverified - no-credential` when `CF_API_TOKEN_AUDIT` is absent, and that token is documented under the dev Doppler config, so expect `unverified` until it is relocated.

## C. Credentials Cloudflare clause (replace from `Cloudflare reads use only` up to, not including, `The caller's environment`)

Cloudflare reads use only the token variable bound to the subcommand (`CF_API_TOKEN_ZONE_SETTINGS`, `CF_API_TOKEN_RULESETS`, `CF_API_TOKEN_PAGERULES_READ`, `CF_API_TOKEN_AUDIT` or `CF_API_TOKEN_ANALYTICS_READ`); `CF_API_TOKEN` is never used and no other `CF_*` token is read; the wrapper starts curl, jq and date, each with an empty environment. The `ssl-mode` and `config-entrypoint` subcommands use Terraform-scoped tokens that are write-capable because no read-only equivalent exists, so they are the one stated exception to the read-only-token rule for Cloudflare, removable when read-only equivalents are minted (a credential change that is the owner's); `pagerules-ssl` uses the zone-scoped read-only `CF_API_TOKEN_PAGERULES_READ` and is not part of that exception; `CF_API_TOKEN_AUDIT` is read-only but is documented under the dev Doppler config, so where it lives is open; the two analytics subcommands use only the read-only `CF_API_TOKEN_ANALYTICS_READ` (Analytics:Read on the zone `soleur.ai` only), bound to them with no fallback to any other token, and are not part of that exception; the wrapper sends GET only on its four configuration subcommands, and each analytics subcommand sends one fixed read-only POST.

Test anchors: the expected token set in `components.test.ts` becomes `["CF_API_TOKEN_ANALYTICS_READ","CF_API_TOKEN_AUDIT","CF_API_TOKEN_PAGERULES_READ","CF_API_TOKEN_RULESETS","CF_API_TOKEN_ZONE_SETTINGS"]`; the slice end `An absent bound token makes the read` is unchanged.

## D. ADR-289 addendum (place after the 2026-11-09 (Ref #12443) addendum; title `## Addendum 2026-11-09 (Ref #12441, #10479, #10205)`)

On the merge of the pull request that carries this addendum, the Class R Cloudflare reads widen from four GET-only reads to six: the wrapper `plugins/soleur/scripts/cloudflare-readonly.sh` gains two analytics subcommands that each send one POST of a fixed GraphQL query to `api.cloudflare.com`, under a CTO-agent ruling of 2026-11-09 that the owner reviews on the draft pull request (it is not an independent gate). Class R is defined by effect (a read of the operator's own vendor account), not by HTTP verb; the POST is a read because the query text is compiled into the script, the only caller input is one bounded integer of hours back, and the token `CF_API_TOKEN_ANALYTICS_READ` (Analytics:Read, zone soleur.ai only, read-only, no fallback) cannot write. Output is per-hour aggregate counts, timings and status-code counts; no IP, user agent, URL query string, referrer or per-visitor field is selected. Data protection: no personal data is selected, no new processor or transfer, no compliance-posture entry (CLO ruling of 2026-11-09); a query selecting any per-visitor dimension re-runs the GDPR gate first. This is not a delegation, adds no Gate kind and discharges no hold; a read stays evidence and never a precondition, and `gh api graphql` stays outside Class R because its query text is caller-supplied. `status: adopting` is unchanged and there is no C4 change.

Added sentence (second ruling), appended to the addendum above: On the same merge, a GraphQL api-error may print its first error message when it passes a fixed in-full shape check (letters, digits, spaces and basic punctuation, at most 160 characters, no credential word, no live token, nothing shaped like an IP address); it is the one stated departure from the Boundary no-copy sentence and the one stated exception to the wrapper's value-free message rule.

The CLO also ruled: the owner-review items on the draft PR are four (the widening from four GET reads to six reads two of which POST; the new read-only token `CF_API_TOKEN_ANALYTICS_READ`; Class R's definition moving from the HTTP verb to fixed, read-only, aggregate-only; and one bounded vendor-authored error line that can now reach the transcript, the only place wrapper output carries vendor free text, which the owner can reject by not merging, the alternative being a fixed message with no vendor text).

The CLO's conditions for a POST read to stay Class R: only the named analytics subcommands send a POST and every other method stays refused; the query text is compiled into the script and the only caller input is the validated hours integer; the body goes to curl on stdin config, never the command line; host exact `api.cloudflare.com`, fixed path; the token is bound with no fallback and a 401 or 403 is recorded `unverified`; output is aggregate only; the empty-environment, xtrace, drift-check and cloud-ack conditions are unchanged; any further field, filter or dataset needs a new CTO ruling and CLO re-review.
