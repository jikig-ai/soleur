# Decision challenges: S7b plan (tracker #9217)

1. **The join population is derived from both sides with no verb list, so it is wider than the brief's "about 29 non-test sites in 20 files".** The brief's figure reproduces under the hand-written verb registry with the series' first recipe (32 sites in 20 files; `j0-derive.py`, first run at this head); with the corrected owner rule and the one-hop sourced-stub arm the same registry funnel reads 39 sites in 22 files. The property is verb-agnostic: a `jq`, `grep` or `timeout` stub that exits without reading is the same hazard, and the registry the series plan named also missed `cryptsetup` (23 lines) and `openssl`. Funnel A finds 60 (test file, verb) pairs in 48 test files. Default taken: the guard derives verb-free and every pair gets a row; stub EDITS follow the reach probe (what actually runs a piped call), so the edit count is expected to stay near the brief's. Reversible: restrict the table to the registry verbs (38 pairs) and record the other 22 as a counted deferral. Class: user-challenge (small; the brief is the default for what gets edited, and it is honoured).
2. **Inline flag-keyed drain in each stub, not a shared stub-drain helper.** The series plan left the choice to this slice. The helper edits the same stubs, adds a sourced path to `#!/bin/sh` heredoc stubs, drains on the verb (masking a mutant that drops the flag, per the 2026-09-30 learning) and needs a suite registration in a fenced file. Class: taste.
3. **The join lives in the existing guard, not a sibling hook suite.** A sibling in `.claude/hooks/` registers for free by glob, but a new registered suite needs a declared affected-edge entry in `scripts/lib/test-affected-paths.sh`, which this slice may not edit. Cost accepted: `SWEEP_PROBE_CHECKS` moves again, and `--affected` will not select the guard when only an owner suite changes (CI's full battery does); the named follow-on slice is on the plan. Class: taste.
4. **Reach probe versus the two alternatives the review offered.** The simplicity seat proposed dropping the probe and draining every non-draining command stub (safe: the drain is flag-keyed, no-op when the flag is absent, and a text-only row can go stale); the DHH seat proposed fixing only the stubs that run. Default taken: keep the probe for the evidence and for choosing edits, and make `exempt` reasons a closed vocabulary (`not-a-command`, `text-only`, `unverified`, `blocked-#N`, `helper-built-stub`, `variable-named-verb`) so stale reasons are greppable. Reversible at Phase 0.3 with no rework: the drain-everywhere variant needs only a longer Phase 2. Class: taste.
5. **Is a permanent guard warranted at all?** The DHH seat: three instances in eleven days, each one red run and a small fix; the dumb version is the J0 measurement, the stub edits with wire asserts, and a learning. Minimal alternative if the operator prefers it: keep Phase 0, Phase 2 and the learning, and keep only the rows for the pairs that RUN (EXEC) with the positional pin, dropping Guard 3. Default taken: keep the full join, because the brief asks for "own plan and Guard Contract" for S7b and the series' stated goal is a guard that owns the producer side. Class: user-challenge.
6. **Dynamic check of each real heredoc stub under a late writer, and a one-case Guard 3.** The correctness seat noted most stubs are standalone heredoc files that could be extracted and run under the control, which would make P2 behavioural; the DHH seat noted Guard 3 exercises only synthetic stubs. Not adopted here: extracted stubs depend on the suite's environment (`$CALLS`, knobs), so the check would need a per-suite harness. Guard 3 kept at one writer shape with a sentinel hand-off and two spelling arrays. Class: taste.
7. **Table shape: a row per pair, not a table of exceptions only.** The devex seat and the DHH seat noted about 60 rows mostly restate what the derivation finds, and every new owner touches one shared file. A row carries the consuming flag token, which no derivation can know without a verb-to-flag registry (the identifier set again); the unlisted-pair message therefore prints a ready-to-paste candidate row. Class: taste.
8. **Funnel B stays in `j0-derive.py`, and the two implementations.** The simplicity seat suggested recording the registry funnel once and deleting it from the script. Kept, because it is what reproduces the brief's figure; the guard's bash derivation is authoritative and the header says so. Class: taste.

Applied at plan review (mechanical, for the record): a positional first-statement pin replaced the region extractor and exit locator; a sentinel hand-off replaced the wall-clock delay; the Phase 2 snippet no longer redirects to `/dev/null.stdin` and uses the repo's `timeout 2 cat` form; spellings carry a shell tag and the pipeline always runs under bash; a one-hop sourced-stub arm and named recall rows were added after the review measured that the derivation missed the `luks-monitor.test.sh` and `cryptsetup` stub and the `ssh` stand-in; the owner rule is a whole-token match; the cut gate in Phase 0.5 was dropped; wall-clock and load conditions left the acceptance criteria.

## Work-time deviations from the plan (recorded when made)

9. **The closed vocabulary gained three words.** `pass-through` (a shim or wrapper that logs and then execs the real binary or the wrapped command, which reads, so a leading drain would steal its input), `deliberate-fault` (a stub that fails on purpose with a status the stub itself decides, the `tr` stub of `ci-deploy.test.sh`) and `arm-drain` (the stub reads stdin before any exit in the arm the producer reaches, keyed on the subcommand rather than the flag, for example the `luksOpen` arm; verified by hand and by the reach probe, not pinned positionally). Measurement found these shapes and none of the six planned words names them truthfully; using `text-only` or `not-a-command` for them would have been a false statement. Each reason stays greppable.
10. **The drain pin is "within the first four code lines of the definition, keyed on the token seen on or before the drain line", not "the first statement".** The repo's own accepted stubs (the harness `cryptsetup` stub, #9245) log first and drain second, and a multi-line `case` puts the flag on one line and the read on the next. A strict first-statement rule would have rewritten stubs that were already safe. It is still positional (no end-of-definition search, no exit locator): `PJ_DRAIN_WINDOW` is the one constant. A drain below the window reads red (control row `producer-join-finder-negative`).
11. **Guard 3 writes more than a pipe buffer instead of using a sentinel hand-off.** The producer writes 1 MiB, so a stub that exits unread fails the pipeline under pipefail whatever the timing, with SIGPIPE ignored (rc 1) and default (rc 141), and a draining stub succeeds. No wall-clock constant and no handshake exists to be wrong. What it gives up: it proves the mechanism at a size beyond the buffer, not at the 3 to 300 byte sizes of the real producers (those race, which is the very flake class; the pin and the evidence cover them).
12. **Wire assert per drained pair (plan phase 2 (b)) was applied only where the stub already captures stdin.** The edited stubs that discard the input (`/dev/null`) have no byte to compare; their existing outcome asserts stay. The captured ones (`registry-luks-escrow`, `sweep-followthroughs`, `operator-digest-provision`, `cron-egress-nftables`, `ci-deploy` docker) keep the capture under the same file name, so their existing assert now reads the hoisted read.
13. **Stubs in suites that run with a restricted PATH use a bare `cat`.** `cron-egress-nftables.test.sh` runs the loader under `env -i PATH="$FX/bin"`, which holds no `timeout`; the first version of the hoist used `timeout 2 cat` and failed 12 assertions at head in the pair run. The stub keeps its original unbounded `$(cat)`.
14. **Eight suites are edited (three under `apps/web-platform/infra/`), not the nine the plan allowed for.** `fresh-boot-ready.test.sh` and `test-git-data-birth-readiness-gate.sh` read as edit candidates and were demoted after reading the producer: the executed pipe in the first runs without pipefail, the second's undrained arm is reached only through a here-string since #9210.
