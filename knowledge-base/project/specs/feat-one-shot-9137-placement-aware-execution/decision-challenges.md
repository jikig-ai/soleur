# Decision challenges: #9137 placement-aware Inngest execution

Technical rulings obtained during `soleur:plan` (2026-11-10). CTO agent spawned headlessly via
`claude --agents <cto.md> --agent cto -p` (no Task/Agent tool in this harness); rulings verified
against the worktree.

## Decision Classes

| Item | Class | Ruling |
|---|---|---|
| T1 mechanism for placement-aware step routing | technical | Ruled by CTO agent, 2026-11-10: Option C — an app-layer fnId-aware forwarder in front of `serve()` in `app/api/inngest/route.ts`; `portable` executes where it lands, `host-affine`/`volume-bound`/unknown/missing-fnId/`forceExecution` calls forward verbatim to the exec host with a loop-guard marker, fail-closed (never run a pinned fn on the wrong host) - `?fnId` is already the routing key the SDK requires (InngestCommHandler.js:902), the live web-2 fan-out makes the cheapest correct fix the right one, and it preserves function ids, EXPECTED_CRON_FUNCTIONS, Sentry slugs, watchdog and deploy-verify unchanged; rejected: (A) per-class app ids (~33-37 id migrations + second registration + consumer churn + still needs a pinned URL), (B) edge fnId steering (drift-prone second copy of the pinned set, paid tier). Dissent: makes web-1 a SPOF for pinned classes — already true today (ADR-119 volume lives only on web-1); record in C4/ADR |
| T2 exec-host identification + pin target | technical | Ruled by CTO agent, 2026-11-10: option (a) — new per-host env `-e SOLEUR_HOST_PRIVATE_IP="$PROXY_BIND"` in ci-deploy.sh prod container (empty for canary), compared exactly to a hardcoded `10.0.1.10` pin constant drift-guarded to `inngest-host.tf:395` `sdk_url` and `network.tf`/`variables.tf` web-1 `private_ip`; equal → execute, different → forward, unset/empty → REFUSE the step call (never execute pinned locally as fallback); a marked request reaching a non-exec host is refused, never re-forwarded - the IP and the pin share one Terraform source and survive web-host-replace; instance-id (`SOLEUR_HOST_ID`) breaks on every replace; always-forward+marker fails when the 8443 publish degrades to loopback. Re-ruled: the first ruling rested on a wrong premise — `SOLEUR_PROXY_BIND` is the literal `0.0.0.0` in the container, ci-deploy.sh:5798. Dissent: a rebooted web-1 with late hot-attached NIC deploys with empty `SOLEUR_HOST_PRIVATE_IP` → pinned fns refused until next deploy — emit a distinct `placement.exec_identity_missing` error + no-SSH runbook step |
| T3 transport for the web-2→web-1 forward | technical | Ruled by CTO agent, 2026-11-10: pinned TLS with the existing session-proxy material (`PROXY_TLS_KEY`/`PROXY_TLS_CERT` via `loadProxyTlsClientCa`, `rejectUnauthorized: true` — NEVER false); receiver bound to the private IP (existing :8443 https server or a sibling listener — implementer's choice, same material + private bind) - forwarded calls carry event data and step state including founder-facing BYOK agent-on-spawn payloads (user data → stricter option is default), and ADR-294's direction for private Inngest links is already TLS; rejected: plaintext :3000 (user payloads in the clear, contradicts ADR-294), origin-tls :443 (CF Origin CA cert cannot validate an IP-addressed dial). Dissent: depends on proxy cert being present/unexpired on both hosts — fail closed + Sentry (proxy-tls.ts already handles missing/unparseable); UNVERIFIED: whether the proxy cert carries IP SANs / identity-check shape — implementer must reuse the existing dial, never a new one |
| T4 scope of this plan | technical | Ruled by CTO agent, 2026-11-10: deliver the primary target only (T1–T3); fallback (a) second SDK worker on the Inngest host stays deferred under #9137's own re-evaluation criteria - its trigger ("a verifier must survive loss of every web host") is unmet: the ADR-248 clock runs on both web hosts and GHA-native schedule covers the rest; the live exposure is fixed by the primary target alone. Non-Goals must restate the fallback's re-evaluation triggers |
| T4a optional web-2 drain to close the exposure window | operator (production-mutating) | Authorize `ga-pool-update mode=drain` (`web2_lb_weight=0`) as an interim risk reduction until the forwarder ships (named by the CTO ruling, split from T1; NOT required by the plan — the fix is the durable close) |
