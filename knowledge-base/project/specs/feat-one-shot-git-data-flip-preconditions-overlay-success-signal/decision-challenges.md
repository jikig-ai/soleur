# Decision Classes — feat-one-shot-git-data-flip-preconditions-overlay-success-signal

Plan: `knowledge-base/project/plans/2026-10-31-feat-git-data-flip-preconditions-overlay-classification-success-signal-plan.md`. References #11704 and #8211 (neither is closed by this PR).

## Decision Classes

| Item | Class | Ruling |
|---|---|---|
| F1 — pause precondition strictness: newest row vs every row in the 2-minute window | technical | Ruled by CTO agent, 2026-10-31: every row per host inside the window must read `new_sessions_paused=1`, and there must be at least one row per host - a single `=0` row means a session could have been admitted; the runbook abort rule already says the same, and a false refusal right after turning the pause on is harmless (retry), so the remedy says to wait 2 minutes after setting the pause. |
| F2 — verdict words for the pause precondition | technical | Ruled by CTO agent, 2026-10-31: two words - `pause_not_on` when a fresh row reads 0, `pause_unread` when no row is under 2 minutes old or the Better Stack read failed - because the operator action differs; `pause_not_on` stays the only word for the 0 case so the issue-text grep still matches; one mutation row per word. |
| F3 — placement and test home of the pause check | technical | Ruled by CTO agent, 2026-10-31: inline in the `flip_preconditions` step, placed last, with executed-step rows and mutation rows in the existing `git-data-cutover-access.test.sh` - a new lib would drag in the shard manifest and other repo-global ratchets for about 15 lines of logic. |
| F4 — outcome when the store tip does not descend from the clone tip | technical | Ruled by CTO agent, 2026-10-31: skip the reset and emit a warn-level structured log, counts only, no Sentry event; a `merge-base` exit other than 0 or 1 falls into the existing catch at level 50. Amended by F7 and F11 below (the skip is only safe with a rescue branch; one reason, not two). |
| F5 — strictness of the first-session info classification | technical | Ruled by CTO agent, 2026-10-31: info only when the rejection has numeric code 128 AND `err.stderr` (falling back to `err.message`) matches `does not exist \(provision it first\)`; anything else stays level 50; the info log carries no path, repo name or user id; the matcher is proven against the real thrown error shape. |
| F6 — success marker shape, read definition and home | technical | Ruled by CTO agent, 2026-10-31: closed-grammar warn line `git_data_replication_success=1 transient_retried=<0\|1>`; the read lives under `scripts/followthroughs/` with its shard entry; "zero markers while sessions are live" = a reporter row with `agent_sessions_live>0` in the window, the newest reporter row reading 0, the window settled at least about 10 minutes after the last live row, and zero markers; a missing reporter row on either host is `READ_UNCLEAN`, never `NO_SESSIONS`. |
| F7 — a diverged skip must not make the store tip unreachable | technical | Ruled by CTO agent, 2026-10-31: (round 2, after the architecture review showed the next force-push would overwrite the only copy of replicated-only commits) before skipping, create a local branch `soleur/store-tip-<12 hex of the store sha>` at the fetched store tip, so the next ordinary `refs/heads/*` replication push carries those commits into the store namespace. No origin-push path sends arbitrary local branches to GitHub (only `session-sync.ts` pushes `HEAD:refs/heads/<KB_SYNC_SIDE_BRANCH>`). Plain `git branch`, no `-f`; an existing branch at the same sha is success; any other failure falls into the level-50 catch and the reset path never runs. |
| F8 — freshness of the newest pause row | technical | Ruled by CTO agent, 2026-10-31: the newest row per host must be at most 75 s old (two missed 60 s ticks) in addition to the all-rows-equal-1 check over the 120 s window - a stale pause is the unsafe direction. |
| F9 — credential scope and data minimisation in the flip step | technical | Ruled by CTO agent, 2026-10-31: bind the Better Stack reader's token per command (`env DOPPLER_TOKEN="$BS_DOPPLER_TOKEN" doppler run ...`, step env under the differently named `BS_DOPPLER_TOKEN`) and extract integers in SQL behind the closed-grammar `match`, so the runner never receives raw rows; anything that is not a clean integer fails closed as unread. |
| F10 — re-check just before the flag write | technical | Ruled by CTO agent, 2026-10-31: accept the gap and document it (the pause is a precondition-time check, not a lock held across the sequence); the R1 sequence re-reads immediately before and after dispatch, the finalizer unwinds on failure, the go gate aborts on any `=0` row, and a second read would put the Better Stack credential beside the flag-write token. |
| F11 — one skip reason, rescue on every skip | technical | Ruled by CTO agent, 2026-10-31: on a `--depth 1` clone `--is-ancestor` exiting 1 cannot separate "store behind the clone" from "diverged", so collapse to one reason `not_descendant` (warn, op `git-data-overlay-not-descendant`) and create the F7 rescue branch on every not-descendant skip; deepening the clone to classify is rejected (a network call at every session start). Extra store heads are bounded by the existing gc. The runbook says a `not_descendant` warn is expected after any GitHub-side change and the count, not a single row, is what to watch. This supersedes the CPO's request for a `store_behind`/`diverged` split (the split is not implementable on a shallow clone). AMENDED by F13 (2026-10-31): "Extra store heads are bounded by the existing gc" is false (gc deletes no refs); the heads are excluded from the overlay fetch and a host-side reaper is deferred; the rescue branch is now named `soleur-store-tip-<12 hex>` (F12). |
| F12 — atomic replication push and flat rescue name | technical | Ruled by CTO agent, 2026-10-31: push with --atomic and name the rescue branch soleur-store-tip-<12 hex> (amends F7) - non-atomic left main forced and the store tip unreferenced when the rescue ref was rejected (reproduced); atomic keeps both; a slash name would let a store head named soleur block every push. |
| F13 — rescue-head retention | technical | Ruled by CTO agent, 2026-10-31: AMENDS F11 ("bounded by the existing gc" is false: gc deletes no refs); exclude rescue heads from the overlay fetch; no --prune, no fixed name; host-side reaper deferred to a tracked issue (trigger: >10 rescue heads in a namespace or >=150 store refs) - --prune would delete store-only branches. |
| F14 — indeterminate ancestry | technical | Ruled by CTO agent, 2026-10-31: best-effort rescue branch, then rethrow to level 50; reset never runs (amends F4/F7) - an overlay error must not leave the store tip unprotected from the next force-push. |
| F15 — success marker volume | technical | Ruled by CTO agent, 2026-10-31: cap one marker per 60 s per process per transient_retried value - bounds Better Stack volume; markers>0 stays valid; markers are presence, not count. |
| F16 — ADR-068 §(d) supersession | technical | Ruled by CTO agent, 2026-10-31: recorded as a partial supersession in the ADR addendum; no new ADR; agent hand-back stays #11717 - the fence orders writers; ancestry decides adoption. |
| F17 — first-session classification | technical | Ruled by CTO agent, 2026-10-31: keep F5 info; document; post-restore refs_assert is the detector - a warn would be signup-rate noise. |
| F18 — MARKERS_PRESENT meaning | technical | Ruled by CTO agent, 2026-10-31: document-only: at least one replication in the window, not per-user coverage - a ratio is meaningless under the F15 cap. |
| NOTE on F8 (appended 2026-10-31; the F8 row is not edited) | technical | Ruled by CTO agent, 2026-10-31: F8's "75 s = two missed 60 s ticks" is imprecise - the reporter tick is 60 s (DEFAULT_REPORT_INTERVAL_MS in quiet-window.ts), so 75 s is one 60 s tick plus 15 s ingest slack, and a single missed tick already refuses; the 75 s bound itself is unchanged. |
| F19 — two-step replication push | technical | Ruled by CTO agent, 2026-10-31: AMENDS F12 - push the rescue ref alone first (skipped when no local soleur-store-tip-* branch), then the --atomic --force push, each step with its own single transient retry - measured: --atomic does not protect the old store tip in the shallow remote-failure class (main forced, rescue ref left out); the rescue-first push left the tip referenced when the second push failed, and the fence accepts the equal lease generation. |
