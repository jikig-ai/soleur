# Decision Challenges: feat-one-shot-auth-mode-selects-credential

Tracker: #11591. Plan: `knowledge-base/project/plans/2026-10-30-feat-auth-mode-selects-agent-credential-plan.md`.
Each technical row was ruled by a delegated agent (hr-technical-fork-is-not-an-operator-question); none was put to the operator.

## Decision Classes

| Item | Class | Ruling |
|------|-------|--------|
| Source of truth for the mode the lease reads: the conversation's engine binding vs the live workspace default | technical | Ruled by CTO agent, 2026-10-30: the conversation binding (`agent_engine_runs.auth_mode`). ADR-233 makes the binding immutable and authoritative, the egress policy and the diagnostic label already read it, and the card copy already says "new conversations". The per-slot credential cache therefore can never go stale. |
| How the lease learns the mode, and where the mode check sits relative to the existing gates | technical | Ruled by CTO agent, 2026-10-30: an optional lazy `resolveAuthMode` on `ByokLeaseArgs`, threaded through `resolveKeyOwnerThenLease` as an options object. Order in `fetchAgentCredentialIntoSlot`: kill-switch, read oauth row (ciphertext only), date gate, owner/delegation gate, THEN the mode read, THEN decrypt and shape check (managed) or skip to the api_key branch (api-key). Gates stay first and unchanged; the mode read happens only for an owner who holds a subscription row with the kill-switch on, so no new round trip for anyone else. Rejected: pre-resolving on every lease; the lease reading the workspace default itself. |
| Fail direction of the mode read | technical | Ruled by CTO agent, 2026-10-30: fail closed with `ByokLeaseError("fetch_failed")` (no new cause, so the `never` rail in `mapByokLeaseCauseToErrorCode`, the WS code and the UI are untouched) when the read throws, returns a value other than exactly `managed` or `api-key`, or no resolver was passed while an oauth row exists. One `reportSilentFallback` event, op `auth-mode-unresolved`, closed `reason` tag, no raw value. |
| `api-key` selected but no api_key row saved | technical | Ruled by CTO agent, 2026-10-30: `api-key` with no saved API key throws `MissingByokKeyError` and never falls back to the subscription token, and in `api-key` mode the subscription value is never decrypted - ratified: an explicit mode choice is a consent boundary, encoded in AC1 and AC8. |
| Conversations with no engine-run row reach the lease (auto-sync system conversation, support conversation) | technical | Ruled by CTO agent, 2026-10-30: no run row and `engine_binding_state='legacy'` resolves to `managed` (matches `assertLegacyConversationEngineBinding`); no run row and any other state fails closed (`fetch_failed`, reason `unbound`). Bind the auto-sync conversation (service client `bind` is granted to `service_role`, verified in migration 138) and the support conversation before dispatch, idempotently, so they follow the dropdown. A bind failure is non-fatal and Sentry-mirrored: the lease still fails closed for a subscription holder, and every other user is unaffected. |
| Reuse of `makeAuthModeResolver` | technical | Ruled by CTO agent, 2026-10-30: do not depend on it directly (its own removal checklist deletes the file with the temporary diagnostic). Extract the binding read into `server/engine-binding-auth-mode.ts`; `agent-auth-mode.ts` delegates to it and keeps its `null` -> `unbound` semantics. |
| ADR | technical | Ruled by CTO agent, 2026-10-30: amend ADR-048 (selection by consumer class AND by the binding's auth mode, plus the gate order), one-line cross-reference in ADR-233. No new ADR, so no ordinal to claim. |
| Test seam for "drives the selection through the real lease" | technical | Ruled by CTO agent, 2026-10-30: inject the resolver function into the real `runWithByokLease` for the matrix; add a second layer that wires the REAL binding resolver to a mocked tenant client so the lease follows a persisted binding that the test flips between leases. |
| What `managed` means for a user with no subscription row | technical | Ruled by CTO agent, 2026-10-30: `managed` for a user with no subscription row keeps leasing their own saved API key, and only the dropdown label changes - ratified: that is today's behavior, and changing it would alter every non-operator user for no benefit. |
| Mode applies to new conversations only (conversation snapshot), with a helper line under the dropdown | taste | Ruled by CPO agent, 2026-10-30: new conversations only, matching the card copy and the immutable binding; helper line "Applies to new conversations. Existing conversations keep the mode they started with." Operator may veto after the fact; default applied. |
| Display labels for the two options | taste | Ruled by CPO agent, 2026-10-30: show "Automatic" for `managed` and "My API key" for `api-key`; stored values unchanged. Operator may re-word; default applied. |
| Helper line wording vs the word "subscription" | technical | Ruled by CTO agent, 2026-10-30: the helper line stays credential-neutral and never names a subscription, with the plan's Phase 4 wording as the single source of truth - ratified: the copy rule in `agent-auth-user-message.ts` and the CLO ruling both require it; the plan line ("Applies to new conversations. Automatic uses the credential saved to your account; My API key uses your saved API key.") governs over any differing quote. |
| Amber disclosure visibility and text | technical | Ruled by CLO agent, 2026-10-30: show it in both modes (advisable, not harmful); tightening the sentence "Soleur-managed provider access remains restricted" is acceptable but not required. Planner keeps the text verbatim so the sibling string in `connected-services-content.tsx` stays consistent and no second component is edited. No Art. 30, Privacy Policy, DPD or GDPR Policy change. |
| Brand-survival threshold | technical | Ruled by CTO agent, 2026-10-30: the brand-survival threshold is `aggregate pattern` - ratified: both secrets belong to the same owner and the owner-only and delegation gates are untouched; escalate to `single-user incident` if any path can ever use another principal's credential (AC16 and the delegation test pin that). |
| Wireframe for the dropdown copy change | technical | Ruled by CTO agent, 2026-10-30: no `.pen` wireframe is needed for the label change, one static helper paragraph and a visibility predicate - ratified: `wg-ui-feature-requires-pen-wireframe` excludes copy and style and no new screen, modal or flow is added; keep the explicit exclusion note in the plan. |

| Retry the failing conversation under the new mode (in-flight conversations) | taste | Ruled by CPO agent, 2026-10-30: not built; revisit only if the new-conversation step proves to be real friction. Listed as a non-goal with re-evaluation criteria. |
| Plan-review: `resolveKeyOwnerThenLease` takes a required `LeaseModeOpts` (`{ resolveAuthMode } \| { restOnly: true }`) and builds lease args once; the source-scan sentinel is cut | technical | Ruled by CTO agent, 2026-10-30: `resolveKeyOwnerThenLease` takes a required `LeaseModeOpts` (`{ resolveAuthMode } \| { restOnly: true }`) and builds the lease args once, `resolveAuthMode` stays optional on `ByokLeaseArgs` so direct REST callers fail closed at runtime, and the source-scan sentinel is cut - ratified: the compiler is the stronger guard and the runtime floor (`no_resolver` fails closed) stays. |
| Plan-review: `ensureConversationBound` repository method dropped; plain `bind` on the just-inserted row, support sticky row bound only when `pending` | technical | Ruled by CTO agent, 2026-10-30: plain `bind` on the just-inserted auto-sync and support rows, a sticky support row bound only when `engine_binding_state` is `pending` and never when `legacy`, and no `ensureConversationBound` method - ratified: a fresh insert has no concurrent binder and mapping no-run to `managed` would let a declined account serve `api-key` owners; the work phase must confirm the `bind_agent_engine_run` grant to `service_role` and `authenticated` in the migration before relying on it. |
