## Decision Classes

| Item | Class | Ruling |
|---|---|---|
| 1. Question: ship the pre-run staging gap in git-commit-secret-scan now or keep open? | technical | Ruled by CTO agent, 2026-10-23: ship a simulated would-be index (index copy, exact replay of literal git add args with superset add -A fallback, quarantined object dir) in shared commit-index-sim.sh; failure to simulate denies, failed exact replay warns with a bypass row; Fix-Size medium. |
| 2. `git rm` / `git mv` earlier in the same command | technical | Ruled by CTO agent, 2026-10-23: record them as stages, never replay them - replaying would delete or rename the user's files, and skipping them can only leave extra indexed content in the would-be index (a superset), the safe direction for a scanner. |
| 3. Pathspec commit (`commit -- p`, `--only`, positional paths) ladder | technical | Ruled by CTO agent, 2026-10-23: accept the tightening - `git add -u -- <literal paths>`; if any path is non-literal (lexer flag x or q, or a glob/brace/tilde character) `git add -u`; `git add -A` only if both fail - it is a strict subset of `add -A` and matches what `--only` records; always-`add -A` would train agents to bypass the hook through false denies on untracked debris. |
| 4. More than one scanned root | technical | Ruled by CTO agent, 2026-10-23: replay exactly only when exactly one root is scanned; with more than one root use the superset in every root - the walker keeps a union of targets and cannot say which root an add applies to, and a misapplied replay would hide content from the scan. |
| 5. Other index-mutating verbs earlier in the same command | technical | Ruled by CTO agent, 2026-10-23: fold in now - `apply`, `update-index`, `checkout`, `cherry-pick`, `merge`, `revert`, `stash`, `am`, `read-tree`, `restore` earlier in the command mean "stages unknown" and force the superset `add -A` (a verb match plus a flag, no replay logic); a script that runs `git add` inside stays a named residual in the hook header with one follow-up issue; a branch-switch `checkout` forcing the superset is acceptable (slower, rare false deny). |
| 6. Loop or function in the command text with a staging verb | technical | Ruled by CTO agent, 2026-10-23: force the superset - text order is not run order there, so exact replay is unsound (the helper is `_ctr_has_loop` in commit-target-roots.sh, confirmed present). |
| 7. Widening the lexer pre-filter (~45 ms perl spawn on chained add-then-commit forms) | technical | Ruled by CTO agent, 2026-10-23: accept the cost; no cache and no bash-only fast path in this PR; add a regression test that `git add -A && git commit -m x` now reaches the lexer. |
| 8. Failed exact replay: split by failure class | technical | Ruled by CTO agent, 2026-10-23: adopt the split - git's own `pathspec ... did not match` keeps row 1 (bypass row, cause `pathspec-missing`, allow if clean) but is trusted only when the replay ran in a directory proven to be the user's (otherwise skip the exact replay and use the superset directly); any other failure (timeout, ENOSPC, exit 128 with another message) rebuilds from a fresh index copy with the superset, and a failed superset denies. Row 1 stands only for this class. |
| 9. `git rm` / `git mv` in the walker | technical | Ruled by CTO agent, 2026-10-23: the walker recognises and ignores them; they do not set `CTR_COMMIT_STAGES` (amends row 2's "record as stages") - they add no new blob content and rm only removes content; add one test that `git rm --cached f && git commit` still reaches the existing scan path. |
| 10. Unknown `--long` option after `git commit` | technical | Ruled by CTO agent, 2026-10-23: only an exact match against a benign table taken from `git commit -h` is benign; any other `--long` option, including a unique-prefix abbreviation, forces the superset; staging options (`--all`, `--include`, `--interactive`, `--patch`) always force it; a test asserts every table entry is accepted by the installed git. |
| 11. Positional pathspec without `--` | technical | Ruled by CTO agent, 2026-10-23: the pre-filter matches only a bare non-option first word right after `commit`; later positionals (after a `-m "..."`) are a named header residual, unscanned as today, with one follow-up issue filed - putting perl on every commit is the worse trade. |
| 12. Force-added ignored files | technical | Ruled by CTO agent, 2026-10-23: when an add record carries `-f`/`--force` (including bundles such as `-fA`) and the exact replay is impossible, also run `git add -f -- <literal words>` in the index copy; if any word is non-literal DENY with "run the force-add as its own call, then commit"; `git add -f .` is allowed to be slow because it scans what the real command would add. |
| 13. Sim library loading | technical | Ruled by CTO agent, 2026-10-23: source `commit-index-sim.sh` in the same checked `if` as `commit-target-roots.sh`; a missing or broken lib denies strict commits through the existing `lib` repair - a lazy source that fails open would let a broken lib silently skip the scan. |
| 14. Simplifications: no `--ignore-errors`, replay every add record | technical | Ruled by CTO agent, 2026-10-23: confirmed - without `--ignore-errors` a real `git add -A` fails the same way and a deny quoting git's first error line is the stricter choice; replaying every add record only over-scans, the safe direction; bound the whole simulation by one timeout, which falls under row 8's "any other failure". |
| 15. Directory proof for exact replay (amends rows 4 and 8) | technical | Ruled by CTO agent, 2026-10-23: exact replay only when (i) the command names no cd / pushd / -C / --git-dir / --work-tree and the PAYLOAD `.cwd` (read from the payload, not the `HOOK_CWD` fallback, which is never empty) is present, absolute and an existing directory, or (ii) every add record and the commit carry the same absolute existing `-C <abs>`, or (iii) `cd <abs>` is the first record followed only by `&&`-joined git records with no `(`, `{`, `\|\|`, `;`, pushd, popd or `cd -` in between; a relative `-C`/`cd` or anything unproven uses the superset - a directory the walker cannot prove is a directory it must not replay. |
| 16. `pathspec-missing` is never allowed outright (amends row 8) | technical | Ruled by CTO agent, 2026-10-23: rebuild with the superset; if the command text has an earlier producer (output redirect, tee, sed -i / --write, or a command word before the add outside git / cd / env / pass-through launchers / true / test / echo-without-redirect, as an allowlist) DENY with the existing `create` repair, otherwise allow with the sim-failed row (cause pathspec-missing); the trusted error is rc 128 AND `^fatal: pathspec '.*' did not match any files$`. |
| 17. Config-transforming staging arguments | technical | Ruled by CTO agent, 2026-10-23: a staging record carrying `-c` / `--config-env` keys matching ^(core\|filter\|diff\|attr\|include\|includeif\|add\|apply\|submodule)\. (case-insensitive), any `GIT_*` env prefix, `--git-dir`, `--work-tree`, `--namespace` or `--attr-source` makes the command opaque: DENY "stage in its own call"; the replay forwards nothing. |
| 18. Pins on every simulation git call | technical | Ruled by CTO agent, 2026-10-23: pass `-c core.fsmonitor=false -c core.untrackedCache=false -c core.splitIndex=false` and neutralise each configured filter (enumerated with `git config --get-regexp '^filter\..*\.(clean\|process\|smudge\|required)$'`); the sim scans raw pre-filter bytes; filter/LFS divergence is a named header residual; Guard 2 compares the real `.git` file listing before and after and denies on any difference. |
| 19. `scan_root` and the per-path `git check-attr` loop (amends the brief's "scan_root unchanged") | technical | Ruled by CTO agent, 2026-10-23: take ONE behaviour-preserving edit - batch the loop into a single `git check-attr -z --stdin diff` call (measured 83 s vs 43 ms at 5,000 paths, same result), not a path cap; the old-vs-new equivalence test covers paths with spaces, quotes and newlines and attribute values set / unset / unspecified / valued; a batch failure DENIES in sim mode and falls back to the old loop on the plain path. |
| 20. Bound the whole simulation including gitleaks | technical | Ruled by CTO agent, 2026-10-23: one total sim deadline of 30 s, `timeout -k 2` with an integer ceiling of at least 1 (never 0), `perl -e 'alarm N; exec @ARGV'` where neither `timeout` nor `gtimeout` exists, DENY if none of the three exists; gitleaks is bounded in sim mode, expiry always DENIES (never bypasses); no content-size proxy. Implementation note from the plan: `scan_root` calls `env ... gitleaks`, which bypasses a shell function, so the bound is a generated wrapper script first on PATH inside the sim directory. |
| 21. Library API for reuse by #10793 | technical | Ruled by CTO agent, 2026-10-23: the lib owns policy-free construction - `cis_plan` (pure over the CTR facts plus an explicit dir, sets CIS_MODE / CIS_WHY), `cis_build <root> <dir> <workdir>` returning exactly 0 built / 10 built with pathspec-missing / 20 failure (any other non-zero is 20; CIS_ERR set), `CIS_ENV=(...)`, `cis_export` / `cis_unexport` restoring prior values and distinguishing unset from empty; the lib never calls `exit` and removes its workdir on failure; the hook glue maps codes to allow / deny / bypass and rule ids; a consumer stub test of about 15 lines is required. |

## Review-round rulings (2026-10-23, batched CTO ruling on panel dissents; rows 22 to 36 amend the rows named)

| 23. Replay environment | technical | Ruled by CTO agent, 2026-10-23: a staging record with an env name outside the allowlist (LC_*, LANG, LANGUAGE, TZ, TERM, NO_COLOR, CI, GIT_AUTHOR_*, GIT_COMMITTER_*, GIT_EDITOR, GIT_PAGER, GIT_TERMINAL_PROMPT), `env -i/-u`, sudo/doas/su/runuser/chroot/nsenter, or `export/unset` of such a name is refused ("stage in its own call"); edits an earlier command makes to ignore, config or attributes are the single named residual "what earlier commands in the same call change is not seen" - a superset cannot reproduce a different HOME, and a producer's later content is unscannable by construction. |
| 24. | 25. | 30. Bound, wrapper, sweep, errexit (amends row 20 and Design 5) | technical | Ruled by CTO agent, 2026-10-23: replace the generated gitleaks wrapper with a bound prefix array on the two call sites, using one fork/waitpid/kill perl program on every host (expiry rc 124, child rc passed through); drop the timeout/gtimeout ladder, the `none` kind, PATH mutation and the epoch clock; drop the stale sweep (residual: a SIGKILL can leave a 0700 temp dir); compute `sim_on` before the first mktemp and install `set -E` plus an ERR trap that denies when `sim_on=1` - perl `alarm`+exec does not stop gitleaks (verified: still running 30 s after a 2 s alarm; the Go runtime ignores SIGALRM), and an unguarded write under `set -e` exits 1, which lets the commit through. |
