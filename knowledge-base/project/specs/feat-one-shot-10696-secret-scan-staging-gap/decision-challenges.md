## Decision Classes

| Item | Class | Ruling |
|---|---|---|
| 1. Question: ship the pre-run staging gap in git-commit-secret-scan now or keep open? | technical | Ruled by CTO agent, 2026-10-23: ship a simulated would-be index (index copy, exact replay of literal git add args with superset add -A fallback, quarantined object dir) in shared commit-index-sim.sh; failure to simulate denies, failed exact replay warns with a bypass row; Fix-Size medium. |
| 2. `git rm` / `git mv` earlier in the same command | technical | Ruled by CTO agent, 2026-10-23: record them as stages, never replay them - replaying would delete or rename the user's files, and skipping them can only leave extra indexed content in the would-be index (a superset), the safe direction for a scanner. |
| 3. Pathspec commit (`commit -- p`, `--only`, positional paths) ladder | technical | Ruled by CTO agent, 2026-10-23: accept the tightening - `git add -u -- <literal paths>`; if any path is non-literal (lexer flag x or q, or a glob/brace/tilde character) `git add -u`; `git add -A` only if both fail - it is a strict subset of `add -A` and matches what `--only` records; always-`add -A` would train agents to bypass the hook through false denies on untracked debris. |
| 4. More than one scanned root | technical | Ruled by CTO agent, 2026-10-23: replay exactly only when exactly one root is scanned; with more than one root use the superset in every root - the walker keeps a union of targets and cannot say which root an add applies to, and a misapplied replay would hide content from the scan. |
| 5. Other index-mutating verbs earlier in the same command | technical | Ruled by CTO agent, 2026-10-23: fold in now - `apply`, `update-index`, `checkout`, `cherry-pick`, `merge`, `revert`, `stash`, `am`, `read-tree`, `restore` earlier in the command mean "stages unknown" and force the superset `add -A` (a verb match plus a flag, no replay logic); a script that runs `git add` inside stays a named residual in the hook header with one follow-up issue; a branch-switch `checkout` forcing the superset is acceptable (slower, rare false deny). |
| 6. Loop or function in the command text with a staging verb | technical | Ruled by CTO agent, 2026-10-23: force the superset - text order is not run order there, so exact replay is unsound (the helper is `_ctr_has_loop` in commit-target-roots.sh, confirmed present). |
| 7. Widening the lexer pre-filter (~45 ms perl spawn on chained add-then-commit forms) | technical | Ruled by CTO agent, 2026-10-23: accept the cost; no cache and no bash-only fast path in this PR; add a regression test that `git add -A && git commit -m x` now reaches the lexer. |
| 8. Failed exact replay: split by failure class | technical | Ruled by CTO agent, 2026-10-23: adopt the split - git's own `pathspec ... did not match` keeps row 1 (bypass row, cause `pathspec-missing`, allow if clean) but is trusted only when the replay ran in a directory proven to be the user's (otherwise skip the exact replay and use the superset directly); any other failure (timeout, ENOSPC, exit 128 with another message) rebuilds from a fresh index copy with the superset, and a failed superset denies. Row 1 stands only for this class. |
| 9. `git rm` / `git mv` in the walker | technical | Ruled by CTO agent, 2026-10-23: the walker recognises and ignores them; they do not set `CTR_COMMIT_STAGES` (amends row 2's "record as stages") - they add no new blob content and rm only removes content; add one test that `git rm --cached f && git commit` still reaches the existing scan path. |
| 10. Unknown `--long` option after `git commit` | technical | Ruled by CTO agent, 2026-10-23: only an exact match against a benign table taken from `git commit -h` is benign; any other `--long` option, including a unique-prefix abbreviation, forces the superset; staging options (`--all`, `--include`, `--interactive`, `--patch`) always force it; a test asserts every table entry is accepted by the installed git. |
| 11. Positional pathspec without `--` | technical | Ruled by CTO agent, 2026-10-23: the pre-filter matches only a bare non-option first word right after `commit`; later positionals (after a `-m "..."`) are a named header residual, unscanned as today, with one follow-up issue filed - putting perl on every commit is the worse trade. |
| 12. Force-added ignored files | technical | Ruled by CTO agent, 2026-10-23: when an add record carries `-f`/`--force` (including bundles such as `-fA`) and the exact replay is impossible, also run `git add -f -- <literal words>` in the index copy; if any word is non-literal DENY with "run the force-add as its own call, then commit"; `git add -f .` is allowed to be slow because it scans what the real command would add. |
| 13. Sim library loading | technical | Ruled by CTO agent, 2026-10-23: source `commit-index-sim.sh` in the same checked `if` as `commit-target-roots.sh`; a missing or broken lib denies strict commits through the existing `lib` repair - a lazy source that fails open would let a broken lib silently skip the scan. |
| 14. Simplifications: no `--ignore-errors`, replay every add record | technical | Ruled by CTO agent, 2026-10-23: confirmed - without `--ignore-errors` a real `git add -A` fails the same way and a deny quoting git's first error line is the stricter choice; replaying every add record only over-scans, the safe direction; bound the whole simulation by one timeout, which falls under row 8's "any other failure". |
