Decisions taken during `plan`/`work` that needed a ruling or went against a
recommendation. Recorded per ADR-084 so `ship` renders them into the PR body.
This planning session ran inside a Task subagent without the Agent/Task tool,
so technical rulings that would have gone to `soleur:engineering:cto` are
recorded as `pending - assumed:` per the technical-ruling-delegation contract.

## Decision Classes

| Item | Class | Ruling |
|---|---|---|
| Gate `gh pr ready` in addition to `gh pr merge`? | technical | pending - assumed: `gh pr merge` only. `gh pr ready` marks review-readiness, not publication — the leak event is the merge landing live paths on `main`. A ready-deny would hit a legitimate draft-for-review flow on non-ship paths, and in the restructured flow (Phase 6.45 before Phase 6.5 ready+arm) gating ready adds no coverage on the sanctioned path. |
| Deny on `M` (modified) rows at live KB paths, or `A` (added) rows only? | technical | pending - assumed: deny on both A and M — the brief's literal "adds or modifies". An M row means the artifact is live at the PR head and this PR did not archive it; remediation is the same archive command, and a live artifact a PR modifies is legitimately that PR's to archive. The M-row false-positive surface (a drive-by edit forcing whole-dir archival of a backlog dir) is accepted — archiving a touched backlog dir reduces the measured ~1747-dir backlog. |
| Fail-open scope for `main`/detached/bare? | technical | pending - assumed: the brief's fail-open applies to the HEAD-based path only. `main`/detached/bare are states where HEAD is not the merge's measured object; a numbered `gh pr merge <N>` or `--match-head-commit <sha>` resolves a pushed object and is always verifiable, so it gates on every checkout state (this is what keeps `soleur:schedule`'s main-checkout merges and drain sessions covered). The literal alternative (exempt all forms on main/detached/bare) is rejected: it would silently disarm the gate in exactly the sessions that merge other PRs. |
| Unresolvable merge target (state L: mixed numbers, non-bare arg, foreign cd, unprovable repo pointer) — HEAD fallback or deny? | technical | pending - assumed: deny carrying `MERGE_TARGET_WHY`. The sibling's HEAD fallback is right for a review-evidence gate grading the session branch; for an artifact census, checking HEAD when the merge targets a different PR is simultaneously a false-pass (leaky remote head from a clean branch) and a false-deny (clean remote head from a dirty branch). Proven-foreign `-R`/env pointers exit 0 — not our repo. |
| PR-head resolution mechanism? | technical | pending - assumed: verbatim-import `pre-merge-rebase.sh`'s #8778/#9401 resolver (`_merge_args`, `--help` pass-through, `_repo_url_parts`, `_repo_flag_operands`, `_repo_env_operands`, `_repo_pointers_same_repo`, `_strip_repo_flags`, MERGE_TARGET_WHY ladder, in-command-cd scan, `timeout`→`gtimeout`→bare wrapper, `^[0-9a-f]{40}$` validation), byte-copied and parity-pinned per the repo's copied-helper convention. `refs/pull/<N>/head` fetch (verified on real origin) resolves the head without a `gh` dependency; `--match-head-commit <sha>` takes precedence when present (the admin hatch's exact merged sha). A shared-lib extraction was rejected — it would force an edit to the live review-evidence gate for ~zero net code. |
| Trigger regex boundary set? | technical | pending - assumed: widen the sibling's start/chain-operator-only boundary per `pre-merge-rebase.sh:121` + `prod-write-defer-gate.sh:179` precedents — add the `\s--\s` member for the sanctioned `with_lock merge-main 600 -- gh pr merge` arming form (#3689 class), the env-assignment-prefix clause, and the paren/pipe substitution members. A gate that cannot see the wrapped arm never fires on the main path. Documented residual, shared with all siblings: `gh pr merge` inside a quoted `bash -c '…'` payload is stripped and does not fire; postmerge Phase 5.8 is the net. |
| Fetch/verify failure (origin unreachable, pull ref missing) — fail open or closed? | technical | pending - assumed: fail-closed deny, sibling parity (`ship-unpushed-commits-gate` T9 posture). An unverifiable head is the silent-miss class this gate exists to end; the deny message names the failed fetch and the manual retry. |
| Unresolvable merge-base (shallow clone) — fail open or closed? | technical | pending - assumed: fail-open silently. The brief's fail-open list (main, detached HEAD, bare repo) is the same class — the gate cannot measure what git cannot compare. A shallow worktree hitting this also breaks `archive-kb.sh` discovery (its merge-base probe falls back silently), so the exposure predates the hook and is noted, not widened. |
| Env escape hatch? | technical | pending - assumed: `SOLEUR_SKIP_KB_ARCHIVE_GATE=1` pass-through, sibling parity (`SOLEUR_SKIP_OPERATOR_STEP_GATE`). It is the deliberate one-keystroke repair for a wedged gate; not a hole — the deny remains the default. |
