| 1. Evidence rubric: what counts as "the suite really reads or executes the file", and the default for an ambiguous pair | technical | Ruled by CTO agent, 2026-10-23: adopt the rubric with class (c) kept and two amendments, and default an ambiguous pair to DECLARE. DECLARE when (a) the suite, or a library it sources or executes at runtime, executes or sources the file, including a computed path and a best-effort source whose failure is swallowed (`plugins/soleur/test/test-helpers.sh:58` and `.claude/hooks/lib/incidents.sh` count); (b) it opens the content (cat, grep, sed, awk, jq, read, readFileSync, import, hash, diff, or copy-then-assert on a COPY); (c) it asserts existence or mode (`[ -f ]`, `test -x`, `ls`) where the verdict depends on it (kept because the recorder cannot see stat probes, so (c) is the class most likely to become a false negative once the lever flips); (d) the path is a data-table row that the suite then feeds to a read, exec or stat loop, and the implementer QUOTES the consumer loop line (no quoted loop means mention). Amendment 1, runtime-mediated reads: a library that opens the path counts for every suite that sources that library at runtime; a library that is only text-scanned (the `scripts/lib/test-relevance-paths.sh` data arrays) does not. Amendment 2, the mention class: messages, docstrings, comments, test-vector arguments to a predicate that never opens the path, fixture rows, files written into a scratch fixture, allow-list, classification and relevance rows, negative-test strings. Ambiguous default: declare a single exact file when all three hold (a 20-minute read cannot settle it; the declaration is an exact file; it adds no more than about 1 suite run per 20 PRs); otherwise (not exact-file, or no consumer can be named) leave the pair for PR5. The PR body lists every ambiguous declare so PR5 can demote it with evidence. Record every pair in a TSV `suite, path, class (a, b, c, d or mention), file:line`, counts in the PR body; no class means no declaration and no accept row. |
| 2. Evidence tier: line-reading only, or the recorder `scripts/audit-suite-reads.sh` as a cross-check | technical | Ruled by CTO agent, 2026-10-23: the recorder is REQUIRED as a one-directional empirical cross-check on a bounded sample; line-reading stays the primary evidence. Sample: the top 12 suites by code-pair count plus 15 drawn at random from the rest (27 suites), `--mode check`. Hard fail: a pair the recorder saw opened that line-reading called a mention MUST flip to declared, and a clean recording (`covered` or `uncovered`) with an unfixed flip fails review. Not a failure: a `disqualified` or `unreliable` row proves nothing either way; it falls back to line-reading and is noted `recorder-blind`; the recorder never converts a declared pair into a mention (it cannot see stat probes). An `uncovered` opens list outside the cover for a sampled suite means missing edges: add them in the same batch or take them as the next reveal round. If the tooling cannot run (no netns, or the host stays over `--max-load`), the PR body says `recorder: not run, <reason>` and halves the confidence claim; it is not a merge blocker; the recorder is never wired into CI. |

| 4. Breadth guard and ALWAYS_ON | technical | Ruled by CTO agent, 2026-10-23: allowed edge forms are an exact file (the default); a directory prefix only when the suite really walks that directory, the walker line is quoted, the prefix has at least 3 path segments and resolves to at most 25 tracked files (the PR body lists the exact count; a wider prefix needs its own explicit justification); `glob:<head>/<tail>` for extension-aware corpus walks only, same quoted-walker requirement.
