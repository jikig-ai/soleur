## Implementation notes (work phase, 2026-10-16)

- G1 proved through the real SDK in two places (vitest on the runner; the docker suite under the production run tuple). The control arm reproduces the exact issue line; the knob-off mutation reddens the docker suite.
- G2 passed: through every visible sibling socket, requests without the sibling's credential get 407, and the caller's own credential is live.
- Found by the census arm and fixed inline (a correctness fix of about ten lines, not an architecture fork): the CLI's peer-messaging sockets (`/tmp/cc-socks/<pid>.sock`, same uid for every tenant session) become connectable once AF_UNIX is allowed. They are now denied for every session via `peerMessagingSocketDirs()` in `buildAgentSandboxConfig` (pre-created, XDG-aware), with a runtime assertion that the sandbox sees none while a host-side socket exists. The peer-message protocol's own authentication was NOT characterised; the mask removes the question for tenant sessions.
- Review-time changes (12-seat review, 2026-10-16), none of which reverses a ruling above: the session-transcript directory (`$HOME/.claude/projects`, `$CLAUDE_CONFIG_DIR/projects`) is masked, because with AF_UNIX allowed a sibling's proxy credential printed by `env` and persisted in a shared-HOME transcript becomes usable; G2 asserts the sandbox sees none.
- `peerMessagingSocketDirs()` now returns the union of `<base>/cc-socks` for base in {`XDG_RUNTIME_DIR`, `CLAUDE_CODE_TMPDIR`, `TMPDIR` (each only when set and absolute), `/tmp`} plus `/tmp/cc-socks-<uid>` (the CLI's fallback); a failed pre-create pages through `reportSilentFallback`.
- The classifier arm is narrowed to the exact, line-anchored `apply-seccomp: unshare(CLONE_NEWUSER): Operation not permitted`; other helper-step EPERMs are not classified (residual, #10455). The mirror debounce key includes `errorCode`.
- `scripts/followthroughs/sandbox-readback-10445.sh` exits TRANSIENT (2) until the PR's merge commit is an ancestor of the deployed tag (`gh api compare`), then exits 0 on `sandbox_canary` pass. It proves fix deployed and canary green, not that hosted Bash works; the real hosted Bash call is recorded in the PIR by the post-merge verification, and #10456's directive gains `secrets=GH_TOKEN`.
- Corrections to the R1 row: "AF_UNIX blocking was recorded as inert" was false (the SDK helper was the per-command AF_UNIX block until 2026-10-06); the ADR-075 addendum states the weaker-than-baseline posture and its bounds. The word "inert" comes from the #8752 plan; the 2026-10-11 ADR-075 addendum says "Invariance caveat".
- Causal evidence (measured 2026-10-16, production-like container: digest-pinned node:22-slim base, Debian bubblewrap 0.8.0, uid 1001, docker default masks, committed seccomp profile): no shim filter, the wrapped Bash call succeeds; shim filter with the knob unset, it fails with the helper EPERM.
- Only the first alert shipped: two `-target=` lines, not four; the second alert and the deploy-time smoke are #10453.
