## Implementation notes (work phase, 2026-10-16)

- G1 proved through the real SDK in two places (vitest on the runner; the docker suite under the production run tuple). The control arm reproduces the exact issue line; the knob-off mutation reddens the docker suite.
- G2 passed: through every visible sibling socket, requests without the sibling's credential get 407, and the caller's own credential is live.
- Found by the census arm and fixed inline (a correctness fix of about ten lines, not an architecture fork): the CLI's peer-messaging sockets (`/tmp/cc-socks/<pid>.sock`, same uid for every tenant session) become connectable once AF_UNIX is allowed. They are now denied for every session via `peerMessagingSocketDirs()` in `buildAgentSandboxConfig` (pre-created, XDG-aware), with a runtime assertion that the sandbox sees none while a host-side socket exists. The peer-message protocol's own authentication was NOT characterised; the mask removes the question for tenant sessions.
