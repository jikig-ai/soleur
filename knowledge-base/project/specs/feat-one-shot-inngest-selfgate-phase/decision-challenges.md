## Decision Classes

| Item | Class | Ruling |
|------|-------|--------|
| F1 Event fields for the self-gate failure: (A) a derived `phase=` token plus integers `tcp= tls= verify=`, (B) raw clamped millisecond timing fields, or (C) both | technical | Ruled by CTO agent, 2026-10-23: (A), appended after `attempts=` with the `rc= http= attempts=` prefix byte-identical; `tcp` counts attempts that reached TCP connect, `tls` counts attempts that completed TLS, `verify` is the last attempt's `ssl_verify_result`, each clamped by `_inngest_link_count99` - raw millisecond timings add cardinality and a certificate-timing side channel for no extra decision power; (B) and (C) rejected; the existing A7 row substring-matches `rc=0 http=502`, so an appended suffix is safe |
| F2 Phase derivation: where, how parsed, token set, fail-safe | technical | Ruled by CTO agent, 2026-10-23: derive in bash from ONE `-w` line (`%{http_code} %{time_connect} %{time_appconnect} %{ssl_verify_result}`) with shape validation (code `^[0-9]{3}$`, times `^[0-9]+[.,][0-9]+$`, zero tested by `^[0.,]*$`, no float math); success stays exactly `rc==0` and the first token `200`; any parse failure or rc 124 gives `phase=unknown` and never aborts; tokens in precedence order `unknown`, `ca_file` (rc 77), `verify` (rc 60, decided from rc because `ssl_verify_result` 1 is ambiguous), `status` (code not 000), `request` (TLS complete, no HTTP status: the incident signature), `handshake` (rc 35, or rc 28 with TCP up and TLS incomplete), `connect` (rc 7 or 6, or rc 28 with no TCP); parse with a here-string and `\|\| true` because curl prints no trailing newline and a bare `read` returns 1 under `set -e`, with a no-newline row |
| F2a Refinement of F2: classify the last three stages by the measured times, not by an rc list | technical | Ruled by CTO agent, 2026-10-23: ratified - the time-based map is version-robust where the rc sets were not (one wire event prints rc 52 on curl 8.5.0 and rc 56 on 7.81 and 8.23; TLS-then-garbage prints rc 1) and every case the first ruling listed maps to the same token; order is unparsable gives `unknown`, rc 77 `ca_file`, rc 60 `verify`, validated 3-digit code not 000 `status` (never from rc alone), `time_connect` zero `connect`, `time_appconnect` zero `handshake`, otherwise `request`; times are zero-tested with `^[0.,]*$` only after the shape check passed; `unknown` only for empty output, rc 124 or a bad shape; stub rows give the SAME times with rc 52, 56 and 1 and expect `request` for all three |
| F3 One curl per attempt with a multi-variable `-w` vs a second diagnostic probe after failure (an unverified `curl -k`, or the existing `/hooks/inngest-tls-handshake` call) | technical | Ruled by CTO agent, 2026-10-23: one curl, no second probe - a `-k` probe on the trust path adds a new unverified-TLS code path and a second timeout budget for a purely diagnostic gain, and the phase fields already localize the failure |
| F4 Mock honesty: how the curl doubles prove they match real curl | technical | Ruled by CTO agent, 2026-10-23: sufficient with four additions, all adopted - the stubs exit non-zero on any `-w` variable or phase profile they do not know (never default to a 200 profile); a differential row compares `(rc class, http, phase)` from real curl with the stub profile for the same phase, not only a real-curl run of the function; under `CI` a missing curl, python3 or openssl is a failure and a local skip is counted explicitly; the TLS-then-close and TLS-then-RST rows assert phase class (both `request`), not exact rc, with loopback ephemeral ports and a clean proxy environment |
| F5 Ratchets and baselines (`MIN_ROWS`, `CI_DEPLOY_ASSERT_FLOOR`, fixture-relative baseline, `PJ_TRIPLES`, `BASELINE_DECLARED_PROBES` 76 to 77) | technical | Ruled by CTO agent, 2026-10-23: no objection; `BASELINE_DECLARED_PROBES` is 76 on `origin/main` at `preflight-discoverability-test.test.ts:3021`, so 77 is right, re-check after rebasing onto `origin/main`; `MIN_ROWS` is an exact count (203 now); grep Better Stack alert queries and runbooks for any full-string match on the `selfgate_failed` detail before merging (done at plan time: the only consumers are `ci-deploy.sh`, the resolver suite and the runbook) |
| Wording of `phase=request` (CTO-added risk) | technical | Ruled by CTO agent, 2026-10-23: `phase=request` means only that TLS verified and no HTTP response came back; the event docs, the runbook and the ADR addendum say "check the terminator and its upstream, not the certificate" and never assert a root cause (the terminator's journald is not shipped, #10880) |
| Scope: ADR-294 addendum and a `deploy-status-debugging.md` row (items the brief did not name) | technical | Ruled by CTO agent, 2026-10-23: keep both - the row is operator-facing triage for a constant reason string that has no row today, one row only; the ADR-294 addendum follows the two earlier flip addenda and is cut first if scope grows; the row and the addendum both say `phase=request` means only that TLS verified and no HTTP response came back, neither names the upstream as the established cause, and the addendum cites only the observed `rc=56 http=000 attempts=3` and the container measurements, with no production reads |
| R3a Plan-review amendment of the phase order: decide the verdict first, then rc-only arms before any time-field shape check | technical | Ruled by CTO agent, 2026-10-23: ratified - order is the success verdict first from rc and the first token alone, then rc 124 or empty output gives `unknown`, then rc 77 gives `ca_file` and rc 60 gives `verify` from the rc alone, then a validated 3-digit code other than 000 gives `status`, then `connect`, `handshake` and `request`, which need both time fields to pass the shape check or the phase is `unknown`; amendment: a code token failing its shape check is emitted as `http=none`, never as the raw token, so every field in the event is a fixed token or a clamped integer; `tcp` and `tls` count only attempts whose own time field passed the shape check |
| R3b `verify=` semantics | technical | Ruled by CTO agent, 2026-10-23: ratified - `verify=` is 0 unless `phase=verify` and then the raw value clamped to 99, because the raw 1 on handshake and CA-file failures would read as a SAN mismatch; a mutation row pins the coercion |
| R3c Simplification review asked to cut `tcp=`, the comma tolerance, two of the seven tokens and the ADR addendum | technical | Ruled by CTO agent, 2026-10-23: all four cuts overruled - keep `tcp=` (the flapping-listener decode across attempts needs it), keep `[.,]` (one character class, locale behaviour unproven), keep all seven tokens (each points at a different fix: trust file, listener, handshake, certificate, upstream, status; collapsing them recreates the incident's ambiguity), keep the ADR addendum at 8 lines or fewer |
| R3d Test-scaffolding shape after review: one shared profile table and printer for both curl doubles, six-scenario real-curl differential, trimmed mutation set | technical | Ruled by CTO agent, 2026-10-23: no objection with two conditions - the printer exits 99 AND drops a sentinel file that every suite asserts absent after each row (the function under test swallows a non-zero curl exit and its stderr, so the exit alone would read as another failed attempt), and the differential compares the stub profile with real curl on (rc class, code, which of connect/appconnect are zero, verify), not on the phase alone; RST and the empty CA file stay stub-only on the evidence file |
| R3e `status` versus a truncated 200 (deepen-pass finding) | technical | Ruled by CTO agent, 2026-10-23: ratified - `status` is only a validated code that is neither 000 nor 200; a 200 code with a non-zero rc (measured rc 18 truncated body) falls through to the time rules and reads `request`; a non-200 code with a non-zero rc stays `status` (a non-200 status really was received); keep the `req_partial` profile and its mutation row and add a row for a non-200 header followed by a truncation expecting `status`; `http=200 phase=request` is a legitimate combination and the runbook says it means a 200 header with the body cut short, not healthy |
