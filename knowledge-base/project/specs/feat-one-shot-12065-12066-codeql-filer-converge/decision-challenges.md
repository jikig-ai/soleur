| check-alerts exit semantics + `needs:` edge | technical | Ruled by CTO agent, 2026-11-04: sweep inherits gate verdict semantics (exit 1 on filing) and the `needs: check-alerts` edge is unchanged - a single verdict contract is the point of convergence, a filing day skipping `close-orphans` merely defers reaping to the next green run while the filed `action-required` tracker is the durable page, and `if: always()` on the reaper is the riskier direction (reaping while the alerting pipeline is degraded contradicts close-orphans' own fail-biased-open design). |
| `dry_run` dispatch input on codeql-to-issues.yml | technical | Ruled by CTO agent, 2026-11-04: add the `dry_run` boolean dispatch input to codeql-to-issues.yml - it mirrors the gate workflow's existing input contract (codeql-main-alert-gate.yml:43-47), is the sole zero-write path to verify the rewired caller post-merge, and its absence would leave no safe way to exercise the sweep end-to-end without filing live issues. |
| `dry_run` scope over `close-orphans` (review dissent, agent-native + data-integrity seats) | technical | Ruled by CTO agent, 2026-11-04: AMENDS the `dry_run` ruling - `close-orphans` gains `if: inputs.dry_run != true` and the input description discloses the reaper skip, because the zero-write contract is a property of the run, not only of the filer step: on a green dry dispatch the reaper still performed real `gh issue comment` + `gh issue close` writes.
