## 2026-10-07 Review (design-validity pass)

8. **`verify` stays a per-line judge; the re-derive-and-diff form was declined.** The simplicity seat proved a stronger verifier exists: export the base tree, run `apply --write` on it with the same inputs, diff against the branch, and require every remaining hunk to be a listed hand edit (it reproduced 22 of 24 files byte for byte). It also closes the concession that a line `apply` refused but the author converted by hand passes `verify`. Declined for S1 because hand edits are keyed by base-side line range and the re-derived tree shifts them as soon as one hand edit changes a line count; the cost is a second keying scheme. Class: taste. Challenge: adopt it in S2 once a slice has a count-changing hand edit to design against.
9. **The 1,080-row equivalence table stays out of the selftest; 13 representative rows stay in.** The simplicity seat called the two equivalence checks a test of the host's `grep`; the plan's AC-8 asks for them by name (one row per cluster class under bash and `sh`). Kept. Class: taste.

Class: mechanical.

The performance seat's one-`git grep`-per-file `verify` batching and the 6-span cap message are deferred: 1 s on a 22-file slice. Class: taste.
