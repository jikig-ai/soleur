## F-C end state / row classes (computed by the scanner; baseline records expected class; suite checks agreement)
Baseline columns: file, name, class, expires, issue-tag.
- `tier-a`: any file with a direct-store read shape, OR a workflow-like file naming the trio with no Tier-B environment. Expiry required (strict ISO). TERMINAL: zero rows.
- `tier-b`: workflow/composite files (.github/workflows, .github/actions) with no direct-store read shape where EVERY job naming the trio declares an `environment:` whose arms are all in the Tier-B set (job-level environment extractor). Expiry `-`. Permanent, base-anchored.
- `sink`: non-workflow files with no direct-store read shape (variables.tf, server.tf, hooks.json.tmpl, cloud-init.yml, soleur-host-bootstrap.sh, host scripts using ${NAME}). Expiry `-`. Permanent, base-anchored.
FALLBACK:* and ALIAS:* rows are always tier-a. A migration PR changes tier-a -> tier-b|sink (key+tag stay; suite recomputes class; marking tier-b without the environment = RED). Final criterion (replaces "empty baseline"): no tier-a / FALLBACK:* / ALIAS:* rows; every tier-b row proves its environment; every sink row has no read shape.
Tier-B environment set: single-source the sibling census's tier_b_environments (tests/scripts/test-infra-privileged-tier-census.sh); a row pins the suite's set as a subset of the sibling's, and the suite additionally accepts `deploy-channel` and `inngest-cutover` as pending names (PR-1 adds deploy-channel to both). A trio read through prd_terraform is tier-a whatever the job's environment. Build the "every job naming the trio declares a Tier-B environment" check in PR-0 against a FIXTURE environment set (live tier-b rows = 0 in PR-0): job with `environment: deploy-channel` and fixture set containing it = green; deleting deploy-channel from the fixture set = RED; non-canonical step name/indentation still passes.
