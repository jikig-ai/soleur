# Decision challenges: feat-one-shot-12585-sandbox-network-access (#12585)

Every technical fork below was ruled by a domain agent; none is an operator question. Operator-only items are named as such.

| F1 Entitlement key for the SandboxNetworkAccess arm | technical | Ruled by CTO agent, 2026-11-18: key on the live forwarder handle (`webEgress !== undefined`, the same expression that feeds `buildAgentEnv`), never on the grant boolean `webEgressEntitled`; absent => deny `not-entitled`. The legacy runner and the support persona never pass it - a grant-keyed allow would send a degraded (forwarder-spawn-failed) session out on the SDK's direct route, the bypass the spike measured. |
| F2 Where the arm learns NO_PROXY | technical | Ruled by CTO agent, 2026-11-18: new import-free module `apps/web-platform/server/sandbox-network-access.ts` owns `SANDBOX_NETWORK_ACCESS_TOOL`, `WEB_EGRESS_NO_PROXY` (moved byte-identical out of the `agent-env.ts` literal; agent-env imports it), `noProxyMatches` and a pure `decideSandboxNetworkAccess`; `CanUseToolContext` gains optional `sandboxNetworkEgress`; an equality test pins it against `buildAgentEnv(...).NO_PROXY` for the same handle - one constant for both consumers; passing the whole env couples the permission layer to an object a refactor can silently change. |
| F3 NO_PROXY matching semantics | technical | Ruled by CTO agent, 2026-11-18: over-deny - exact, `*.x`/`.x` (suffix entries also match the apex), literal `*` matches all; normalize (trim, lowercase, one trailing dot, IPv6 brackets, `:port` only on bracketed v6 or single-colon hosts); deny `malformed-host` for anything neither `net.isIP` nor LDH, or whose last label is all-numeric (catches `2130706433`, `0x7f.1`); deny `loopback-literal` for 127/8, ::1, ::, 0/8 and IPv4-mapped forms; other IP literals stay allowed so squid's deny-CIDR list stays the single source for private ranges - whether the SDK proxy short-circuits loopback outside NO_PROXY is unverified on 0.3.321. |
