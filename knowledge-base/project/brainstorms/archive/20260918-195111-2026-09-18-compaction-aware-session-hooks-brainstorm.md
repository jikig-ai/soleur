# Brainstorm: Compaction-Aware Session Hooks — an evidence-based "continue in a fresh session" gate

**Date:** 2026-09-18
**Trigger:** anthropics/claude-code#14258 closed 2026-08-17 — Claude Code v2.1.76 shipped a `PostCompact` hook (matcher `manual|auto`), alongside `PreCompact` (plain-text stdout becomes the summarizer's custom instructions; exit 2 blocks) and `SessionStart` matcher `compact` (model-visible `additionalContext` injected verbatim after the summary). Operator asked whether Soleur's workflow can use this to decide *accurately* when to ask the operator to continue in a fresh session, and what else it unlocks. Local CLI 2.1.273.
**Lane:** cross-domain
**Brand-survival threshold:** single-user incident

---

## What We're Building

One hook-agnostic plugin script, `plugins/soleur/scripts/compaction-state.sh`, bound three ways in `plugins/soleur/hooks/hooks.json` (so every marketplace install gets it, not just this repo's `.claude/settings.json`):

1. **Fresh-session gate (`SessionStart` matcher `compact`).** Reads `transcript_path` from the hook envelope with *bounded* greps (transcripts here run 13–30 MB; never `cat`): counts `"subtype":"compact_boundary"` records, reads the last one's `compactMetadata.{trigger,preTokens,postTokens,cumulativeDroppedTokens}`, and finds the last `soleur:*` skill invocation to derive the current workflow phase. Emits an `additionalContext` directive (≤10 k chars, `jq -n --arg`, exit 0 on every path):
   - *always*: "Compaction #N (`trigger`, pre→post tokens) landed during `<phase>` on branch `<b>`. Re-read the plan and `session-state.md` before editing anything (`hr-always-read-a-file-before-editing-it`). Refresh the resume prompt."
   - *when the trigger rule fires*: "At the next phase boundary, emit the resume prompt and recommend the operator continue in a fresh session. Do not pause a running `/soleur:one-shot`; carry the recommendation into its final resume prompt."
2. **Summary shaping (`PreCompact`).** Plain-text stdout instructing the summarizer to preserve verbatim: branch, worktree path, PR #, issue #, plan path, current skill/phase, unchecked acceptance criteria, `## Operator Holds`, and every file path mentioned. Pointer-style (paths), never inlined file bodies.
3. **Checkpoint (`PostCompact`).** Refreshes `knowledge-base/project/specs/<branch>/session-state.md` with **allowlisted structured fields only** (branch, worktree, PR/issue #, plan path, phase, compaction count + last metadata, timestamp) under a `<!-- generated by PostCompact; allowlisted fields only -->` provenance line; a gitleaks pass gates the write. Never copies `compact_summary` prose, user prompts, or `tool_result` bodies.

Plus the prose retirements the gate makes obsolete: the unconditional "run `/clear` before `/soleur:work`" in `plan/SKILL.md` and "Tip: after shipping, run `/clear`" in `work/SKILL.md` become conditional on the injected signal.

## Why This Approach

**Approach A — stateless transcript reader (chosen).** The transcript already carries every signal slice 1 needs, and `SessionStart:compact` receives its path. No counter file, no plugin-owned store, no `.gitignore` entry the plugin cannot add to a user's repo, and no dependency on the undocumented `PostCompact`↔`SessionStart:compact` ordering for slices 1–2.

**Approach B — stateful counter store (rejected).** `PostCompact` writes `.claude/.compaction/<sid>.json`, `SessionStart:compact` reads it. The CTO assessment showed the obvious host — `.claude/.session-manifests/<sid>.json` — is repo-side, gitignored, absent for marketplace installs, and **overwritten** by `session-rules-loader.sh` on every SessionStart including `compact`. A plugin-owned sibling fixes that but still needs the ordering probe before slice 1 works at all. More moving parts for the same signal.

**Approach C — skill-prose only (rejected).** Rewrite the `/clear` prose to "if you have compacted…". The model cannot observe its own compaction count; that is precisely today's inaccuracy.

## Key Decisions

|---|----------|-----------|
| 1 | **Trigger rule:** recommend a fresh session when `trigger=auto` AND (this is the 2nd+ auto-compaction in the session OR `postTokens/preTokens > 0.15`). A first auto-compaction only re-primes. Manual `/compact` never triggers. | Count alone nags on healthy 1M sessions; ratio alone misses repeated small compactions. The ratio catches a bloated summary (the failure mode where the summary itself is the problem). | 4 | **State location:** none for slices 1–2. Slice 3 writes only the committed `session-state.md` (existing artifact, sole writer today is `one-shot/SKILL.md`). | A fresh session is a different `session_id`/scratchpad, so a resume artifact must live in the repo. |

## Open Questions

1. **Does `SessionStart` matcher `compact` fire for `auto` compaction as well as manual?** Docs say "resuming after a compaction"; verify on the first forced auto-compaction during the plan-time probe. If not, slice 1 must fall back to a `PostCompact`-written scratch file read by `UserPromptSubmit` (the community workaround) — a spec change.
2. **Phase derivation for marketplace users:** `.claude/.skill-invocations.jsonl` is repo-only. The transcript's `Skill` tool-use records (`"skill":"soleur:<name>"`) are the portable source; confirm the grep pattern is stable across CLI versions.
3. **Local compaction metric (deferred → #8324):** a `SOLEUR_COMPACTION` record in the existing gitignored incidents ledger (`.claude/hooks/lib/incidents.sh` pattern → `rule-metrics-aggregate.sh`) would finally measure which skills blow the window, feeding the skill-description-budget work. Local-only, so no disclosure change; a Jikigai-operated sink would contradict privacy policy §4.1 and is out of scope.
4. **Devin `PostCompaction` measurement:** needs an arm where a compaction actually occurs on a branch with the marker hook bound (#8172's residual).

## User-Brand Impact

- **Artifact:** the three compaction hooks in `plugins/soleur/hooks/hooks.json` (`compaction-state.sh`) and the `session-state.md` checkpoint writer.
- **Vector:** worst case is slice 3 copying secret- or PII-bearing transcript text into a committed, pushed `session-state.md` on a user's remote — a silent exfil through the user's own git history; second-order is a mis-fired directive that tells a founder to abandon a healthy session mid-pipeline.
- **Threshold:** single-user incident.

## Domain Assessments

**Assessed:** Marketing, Engineering, Operations, Product, Legal, Sales, Finance, Support

### Engineering

**Summary:** Verified `PostCompact` stdin carries `compact_summary` + `transcript_path` (stdout never model-visible); statusline `context_window` data is unreachable from hooks. `.session-manifests` is repo-side and overwritten per SessionStart, so no piggybacking; hooks.json already binds `SessionStart` `compact` for the Codex shim, adding `PreCompact`/`PostCompact` blocks is trivial. Slice 3 is the large part (redaction + commit semantics). Recommended decision rule adopted as Key Decision 1. Recommends an ADR for the state-store/handoff decision.

### Product

**Summary:** Phase 4 milestone, internal-tooling row (protects alpha-tester validation on the CLI plugin, not a customer-facing roadmap row). Nudge at the next phase boundary, never mid-`one-shot`; threshold as env override, not a setting; define precedence between the hook and the skills that already write `session-state.md`. Success signal: compaction/resume-tagged learnings per month, `unkept-promise-hook.sh` firing rate after compaction, alpha-tester "the agent lost track" mentions.

### Legal

**Summary:** Slices 1–2 are purely local and already covered by privacy policy §4.2 ("workflow state stored locally"); no disclosure change. Slice 3 must be allowlist-only structured fields with a gitleaks pass before write, never transcript prose or `tool_result` bodies. `/soleur:gdpr-gate` regex does not match `plugins/soleur/hooks/**` — run it manually on the slice 3 writer at plan Phase 2.7. A Jikigai-operated telemetry sink would require policy/DPD/Art. 30 updates in the same PR.

## Research Reconciliation

- **Premise corrected:** local `SOLEUR_*` stdout markers do **not** reach Better Stack (`betterstack-query.sh` reads prod Vector logs only); they terminate in a local JSONL ledger aggregated by CI. The deferred metric follows that pattern.
- **Prior art:** `2026-02-22-context-compaction-command-optimization.md` established `session-state.md` as the compaction-boundary error-forwarding artifact — slice 3 extends it, reverses nothing. No hook anywhere today branches on `source == "compact"`; all three SessionStart scripts fire identically regardless of source.
- **Test harness:** nothing validates hook event names (`components.test.ts` has zero `hooks.json` references), so `PreCompact`/`PostCompact` need their own `*.test.sh` with stdin fixtures and a `components.test.ts` schema case.
