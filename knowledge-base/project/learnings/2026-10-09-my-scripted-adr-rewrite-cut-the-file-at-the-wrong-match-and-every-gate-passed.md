# Learning: my scripted ADR rewrite cut the file at the wrong match, and every gate I ran passed

## Problem

PR #9772 (census script plus a path gate for the secret-scan smoke matrix, ADR-276 stage S1) went through twelve review seats, two targeted fix rounds
and a verification pass. The most serious defect of the whole review was not in the code under review: it was my own edit to ADR-276 in the first
fix round.

I replaced the ADR's S1 amendment with a rewritten one using `s[:s.index("## Amendment 2026-10-08 (S1, #9727)")] + new_text`. The heading text also
occurs inside a backticked reference in the Stage-status line 250 lines earlier, so `index` returned the FIRST occurrence and the write replaced
everything after it: Context, Considered Options, Decisions 1-8, Consequences, Cost Impacts, NFR Impacts and Principle Alignment. The file went from
299 to 61 lines. `check-adr-ordinals.sh` (numbering only) and markdownlint both passed on the truncated file, the commit message did not mention a
deletion, and the amendment I had just written cited Decision 3(a), (e) and 5, which no longer existed in the file. A history seat found it in the
next review round by diffing the file's size against the parent.

## Solution

Restored the body from the pre-truncation commit and re-applied the two intended edits with line-anchored matches (`re.finditer(r'^## ...$', s, re.M)`,
asserting exactly one match), then proved the result with `git diff <base> -- <adr>`: only the Superseded note and the rewritten amendment, and the
same eleven `^#` headings at both commits.

## Key Insight

A scripted rewrite of a document is a deletion with a replacement attached, and none of the repo's structural gates look at what was deleted. After
any scripted whole-section rewrite, diff the file against its base and read the deletion count before committing: a docs diff that deletes ten times
what it adds is the signal, and no lint produces it. Anchor the cut on a line-start match and assert it matches once.

Two more findings from the same review are worth keeping:

- **Every fix round introduced defects in its own area.** Round 1 of fixes added a signal-handling test that failed 1 run in 100 idle and 14 in 100
  under load on an unmutated tree (an outer `timeout` re-sent the signal to the process group, so the script received a second signal mid-cleanup).
  Only a seat that re-ran the new rows under load found it; the fix agent's own run was green. A new test with a signal, a clock or a process group
  needs a loaded-machine loop before it is committed, not one green run.
- **The review made the suite cost visible, against the stage's own thesis.** The stage exists to remove CI runner demand; the two suites it adds grew
  from "a few seconds" to about 50 seconds per full-battery run (hundreds of assertions, dozens of mutants). That is a quarter to a half of the
  gate's net saving at the measured hit share. It was recorded in the ADR amendment rather than hidden; the stage that makes PR runs affected-only
  removes it.

## Session Errors

1. **ADR-276 truncated by `str.index` on the first occurrence of a heading that also appears in a list line** — Recovery: restored from the parent
   commit and re-applied with line-anchored matches — **Prevention:** after any scripted section rewrite run `git diff <base> -- <file>` and read the
   deletion count; match headings with `^...$` and `re.M` and assert exactly one match.
2. **A `git stash list` slipped into a read-only probe** and was blocked by the stash hook — Recovery: re-ran without it — **Prevention:** none beyond
   the hook; one-off.
3. **Fix-round tests were flaky on a pristine tree (signal rows)** — Recovery: removed the outer `timeout`, shielded the cleanup trap, ran 250 loaded
   iterations — **Prevention:** loop any signal/clock/process-group test under load (24 busy loops) before committing it.
4. **The review-evidence commit generated by the plugin script lacks the `Co-Authored-By` trailer and was pushed before I noticed (amend rejected as
   empty; no force-push)** — **Prevention:** run the trailer script, then check `git log -1 --format=%B` before the push; the script should emit the
   trailer itself.
5. **Plan-quoted figures were wrong or imprecise** (a 17% break-even that should be 12%, "3.3 minutes per run" from a per-head denominator, a rollback
   sentence that would have run the matrix on push) — **Prevention:** recompute every figure a decision depends on from the committed data before it
   goes into an ADR; the seat that re-derived them caught all three.
6. **A review seat killed a `yes` process it did not start** while cleaning up its own load generators — **Prevention:** start load generators from a
   recorded PID list and kill only those.
