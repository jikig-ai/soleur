# Learning: a read-only verifier refused the store its own producer writes, and its write-guard census was a lexer arms race

## Problem

PR #11567 (Ref #8211, closes #11431) added `mode=refs_assert`: a read-only, stdin-delivered host script that lets the owner attain REFS-CONFIRMED (a replicated branch tip exists on the git-data store) without SSH. Three defect classes survived a design review, a plan-review panel, a first implementation with a green 163-assertion suite and a 12-seat code panel:

1. **A refusal rule validated against a hypothesis, not the producer.** Ruling F20 kept a "`shallow` file means incomplete repository" refusal. The real producer is a `--depth 1` workspace clone pushed with `receive.shallowUpdate=true`, which makes the bare store GAIN a `shallow` file. The verifier would have refused every real replicated store, so REFS-CONFIRMED was unreachable on the intended path. Twelve seats and the author's own mutation battery read the rule as fail-closed and good. It was found by the architecture seat tracing the producer (`ensure-workspace-repo.ts:476`, `git-data-transport-wrapper.sh:154`) and then reproduced with real git in one scratch repo.
2. **A static census of a bash script built as a hand-written lexer.** The suite's "the host script writes nothing" guard was a Python tokenizer. Round 1 found it blind to the first command of a `case` arm and to the argv of allowed words; the fix reintroduced the same class, and round 2 found five more lexer bypasses (`[[` as an argument, a case label `)` inside `${}`, `$'\\'`, assignment prefixes, `\<newline>#` comments) plus assignments it skipped. Each round's fix was another arm of the same race.
3. **Registered-suite ratchets are repo-global and a scoped fix agent cannot see them.** The new suite defined `assert_fixture_dir` inline and wrote under 60 relative sites; `fixture-relative-assert` and `fixture-dir-operand-assert` went red only when the lead re-ran them on the combined tree.

## Solution

- Removed the shallow refusal (CTO F31) and pinned the opposite: a positive row that builds a REAL depth-1 clone, pushes it with `receive.shallowUpdate=true` into a real bare repo, asserts the `shallow` file exists, and requires rc 0. A garbage `shallow` file already fails by itself in `for-each-ref`, so no replacement check was needed.
- Bounded the census with a stated contract (F38): it catches accidental, plainly spelled additions in dormant paths; it is not an adversarial-author defence. The property check is runtime: every external command in every test world is recorded by a shim and checked against a closed list of literal call-site forms. Gave the allowlist derivation-from-the-script and parity both ways.
- Brought the suite onto the canonical `assert_fixture_dir` and `: "${TMPDIR:=/var/tmp}"; mktemp -d -t ...` so the scanner sees absolute paths, instead of regenerating either baseline.

## Key Insight

A verifier's REFUSAL predicates are claims about what the producer can emit, and the producer's real output is the only authority. When a rule reads "refuse state X because X means broken", build the store the way production builds it (the real clone flags, the real push options) and run the verifier against it before the rule is ruled in. A mutation battery, a panel and a green suite all score the verifier against fixtures the author drew from the same hypothesis; the false refusal is invisible to them by construction. Corollary: a static lexer for a language you do not control is a treadmill. After the second consecutive round that finds a fresh bypass, delete the ambition (state the contract, push the property to a runtime recorder) rather than patching a third arm.

## Session Errors

1. **Brief premise not in the code** (a "hashed-name convention" in `git-data-cutover.sh`; an issue-requested `synthetic_id` dispatch input that would persist an id in run metadata) — Recovery: plan recorded both in Research Reconciliation and the CTO ruled no id input — **Prevention:** treat a brief's or issue's named convention as a claim; `grep` for it before planning against it (already the plan skill's reconciliation step; no new rule).
2. **Shallow refusal built on an unverified premise (F20)** — Recovery: architecture seat flagged it; lead reproduced with real git (depth-1 push leaves `shallow`); CTO overturned F20 — **Prevention:** a new refusal predicate in a verifier needs a fixture produced by the REAL producer's own flags before it is ruled in; routed as a bullet in `plugins/soleur/skills/review/references/risk-tier-and-fix-rounds.md` (review/SKILL.md is at its byte ceiling).
3. **Implementer's "suite green" covered only its own files; two repo-global fixture ratchets were red** — Recovery: lead re-ran the ratchets on the combined tree and a fix agent adopted the canonical helper — **Prevention:** already documented (work Phase 2 "A fix agent's suite green..."; review fix-round notes); the miss was not briefing the implementer by name — brief fixture ratchets (`fixture-relative-assert`, `fixture-dir-operand-assert`) in the spawn prompt whenever a new `*.test.sh` is added.
4. **Write-guard census as a hand-written bash lexer; three rounds, fresh bypass each** — Recovery: CTO F38 bounded the contract, runtime argv recording became the property check — **Prevention:** after the second round that finds a bypass in a heuristic, stop patching and re-scope the heuristic (already in review Sharp Edges: "DELETE the heuristic rather than patch it"; this PR is another measurement of it).
5. **Fix agents stalled twice on dead background monitors (one idle ~4 h with six files uncommitted)** — Recovery: `ListAgents`/`git status` showed no progress, `SendMessage` resumed the agent with "run foreground, commit what is green" — **Prevention:** brief implementers to run suites and mutation proofs in the FOREGROUND with `timeout` and commit per green unit; the lead checks `git log`/file mtimes when a completion notice says "waiting on its own background work".
6. **Hook rejections: `git stash list` and `pgrep -f` denied; a scratch-repo commit with a `$VAR` path denied** — Recovery: used `pgrep <name>`, literal absolute paths — **Prevention:** already hook-enforced (`guardrails.sh` block-stash, `pkill-self-match-guard.sh`, the commit-target resolver); no change.
7. **`origin/main` moved three times and conflicted in append-only registries** (`PROMOTED_FILES`, `suite-durations.tsv`, generated C4 JSON) — Recovery: merged `origin/main`, kept both sides, regenerated the JSON via `scripts/regenerate-c4-model.sh` — **Prevention:** run `git merge-tree --write-tree origin/main HEAD` immediately before every push and spawn, as the review skill already prescribes; the append-only registries are a known conflict magnet.
8. **Two seats contradicted each other on the run-identity field (`name` vs `displayTitle`)** — Recovery: the architecture seat's empirical `gh run view <id> --json name` settled it — **Prevention:** a seat finding about an external CLI/API field gets one measured query before it is applied (already in review Sharp Edges for reviewer-prescribed flags).
9. **Two closing messages promised an action with the turn ending** (Stop hook) — Recovery: ended with `Paused:` lines — **Prevention:** already hook-enforced; when waiting on background seats, end with one `Paused: <the thing awaited>` sentence.
