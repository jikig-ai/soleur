# Learning: an allow-list of line shapes is not a closed sequence, and a hook that matches command TEXT stops delegated agents silently

## Problem

Two instances of one shape on PR #9448 (web-host LUKS distinct passphrase, escrow gate): a check certified something narrower than the property it was named for, and the failure was silent.

1. **The HALT pin.** The fix for "the rotation HALT is only text-pinned" was an allow-list of line SHAPES for the apply step's destroy-guard prelude (a line may be `exit ...`, `fi`, `echo "::error::..."`, a `grep -F ... tfplan.txt` and so on), plus an executed harness. A fresh-eyes verification pass bypassed it with four one-line edits the checker accepted AND the harness ran past the HALT: `exit $rc` before the HALT `if`, an `rc` `if` wrapped around the HALT with a spare `fi` after it, and an `${a[luks_rotations=0]:-}` array-subscript assignment hidden inside an `echo` or `grep` argument. Each line is a permitted shape; the property ("nothing can skip or neuter the HALT") lives in the order, the count and the balance of the lines, which a per-line allow-list does not see. A second gap sat beside it: the numeric-validation requirement was satisfied by any subset of counters.
2. **The deferring hook.** `.claude/hooks/prod-write-defer-gate.sh` matches the TEXT of a Bash command (`... ; terraform apply`) including heredoc bodies. Five delegated agents (fix agents, a review seat and the verifier) wrote test fixtures through heredocs whose body contained that literal text (the repo's own census tests assert on it). The hook returned `defer`, a subagent cannot obtain approval, and each agent stopped with no report: four silent stops, each costing a resume round-trip. No production write was attempted.

## Solution

- **Closed sequence.** `destroyGuardPrefixViolations` now consumes the span from the step's `run:` header through the HALT's `fi` as a closed sequence: each required statement exactly once and in order, one slot per block (echoes, then the grep, then the exit, then `fi`), `if`/`fi` counts balanced, nothing after the last `fi`, echo and grep bodies limited to plain counter variables (any `${..[..=..]..}`, `$(( ))`, `$(` or backtick refused), and the numeric validation must name every counter. The executed harness runs the real step text from its start under `bash -e` with the real acknowledgement environment and ten mutants, each shown to defeat the HALT when run unchecked, so the checker rows are load-bearing. See the commit `08c5369eb1`.
- **Hook.** Delegated agents write any file whose text contains such strings with the Write tool and run it with a short Bash command; a deferred Bash call is reported, not retried. The hook's heredoc-body false positive is NOT fixed here (different subsystem) and was not filed: the simplicity reviewer DISSENTed on the filing because the proposed re-evaluation trigger ("the next time an agent stops") has no grep-able signal, and warned that the obvious fix is a fail-closed hazard. Design notes for whoever takes it: strip ONLY heredoc bodies (from the `<<[-]?['"]?TAG` line to the terminator), never quoted strings, because stripping quotes would let `bash -c "terraform apply"`, `eval "..."` and `ssh h '...'` through; keep the opener line scanned (`cat <<EOF; terraform apply` must still defer); an unterminated heredoc must fail closed (no stripping); handle `<<-`, quoted and unquoted tags and several heredocs per command. A concrete trigger for a future filing: the grep `hook_deferred_tool.*prod-write-defer-terraform-apply` over agent transcripts, or a second recurrence.

## Key Insight

A per-line allow-list is a statement about each line, and a guard's property is almost always a statement about the whole span. When the property is "nothing can skip or alter X", state it as a closed sequence (index, count, balance, nothing after) and prove it with mutants that are each shown to defeat the guarded thing when the checker is bypassed; otherwise the checker's green is a sentence about the lines the author had in mind. Separately, any hook that gates on command TEXT will fire on text that merely quotes the command, and the people it stops are non-interactive agents that cannot approve, so the failure mode is silence rather than a prompt.
