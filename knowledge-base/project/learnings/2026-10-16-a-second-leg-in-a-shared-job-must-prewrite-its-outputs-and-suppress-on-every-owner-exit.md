# Learning: a second leg in a shared job must pre-write its outputs and suppress on every exit its sibling owns

## Problem

#7521 part (b): the registry store fill-rate detector was a follow-through whose PASS closed its tracker on 2026-08-14, so nothing ran it afterwards. The fix (PR #10444) runs the existing script unmodified as an independent fill-rate leg of the hourly `scheduled-zot-restart-loop.yml` workflow: a probe step plus three filing steps, placed after the Sentry check-in. A 12-seat review panel and a targeted fix round then found the same four classes the first implementation shipped, each reported by several seats independently:

1. **The probe wrote its outputs only at the end.** A step timeout or kill left `fill_verdict` and `fill_defect` unset, every filing step was gated on `outputs.X == 'LITERAL'`, so nothing filed, and the plan's Observability block still claimed a probe-defect issue (six seats converged).
2. **The defect rule suppressed only `ALARM_EXIT == 2`** (the exit that errors the Sentry monitor). Exits 3 (PRODUCER_SILENT) and 4 (INGEST_DARK) already file their own issues, so a fill-only TRANSIENT double-filed a probe-defect issue whose body said the zot leg was healthy (four seats; the comment and the code disagreed).
3. **The wiring test pinned step BODIES but not the wiring around them.** Nine to sixteen single-line workflow mutations stayed green: a step's exact `if:`, env key sets and sources, `continue-on-error`/`shell:`/`working-directory`, job and workflow `env`/`defaults`/`outputs`, bracket-syntax references, the `--json` fields and `--state open` of every issue lookup.
4. **New prose in the fix overclaimed.** "A step timeout or a runner kill also files it" is false (a runner loss or the 8-minute job timeout makes `!cancelled()` false, so no filing step runs); "it is never a store state" ignored a failing `gh issue create`; an ADR line cited a "carve-out" in ADR-033 that does not exist.

## Solution

- **Pre-write the failure defaults as the first statement of the step**, then let the end-of-step write override them: `fill_verdict=UNEVALUATED`, `fill_defect=true`, `fill_line=probe step did not complete`. The runner processes the `GITHUB_OUTPUT` file in a `finally` block after the step handler (read from actions/runner `ActionRunner.cs` by two review seats), and a repeated key keeps the last value. A mutation row moves the pre-write below the script call and goes red. Be exact about the scope: a step timeout is covered; a job timeout or cancellation files nothing (state it).
- **A leg that reads the same inputs as an owner leg suppresses on every exit code the owner owns** (here 2, 3 and 4), taken from the owner's exit contract, with a fixture per code. Keep the never-suppressed class (UNEVALUATED) explicit.
- **Close a defect issue on one PASS, and record the trade** (a flapping probe re-files new issue numbers); keep the age test only for the issue whose meaning is "no FAIL for N hours". Close the issue with the age test FIRST so a failing defect close cannot starve it under `set -e`.
- **Pin the wiring, not just the bodies:** the exact `if:` of each step, each step's full key set, job/workflow `env`/`defaults`/`outputs`/`permissions`, exactly-N steps referencing the outputs by ANY key or syntax, and have the `gh` shim project the canned list to the `--json` fields requested so dropping `updatedAt` or `title` fails.
- **Every claim a fix ADDS to prose is a new unmeasured claim:** name the falsifying command and run it (here: `grep` the ADR for the cited carve-out; read the runner source for the flush).

## Key Insight

A second leg added after an existing monitor inherits the job it shares and the stream it reads, so its safety is decided by three things a body-level test cannot see: what its gated steps do when the producing step dies before writing anything, which of its sibling's verdicts already own the condition it would file about, and whether the step's own `if:`/env/keys are what the suite pinned. Defaults written before the risky call, suppression derived from the owner's exit contract, and pins on the wiring close all three.
