# Troubleshooting: Shared bwrap seccomp filter + fd hygiene across two sandbox insertion points (#8752)

## Problem

PR #8732 hardened the C4-render bwrap argv (fd sweep, `--seccomp`), but the Agent SDK spawn — which deliberately grants tenants arbitrary code execution — had no equivalent: no nested-userns filter, and every fd the runner process held leaked into the sandbox. The issue required ONE shared policy artifact applied at two mechanically different insertion points.

## Environment

- Module: `apps/web-platform` (`infra/bwrap-userns-clone3-deny.bpf`, `infra/bwrap-shim/bwrap`, `scripts/gen-bwrap-userns-seccomp.mjs`, `server/c4-render.ts`, `server/agent-runner-sandbox-config.ts`, `scripts/sandbox-canary.mjs`)
- Image: pinned `node:22-slim` / Debian Bookworm, `bubblewrap 0.8.0-2+deb12u1`
- PR: #9595, Issue: #8752
- Date: 2026-10-06

## What Didn't Work

- **`sock_fprog` serialization for `--seccomp <fd>`.** bwrap reads the fd as a *raw `sock_filter` array* (`len % 8`, `program.len = len/8`) — the `seccomp_export_bpf` header bytes parse as garbage instructions → `EINVAL` at spawn. Measured, not read.
- **`clone3 → EPERM`.** `clone3` takes its flags in a userspace `clone_args` seccomp cannot inspect; EPERM breaks glibc's `posix_spawn` (moby/moby#42680). `ENOSYS` makes callers fall back to `clone`, where `CLONE_NEWUSER` *is* inspectable and denied. The runc-side precedent is `7a8d7162f9d72f20d83eaa36aeb5426deecd58f2`; the moby commit is `9f6b562`.
- **`unshare -m` as the over-broad control.** Inside a bwrap sandbox the payload runs capability-free (capset zeroed before exec), so every nested non-userns unshare EPERMs regardless of the filter — the control can never discriminate. The correct control is a forked child (clone() without `CLONE_NEWUSER` must succeed).
- **`spawnSync(..., {stdio: [..., hostFd]})` + naming that fd in argv.** Node maps the parent fd to the child at the *stdio array index* (fd 3), not the parent's number. Passing `--args <hostFd>` → `EBADF` → false `sandbox_broken` on every deploy. Name the child index.
- **A `prev`-token fd-preserve scan.** `--setenv --args 9` puts an fd-option name in VALUE position; prev-tracking preserves the fd → silent leak. The shim scan must be arity-aware (skip each option's declared argument count) and stop at `--`.
- **Non-zero = denial in expected-fail probes.** A `bwrap:` setup error or host-side denial satisfies `rc != 0` vacuously. Require the payload's own `Operation not permitted` signature *and* an unfiltered positive control in the same row.

## Solution

- **One artifact, two insertion points:** the committed `.bpf` (generated by `gen-bwrap-userns-seccomp.mjs`, byte-parity `--check`) is consumed by `bwrap --seccomp 9` on the C4 argv (fd opened post-sweep in `CLOSE_FDS_SCRIPT`, fail-closed) and by a baked `/usr/local/bin/bwrap` PATH shim on the Agent SDK side, which sweeps inherited fds and injects `--add-seccomp-fd` (repeatable — a future SDK `--seccomp` conflicts loudly instead of last-wins overriding).
- **Filter:** arch gate `KILL_PROCESS` for non-x86_64, `clone3` + x32 → `ENOSYS`, `clone`/`unshare` with `CLONE_NEWUSER` → `EPERM`, default `ALLOW`.
- **Deploy tripwires:** four derived canary probes — nested-`unshare -U` must EPERM, fork must survive, an fd census *carrying a deliberately unreferenced fd* must stay at `4 + #(fd-valued argv opts)` (a sweep regression is now observable), and a real `--args <fd>` NUL-transport spawn must succeed. `bwrap-shim:` stderr → `sandbox_broken`/`bwrap_shim_refused`, never `canary_infra_error`.
- **Boot self-probe:** `probeAgentSandboxHardening` (marker identity on the PATH bwrap + artifact shape) runs after listen, production-only, report-only.

## Session Errors

- **sock_fprog header in the generator** — Recovery: emit raw `sock_filter[]` after reading bwrap's `seccomp_program_new` source. — Prevention: real-binary install check (`--seccomp` end-to-end row) before asserting byte parity.
- **Vacuous EPERM attribution (probe passed on bwrap setup failure)** — Recovery: require the payload's own EPERM text + reject shim exit 65. — Prevention: every expected-fail probe needs an unfiltered positive control in the same row.
- **`--args <hostFd>` numbering bug (host fd ≠ stdio index)** — Recovery: `"--args", "3"` — caught by review seat before commit. — Prevention: exported `runArgsFdTransportProbe` is live-tested in `bwrap-shim.test.ts` through real bwrap.
- **Value-position desync in the preserve scan** — Recovery: arity-aware parser with an fd1/fd2/a1/a2/a3 table. — Prevention: `§D4` byte-identity check between shim and canary vocabularies + a dedicated desync test row.
- **Stray `});` from a partially-applied edit broke the canary test file** — Recovery: removed. — Prevention: re-run the touched suite before declaring a batch done.
- **`APP_ROOT = join(fileURLToPath(import.meta.url), "../..")` tripped the containment manifest** — Recovery: `join(dirname(...), "..")` idiom + manifest cleanup. — Prevention: run `repo-wide-containment.test.ts` in every touched-suite sweep.
- **markdownlint silently no-op'd on `knowledge-base/project/`** — the dir is `.markdownlintignore`-scoped (#7927); the earlier "clean" result was vacuous for spec files. — Prevention: check `.markdownlintignore` before citing a lint pass as evidence.
- **`fd_census` latent-only detector** — census measured only an incidentally-clean fd table; a shim whose sweep regressed would deploy green. — Recovery: `leakFd` deliberately passes an unreferenced fd so `fd_hygiene_bypass` discriminates. — Prevention: a probe that can only pass by construction is not a probe — every census/bound needs a discriminating input.

## Prevention

- Real-binary e2e rows (never byte-shape only) for anything consumed by an external tool's fd/CLI contract.
- Positive control + signature-required denial on every security probe — non-zero is unattributable.
- Exported probe functions exercised in unit tests against the real shim+bwrap, not only via the CLI path.
- Byte-identity assertions wherever two files must mirror a vocabulary (shim ↔ canary fd options).
