# My fixture shared the bug, so the test could not see it

**Date:** 2026-08-11 · **PR:** #7435 · **Issues:** #7341, #7436, #7437, #7440

## Problem

Two verification obligations from the 2026-08-10 zot registry recut had no mechanism behind them:
#7431's invoice reconciliation (an external event weeks away) and the post-recut fill rate (the
measurement that decides #7341). Both were session-local and would have died at the context
boundary. Building the two sweeper probes surfaced seven defects **in the probes themselves**,
every one of which produced a green verdict.

## Key insight

The previous session's lesson was *a check certified something other than what it named*. This
session produced a sharper variant that the earlier prevention does not cover:

> **A fixture that shares the code's wrong assumption cannot see the bug — the two errors cancel
> and the harness goes green.**

Better Stack emits `dt` naive in UTC. `datetime.fromisoformat(...).timestamp()` on a naive
datetime assumes **local** time, so on this UTC+2 host every sample read two hours older than it
was, and the staleness gate called a live heartbeat 124 minutes stale. The 11-case harness passed
throughout — because the stub built its fixtures with `datetime.now()`, the same local-time
assumption. Only running the probe against production revealed it.

The rule "one fixture must be transcribed from a measured response" was **satisfied and did not
help**. I did transcribe the marker's field shape from a real line. What I did not transcribe was
its *timezone*, because a field shape is visible in a sample and a timezone convention is not.

The generalisation: **a fixture can only falsify assumptions the fixture author did not share.**
For anything where the fixture is generated by the same mental model as the code — time bases,
encodings, ordering, units, locale — the harness is structurally blind, and the only instrument
that resolves it is a live run.

## The seven defects

| # | Defect | What made it green |
|---|---|---|
| 1 | 72h window straddled the recut | Fitted one line through the old 100%-full volume and the new empty one — `PASS slope=-58.48pp/day proj14d=-811`. A wipe is a step discontinuity, not a trend. |
| 2 | `boot_id=([0-9a-f-]+)` | A class not covering the whole token still *matches*, capturing the longest acceptable **prefix**. Two distinct boots collapsed and compared equal, silently disabling the scoping the check rested on. |
| 3 | Count floor with no span floor | Twelve 5-minute samples span one hour. Enough rows to clear any count floor while extrapolating an hour of jitter across two weeks — and precisely the freshly-recut shape. |
| 4 | A dead host passed | 48h of low-flat history ending 40h ago cleared the span floor and fitted `+0.00pp/day`. The check certified *"the last readings we happen to have were low"* and was loudest-green when the host was gone. |
| 5 | Fixture shared the bug | Above. |
| 6 | PASS tested before FAIL | An operator's `RESULT: FAIL retracting: that was the July invoice` lost to the `RESULT: PASS` it was retracting. Comments are append-only, so a premature PASS cannot be withdrawn. |
| 7 | Neither harness ran in CI | `test-all.sh` registers suites by hand. An unregistered `.test.sh` runs only when invoked personally — so for probes that auto-close a tracker, the anti-vacuity floor was decoration. |

Defects 3, 4, 5 and 6 were introduced by the fixes for 1 and 2, continuing the previous session's
pattern: the defect rate per fix did not fall, only the catching did.

## Instrument errors while investigating the root cause

Four measurements taken to attribute the disk consumption were themselves wrong, and each was
caught only by disbelieving a suspicious result:

1. Grepped `gc` and `uploads` and read per-repo counts off the output. Both matched **substrings
   inside heartbeat markers**, not zot log lines. The counts were meaningless.
2. Concluded "6 PatchBlobUpload occurrences post-recut". They were 6 heartbeats echoing **one**
   stored error via the `zot_last_err` field.
3. A regex using `[^,]+` to parse `zot_last_err` returned **0 of 289** matches, because the message
   itself contains a comma. A zero that looks like a finding is the most dangerous instrument
   output there is.
4. Nearly filed `zot_last_err` as a defect for carrying INFO-level lines. It has a discriminator:
   `zot_last_err_src=error` ↔ `level:error` (6 heartbeats), `src=fallback` ↔ `level:info` (123).
   Checking first avoided filing a false defect against working code.

That investigation ended in a real finding rather than a conclusion: **the registry host ships no
zot logs at all** — over 6h, all 72 rows mentioning `soleur-registry` are the heartbeat, and all 53
`zotregistry.dev` matches are echoes inside it. Filed as #7440. Before asserting it I enumerated
every Better Stack source and found exactly one team-wide, which turned "I may have looked in the
wrong place" into "there is no other place". That check is what makes the claim safe to act on.

## Prevention

- **For any value with an implicit convention — timezone, encoding, unit, ordering, locale — the
  fixture cannot be the only witness.** Run the real thing once and compare against a fact
  established independently (`date -u`, a known-good row). Ask of each fixture: *which of my
  assumptions could this fixture not contradict, because I generated it from those assumptions?*
- **A probe that decides an incident must reject staleness explicitly.** "Latest sample" is only
  "current state" if the sample is recent; otherwise the check is loudest-green when the subject
  is gone. Pair every threshold gate with a freshness gate.
- **Order verdict arms so the irreversible one wins.** In append-only evidence (issue comments) a
  wrong PASS cannot be withdrawn, so FAIL must be tested first. The arm order is an assertion and
  needs its own test case.
- **A harness that is not registered does not exist.** When adding a `.test.sh` under a directory
  whose peers are hand-registered in `test-all.sh`, register it in the same commit — otherwise the
  anti-vacuity floor and every case behind it are decoration.
- **A count from a sampler is a lower bound, and must be written as one.** The heartbeat samples
  one log line per five minutes; "3 occurrences" is "at least 3".
- **Before writing "X does not exist anywhere", enumerate the search space.** One API call turned a
  scoped negative into a team-wide one.

## Session Errors

1. **Shipped a probe whose first live run reported a wipe as a trend.** Returned PASS on a
   `-58.48pp/day` slope. **Prevention:** scope any time series to the identity of the thing being
   measured (`boot_id`); a replacement is a discontinuity, never a data point.
2. **Wrote a character class that silently prefix-matched.** `([0-9a-f-]+)` against
   `bootOLD-aaaa`. **Prevention:** capture whole tokens with `(\S+)` unless the class is the
   assertion.
3. **Built a fixture that shared the code's timezone assumption.** Covered above.
4. **Let a dead host pass.** **Prevention:** freshness gate beside every threshold gate.
5. **Tested PASS before FAIL** in an append-only evidence channel. **Prevention:** the
   irreversible verdict is evaluated first.
6. **Added two harnesses without registering either in `test-all.sh`.** **Prevention:** register in
   the same commit as the harness.
7. **Twice, an apostrophe in a comment terminated the single-quoted python block it sat inside**
   ("runner's", "probe's"). Caught by shellcheck and by the harness dropping to 2/11.
   **Prevention:** treat single-quoted heredoc/`-c` bodies as apostrophe-free zones and say so in
   the block.
8. **Wrote the invoice probe to take the issue number as `$1`.** The sweeper invokes scripts with
   no arguments under `env -i`, so it would have returned TRANSIENT forever and never closed.
   **Prevention:** read the caller's invocation line before designing a callee's interface.
9. **Filed an issue with an inline `--body` containing quotes**, which the follow-through directive
   gate could not parse (its extractor stops at the first inner quote), producing a confusing
   block on an issue that *did* carry a directive. **Prevention:** `--body-file` for any issue body
   with a directive — which is also the documented pattern.
10. **Four bad measurements during root-cause work**, enumerated above. **Prevention:** before
    reading a count, confirm the grep matched the stream you meant and not a marker echoing it.
11. **Two Bash calls timed out at the tool's 2-minute default** (`git commit` with hooks, a suite
    run) and one was reported as failed when the commit had in fact landed. **Prevention:** use
    `run_in_background` for anything invoking pre-commit hooks or a suite.
