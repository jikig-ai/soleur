# scripts/pr-fanout-ledger.txt — every workflow that fires on a PULL REQUEST PUSH.
#
# "Fires on a PR push" = declares on.pull_request or on.pull_request_target with no
# `types:` or with `synchronize` in `types:` — OR declares on.workflow_run naming a
# firing workflow with no `branches`/`branches-ignore` filter (it runs once per run
# of that workflow, i.e. once per PR push: fix-constraints-stage-b.yml). Workflows
# gated to opened/closed only, or chained with `branches: [main]`, are not in the
# generator and have no row.
#
# jobs = the workflow's DECLARED job count, a CEILING the enumerator compares `<=`.
# A `uses: ./.github/workflows/<callee>` job counts the callee's declared jobs (it
# dispatches them). A matrix job is ONE declared job; its legs are NOT counted, so
# this column is a bound on declared jobs, not on runner slots (ci.yml's two shard
# matrices and secret-scan's smoke-tests matrix each occupy more slots than rows).
# if:-skipped jobs are declared but consume nothing. paths = yes when the trigger
# carries a paths/paths-ignore filter (a pull_request.branches filter is NOT a paths
# filter; such a workflow is still ledgered as firing). cancel = yes ONLY when the
# enumerator can PROVE a superseded push cancels the run, which needs ALL of: the
# cancel FORM — cancel-in-progress is `true` or ci.yml's
# `${{ github.event_name == 'pull_request' }}` ternary (`true`, `false` and that
# ternary are the three accepted spellings; any other expression fails A4c) — AND the
# GROUP SHAPE — the group references `github.ref`, `github.head_ref`,
# `github.ref_name`, `github.event.number`, `github.event.pull_request.number` or
# `github.event.pull_request.head.ref` — AND no per-run token in the group
# (`github.sha`, `run_id`, `head.sha`, ...: a key that is unique per push never
# collides, so it never cancels, whatever else it mentions). A static-string group
# or any other shape scores `no` (fail-closed: unprovable, not disproved). Workflow-
# level or job-level blocks both count; ANY qualifying block scores the workflow yes.
# Every block using the ternary form must also carry ci.yml's group expression
# byte-for-byte (A6), so a copy regressed to a per-ref-only group cannot hide behind
# cancel=yes on a `push: main` arm (the #7931 class).
# consequence = what breaks if this does not run on every PR push; a cancel=no row
# MUST also say why, as `no cancel: <reason>` (A5). A row with no consequence is a
# row that should not exist. Columns are TAB-separated (unlike required-checks.txt,
# which is one name per line); a row with any other field count fails A-parse by
# line number.
#
# The test (plugins/soleur/test/pr-fanout-ledger.test.sh) reddens on: a firing workflow
# with no row; a row whose workflow no longer fires; a workflow declaring MORE jobs than
# its row; a paths or cancel flag that disagrees with the file; a ternary-form block
# whose group is not ci.yml's. Growth requires editing this file, and editing this
# file requires naming the consequence (ADR-216 shape; ADR-216 addendum 2026-09-14).
# The jobs column is a CEILING, not a floor: lower it when a workflow shrinks; raise it
# only with a named consequence. A reader who raises a row to match a file that GREW
# has reversed the ratchet. Next reduction candidate, measure first: the remaining
# advisory ci.yml jobs.
#
# Format: <workflow><TAB><jobs><TAB><paths><TAB><cancel><TAB><consequence>   (comment lines: leading-# only)
# workflow	jobs	paths	cancel	consequence
